# クイックスタート: 実際のプロキシと実際のサイトを、コマンドラインとサーバーから使う {#quickstart-a-real-proxy-and-a-real-site-from-the-command-line-and-the-server}

これらの手順は、自動チェックが扱えないものを扱う。CI のプラグインはインターネットなしで応答し、プロキシとアドレスのテストはループバックに対して実行され、CI は Windows アプリを実行しない。セットアップとチェックは [development.md](../../docs/how-to/development.md)、[running-vv.md](../../docs/how-to/running-vv.md) を参照。

## 前提 {#prerequisites}

- 手順書の手順で作った、公開サイトを取得するプラグイン。`options` と `default` を宣言する設定と、`secret` の設定を持つ。および、テスターのルーターの LAN アドレスを `fetch` が要求する変種。
- テスターが管理できる LAN 上の HTTP プロキシ (要求を記録するもの)。および、認証の手順のための、誤ったパスワードつきのそのアドレス。
- コンテナイメージから動く vv と、Windows 上の `VVMDM.exe`。それぞれ動画を 1 本取り込んでおく。

## 手順 {#steps}

| 手順 | 期待される結果 | 受け入れ |
| --- | --- | --- |
| 既定値が選択肢にないマニフェストで `mdm plugin pack` を実行する | 理由が `default` と `options` を名指しする。モジュールのバイト列は変わらない | 3、エッジケース |
| 修正したマニフェストで `mdm plugin pack` を実行し、続けて `mdm plugin run plugin.wasm fetch <public URL>` を実行する | 保持した `workInfo` が出力される。プラグインが標準エラーに書いた行がコマンドの標準エラーに現れる | 1、4 |
| LAN の変種で `mdm plugin run` を実行する | コマンドは `blocked_address` とルーターのアドレスつきで終了コード 1 になる | 2 |
| LAN のプロキシを指す `--proxy` で `mdm plugin run` を実行する | プロキシのログに要求が見える。結果はプロキシなしと同じである | 7 |
| パックしたプラグインを設定画面に追加し、その設定ダイアログを開く | 既定値は既定値として表示され、選択肢のある設定は選択肢からの選択になる | 5 |
| プラグインを承認し、秘密の設定に値を入力し、受け取った設定を標準エラーに書くプラグインで、選択肢を持つ設定を変えずに取得する | 設定画面の直近の実行の出力が、既定値と、`[secret]` として伏せた秘密を示す | 6、10、11 |
| Network セクションでプロキシを設定し、もう一度取得する | プロキシのログに要求が見え、取得は成功する。プロキシを消去して取得する: プロキシのログには何も増えない | 7 |
| プロキシを設定した状態で、LAN の変種で取得する | 取得はルーターのアドレスつきで失敗する。プロキシのログには、それへの要求がない | 8 |
| 誤ったパスワードのプロキシを設定して取得する | 取得はプロキシを名指しするネットワークエラーとして失敗する。ネットワークを使わない別のプラグインは引き続き動く | エッジケース |
| 比較で、取得したタグのうち 2 つを外して適用する | 残りのタグだけが仮のタグとして付く | 9 |
| `VVMDM.exe` でプロキシの手順を繰り返す | Network セクションに LAN スイッチとプロキシの行が表示される。結果は同じである | 7、8 |
