# クイックスタート: コンテナと Windows アプリで、実際のサイトに対して実際のプラグインを使う {#quickstart-a-real-plugin-against-a-real-site-on-the-container-and-the-windows-app}

これらの手順は、自動の検査が扱えないものを扱う。CI のプラグインはインターネットなしに答え、そのアドレスのテストはループバックに対して動き、CI は Windows アプリを実行しない。準備と検査: [development.md](../../docs/how-to/development.md)、[running-vv.md](../../docs/how-to/running-vv.md)。

## 前提 {#prerequisites}

- [プラグインの契約](contracts/plugin-contract.md) からビルドした、テストする人が選んだ公開されたサイトを検索し取得するプラグインと、その `fetch` がテストする人のルーターの LAN のアドレスに要求する変種。
- コンテナイメージから動かす vv と、Windows の `VVMDM.exe`。それぞれに取り込んだ動画が 1 つある。

## 手順 {#steps}

| 手順 | 期待する結果 | 受け入れ条件 |
| --- | --- | --- |
| 設定画面でプラグインを追加し、承認する | 名前、バージョン、ネットワークの通知とともに未承認として表示され、その後承認済みとして表示される | 1 |
| 動画のページで、実際の作品の語で検索し、候補を選ぶ | サイトからの候補が現れる。1 つを選ぶと、今のタイトルとタグと、取得したタイトルとタグが並んで表示される | 3 |
| タイトルとタグだけを選んで適用する | 表示名が変わり、タグが仮のものとして現れる。ページのそれ以外は何も変わらない | 4 |
| LAN の変種で取得する | 取得は失敗し、失敗はルーターのアドレスを挙げ、動画は変わらない | 5 |
| 同じ名前でビルドし直したプラグインをアップロードする | 未承認に戻り、動画のページの選択肢から消える | 2 |
| `VVMDM.exe` で最初の 3 つの手順を繰り返す | 同じ結果 | 1、3、4 |
