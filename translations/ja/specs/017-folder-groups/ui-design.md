# UI 設計: フォルダのグループを 1 件として一覧に出し、続けて再生する {#ui-design-listing-a-folder-group-as-one-entry-and-playing-it-continuously}

**機能**: [親 Issue #326](https://github.com/syudead/vv/issues/326)

出典: 見た目の規則、シェル、一覧の密度は [ライブラリ UI: 見た目の規則と一覧の構造](../../docs/design-docs/library-ui.md) と [`web/src/index.css`](../../web/src/index.css) の `@theme` に従う。動画ページの構造と再生終了のレイヤーは [012 の ui-design.md](../012-video-detail-ia/ui-design.md) に従う。フォルダ画面の構造は [011 の ui-design.md](../011-folder-browser/ui-design.md) と [013 の ui-design.md「フォルダ画面」](../013-library-search/ui-design.md#folder-screen) に従う。タグチップ、選択バー、コンボボックスは [014 の ui-design.md](../014-video-tags/ui-design.md) に従う。ゲスト向けの縮退は [016 の ui-design.md「ゲスト向けの縮退」](../016-single-account-auth/ui-design.md#guest-degradation) に従う。画面が使う応答とルートは [contracts/library-api.md](contracts/library-api.md) と [contracts/folder-groups-api.md](contracts/folder-groups-api.md) で決まっており、グループの視聴状態と開くメンバーの決め方は [data-model.md、グループの視聴状態と開くメンバー](data-model.md#group-watch-state-and-the-member-to-open) にある。この文書はそれらを蒸し返さない。

この文書が定めるのは、グループカード、フォルダ由来のタグの区別、動画ページのメンバー一覧と自動再生の通知、フォルダ画面と動画ページのまとめ方の操作が、既存の画面に**加えるもの、または変えるもの**だけである。色、角丸、影のトークンは新しく加えず、`tokens.test.ts` の `pairs` にも何も加えない (後述の「アクセシビリティ」)。

## 画面の境界 {#screen-boundary}

| 場所 | 変わるもの |
| --- | --- |
| ライブラリ (`/`) のグリッド表示とリスト表示 | 要素が `LibraryItem` になる。グループの要素はグループカード (`web/src/library/`) とグループの行として現れる。通常の動画の要素は今の `VideoCard` と `VideoRow` のままで、見た目は変わらない。セクション、見出し、タブはない (要件 15) |
| カードと動画ページのタグ | フォルダ由来のタグは、手で付けたタグと形が異なる (要件 13)。有効なタグフィルタの行、候補一覧、管理ページは変わらない |
| 選択バー | `N 件を選択中` の N と `タグを外す` の候補が変わる (要件 21 と 13)。操作の並びは変わらない |
| 動画ページ (`/videos/:id`) | グループのメンバーを開いたときだけ: 題名の上の 1 行 (「グループの行」)、関連動画の列の上のメンバー一覧と区切り (「メンバー一覧」)、再生終了時の通知 (「自動再生の通知」)。グループ外の動画のページは変わらない (要件 27 の後半、受け入れ条件 17) |
| フォルダ画面 (`/folders/{rootId}/…`) | `動画 N` 見出し行の右端のまとめ方メニュー (「フォルダのまとめ方メニュー」)。一覧は引き続き動画を 1 本ずつ表示する (要件 22)。最上位 (`/folders`) と検索結果には何も加えない |
| ゲスト | グループカードは視聴状態と視聴済みの本数を省く。まとめ方メニュー、動画ページのメニュー、タグは表示しない ([data-model.md、利用者ごとの見え方](data-model.md#visibility-per-audience)) |

## グループカード {#group-card}

### 構造 {#structure}

グループカードは通常の動画カード (`VideoCard`) と同じ箱 (`rounded-lg`、`bg-surface`、`shadow-card`、ホバー時の浮き上がり、選択時の `ring-2 ring-accent`) を使い、同じ場所に同じ大きさで置かれる (要件 16、`UI品質` の「視覚的な階層」と「情報密度」)。サムネイルの枠にはフォルダ画面のフォルダカードと同じフォルダの絵を描くので、グループは「内容のそろったフォルダ」に見える。

| 部分 | 形 |
| --- | --- |
| **フォルダの絵** | 共通の `FolderArt` (`web/src/videoList/FolderArt.tsx`) をそのまま使う。タブ付きの背面パネルの上に、`previews` (サムネイルを生成済みのメンバー最大 4 本、順番どおり) が斜めに重なる。マウスを横に動かすと、その位置の 1 枚が前に出てプレビューを再生する。メンバーのサムネイルがなければ背面パネルだけを描く |
| **本数と長さのバッジ** | 背面パネルの右下 (`right-5 bottom-4`) に、動画カードの長さと同じ面 (`bg-navbar/85`、`text-[11px]`、`tabular-nums`) で `12 本`、続けて合計の長さ。前に出た画像より上 (`z-20`) にあり、操作できない (`pointer-events-none`)。合計の長さ (`durationMs`) がなければ本数だけを表示する。視聴済みの本数は数字では表示しない。絵がすでにフォルダを示しているので、lucide の `Folder` マークも置かない |
| **左上** | 選択チェックボックス (今と同じ位置) |
| **下部の進捗** | `watchState = inProgress` のときだけ: 動画カードと同じ `h-[5px]` のバーで、`bg-accent` の幅は `watchedCount / videoCount`。`watchedCount = 0` で視聴中 (最初のメンバーを途中まで見た) のときはバーの溝 (`bg-fg-subtle/50`) だけが見え、「見始めた」ことを示す。`role="progressbar"` の `aria-valuenow` は同じ比率で、アクセシブルネームは `視聴済みの本数の割合`。`unwatched` と `watched` では表示しない |
| **題名** | グループ名を `h3`、`text-sm font-medium` で 2 行に切り詰め、全体を `title` に入れる。動画の題名と同じスタイル (`UI品質` の「タイポグラフィ」)。`watched` のときは動画と同じく `text-fg-muted` |
| **タグの行** | メンバーのタグの和集合 (`tags`) を、動画カードと同じ `CardTagRow` で表示する。フォルダからだけ来たタグは「フォルダ由来のタグチップ」の形になる。タグがなければ行はない |
| **公開マーク** | 表示しない。グループの要素には `public` がない |

- 追加日、サイズ、`フォルダ` という語は表示しない。カードが加えるのは本数と長さのバッジだけで、高さは動画カードとそろう (`UI品質` の「情報密度」)。

### 押下と選択 {#pressing-and-selection}

- カード全体が `/videos/{openVideoId}` への 1 つのリンクで、(動画カードと同じく) `state.from` に今の一覧の URL を入れる。メンバー一覧の画面は開かない (要件 23、`要求を満たしたことにならない変更`)。アクセシブルネームは `〈名〉、〈N〉本のグループ` で、`watchedCount` が 1 以上なら `、〈M〉本を視聴済み` が続く。ゲストには本数までで止める。
- 選択チェックボックス (アクセシブルネーム `「〈名〉」のグループを選択`) をオンにすると、`videoIds` のメンバー全員を選択に加える。オフにするとメンバー全員を外す。メンバー全員が選択されているとき、カードは選択された見た目になる (要件 21)。選択バーの `N 件を選択中` の N はカードではなく動画の数 (メンバーを数える) である。タグの追加と削除、`公開` がその数に作用するからである。
- そのため、選択バーの全選択は、選択数を `total` (要素の数、つまりカードの数。今の `count >= total`) と比べて無効にしない。1 つのグループを選ぶと選択数が `total` を超え、未選択の要素が残っているのにボタンが無効になってしまう。無効になるのは送信中と、選択が最新の全選択 (`GET /api/library/ids`) の応答の `ids` の集合と等しい間だけである。動画を 1 本でも外すか加えるか、選択を解除する条件の変更があれば、再び有効になる。読み込んだ要素がすべて選択されていても、読み込んでいない要素が残っている場合があるので有効のままにする。
- 選択中 (1 件以上選択している) は、カードを押すと動画カードと同じくその選択を切り替える。
- カードにまとめの解除やタグへの変換の操作は置かない (`UI品質` の「操作の優先度」)。それらは動画ページの「グループの行」とフォルダ画面の「フォルダのまとめ方メニュー」にある。

### リスト表示の行 {#list-view-row}

リスト表示 (ライブラリのみ) のグループの行は、動画の行 (`VideoRow`) と同じ列を埋める。

| 列 | グループの行 |
| --- | --- |
| 選択 | 動画の行と同じチェックボックスで、意味は「押下と選択」のとおり |
| サムネイル | 最初のメンバーのサムネイル (`previews` の先頭)。`inProgress` のとき、下部の進捗は `watchedCount / videoCount` |
| 題名 | グループ名 (`/videos/{openVideoId}` へのリンク)。その下に、lucide の `Folder` (`size-3`) と `12 本` を置いた `text-xs text-fg-muted` の 1 行 |
| 視聴済み | `watched` なら動画と同じく `Check`。`inProgress` なら `tabular-nums` で `3 / 12`。`unwatched` なら空 |
| 長さ | 合計の長さ (不明なら空) |
| 画質 | 空 (メンバーごとに異なる) |
| サイズ | 合計 |
| 追加日 | `addedAt` (最新のメンバー) |

### 更新と削除 {#refresh-and-removal}

- 一覧に残っているグループカードは、メンバーの再生位置、タグ、`video` イベントが変わると `GET /api/folders/{rootId}/group` から取り直す。取り直しの間カードの見た目は変わらず (スケルトンなし)、応答が届くと置き換わる。
- 取り直しが 404 を返すと、カードを一覧から取り除く。件数の行の `total` は、次に一覧を読むまで残ることがある。取り除くときには何も知らせない。主な場面は、再生から戻ると上書き設定の変更でグループが単独の動画に戻っていたというもので、一覧を読み直せば整合する。

## フォルダ由来のタグチップ {#folder-derived-tag-chip}

3 つのタグチップの形 (014 の「タグチップ」) に、出どころの区別を加える。大きさ (`h-5`、`h-6`、`text-xs`) は変えず、形と面で区別する (要件 13、`UI品質` の「タイポグラフィ」)。

| 出どころ (`VideoTag`) | 形 |
| --- | --- |
| `manual` だけ、または `manual` と `fromFolder` の両方 | 今の動画タグチップ (`bg-elevated`、面あり) |
| `fromFolder` だけ | 面なし。破線の枠 `border border-dashed border-border-strong`。名前の前に lucide の `Folder` (`size-3`、`text-fg-subtle`、`aria-hidden`) |

- 破線の枠は「フォルダ構造から借りた」ことを伝える形であり、色だけの違いではない (`UI品質` の「アクセシビリティ」)。文字色は今のチップと同じ (カードでは `text-fg-muted`、動画ページでは `text-fg`)。面がないので、文字は親の面 (カードでは `surface`、動画ページでは `bg`、`+N` のポップオーバーでは `elevated`) の上に載る。どの組も `pairs` にすでにある。
- 操作できる形 (カード) でのアクセシブルネームは `〈名〉で絞り込む` のままで、その後に視覚的に隠した `（フォルダ名から）` が続く。
- 押したとき (そのタグで絞り込む) の動作は、出どころによらず同じである。
- **動画ページ**: `fromFolder` だけのチップには × がない (要件 13)。名前の部分は今と同じ `/?tag=<id>` へのリンクである。両方の出どころから付いたチップは今の形 (名前 + 縦線 + ×) を保つ。× を押すと手で付けた部分だけを外し、応答の後、チップは同じ場所で破線になる (消えない。受け入れ条件 9)。フォーカスは次のチップの × へ、なければ前のチップの × へ、それもなければ `タグを追加` の入力へ移る (014 と同じ規則。破線のチップには × がないので飛ばす)。
- **`タグを追加` の候補**: その動画にフォルダからだけ付いているタグも候補に出る。確定すると手でも付け、チップは面のある形になる。
- **選択バーの `タグを外す`**: 候補は `manualCount >= 1` の集計タグだけである。フォルダからだけのタグは外せないので、候補に出さない (`disabled` の行も出さない)。「一部」と件数は `manualCount` で決め、`一部 1 / 3 件` の分母は選択数のままである。選んだ動画のどれにも手で付けたタグがないときの文言は `選んだ動画に、外せるタグはありません` である (フォルダ由来のタグはあり得るので、`タグはありません` とは言わない)。
- 並びは API の順 (名前の自然順) のままで、出どころで分けない。

## 動画ページ {#video-page}

### グループの行 {#group-line}

`Video.group` があるときだけ、題名 (`h1`) の**上**に 1 行を置く (要件 25)。題名とタグのまとまり (`flex flex-col gap-2`) の最初の項目で、題名との間は `gap-2` である。

- 左から: lucide の `Folder` (`size-3.5`、`text-fg-subtle`、`aria-hidden`) → グループ名 (`text-fg-muted`、1 行で切り詰め、全体を `title` に入れる) → `text-fg-subtle` の `·` → `3 / 12` (`tabular-nums`)。行全体は `text-xs` (`sm` から `text-sm`)。題名 (`text-xl` から `text-2xl`) より小さく副次的な色なので、題名の上にあっても題名より先に目を引かない (`UI品質` の「視覚的な階層」)。
- ヘッダー帯のパンくずがすでに同じフォルダにリンクしているので、グループ名はリンクにしない。
- **所有者**には、行全体が `ChevronDown` (`size-3.5`) で終わるゴーストの `sm` `Button` (`-ml-2` で文字の左端を題名にそろえる) で、`ui/Menu` を開く (要件 29)。アクセシブルネームは `グループ「〈名〉」、12 本中 3 本目。まとめ方のメニュー`。項目:

| 項目 | 動作 |
| --- | --- |
| `まとめを解除` (lucide の `Ungroup`) | `PUT /api/folders/{rootId}/grouping`、`mode: ungroup` |
| `グループをタグに変える` (lucide の `Tag`) | `POST /api/folders/{rootId}/grouping/tag`。`group.folder.path` が空 (登録フォルダそのもの) のときは表示しない (contracts/folder-groups-api.md、[グループをタグに変える](contracts/folder-groups-api.md#turning-a-group-into-a-tag)) |

- `直下をまとめる` はない。動画ページが表示するのはすでにグループなので、意味をなさない。
- メニューが開いている間、Esc はメニューを閉じるだけでページは閉じない。フォーカスはトリガーに戻る (`ui/Menu` の既定)。動画ページは Esc を `window` のキャプチャ段階で受け取るので、開いた `ui/Menu` (`role="menu"`) を、今の除外 (速度メニュー、ポップオーバー) と同じく除外に加える。これは 012 の「操作の詳細」にある Esc の例外をもう 1 つ増やす。
- **ゲスト**には、行は操作できない文字である (`Video.group` はゲストにも公開されたメンバーから作る)。
- 操作の後、動画 (`GET /api/videos/{id}`) と関連動画を取り直す。`group` がなくなるので、この行、「メンバー一覧」、前後の矢印は通常の動画の形に戻る。ライブラリのスナップショットも破棄するので、ページを閉じると一覧を読み直す (Structural Decisions 10、受け入れ条件 3、4、5)。トーストで知らせる:

| 操作 | トースト |
| --- | --- |
| まとめの解除 | `「〈名〉」のまとめを解除しました` |
| タグに変えた、`created` が true | `タグ「〈名〉」を作り、まとめを解除しました` |
| タグに変えた、`created` が false | `タグ「〈名〉」を付け、まとめを解除しました` |

- 送信中、メニューのトリガーは `disabled` である。メニューを開くこと自体が操作なので、取り消しのための確認ダイアログはない。どちらの操作も、フォルダ画面のメニューで `自動` に戻せる (タグは管理ページで削除できる)。
- 失敗するとトーストを表示し、画面は変えない:

| 応答 | トースト |
| --- | --- |
| 400 `invalid_request` (タグ名の規則) | `「〈名〉」はタグの名前に使えないため、タグに変えられません` (Edge Case `グループをタグに変えられない名前`) |
| 409 `conflict` | `このフォルダはもうグループではありません`。動画と関連動画を取り直す (別のタブが先に変えた) |
| 404、その他 | `変更できませんでした` |

### メンバー一覧 {#member-list}

`RelatedVideos.group` があるときの右の列 (`lg` 未満では下) (要件 26)。

- 列の最初の見出し (`h2`、`text-sm font-semibold text-fg`) は `続けて再生` で、その右に `text-xs text-fg-muted tabular-nums` の `3 / 12` を置く (`flex items-baseline justify-between`)。これで、自動で続く範囲が、区切りに達する前に先頭で読める。
- その下に、メンバーを順番どおりに並べる (数千本でも切らない。Edge Case `大きなグループ`)。関連動画の応答は、現在のメンバーの周りの最大 100 本の窓だけを運ぶ (contracts/folder-groups-api.md §3)。一覧は残りを `GET /api/videos/{id}/group-members` で 100 本ずつ読む (issue 674、後述の「窓の外の読み込み」)。各行は今の関連動画の行の密度 (サムネイル `w-40`、長さのバッジ、題名 `text-sm font-medium`、行間の `gap-3`、ホバーの `bg-hover-wash`) を持ち (`UI品質` の「情報密度」)、次を加える:

| メンバー | 形 |
| --- | --- |
| すべての行 | 先頭 (サムネイルの左) に `w-5 text-right text-xs text-fg-muted tabular-nums` で順番の番号を置く。数えなくても今の位置と残りが読める |
| 視聴済み | 題名を `text-fg-muted` にし、その右に lucide の `Check` (`size-3.5`、`text-success`)。視覚的に隠した `視聴済み` を読み上げ、アイコンは `aria-hidden` |
| 途中まで視聴 | 今と同じ下部の進捗バー |
| **再生中** | リンクではない。`aria-current="true"`、面 `bg-active-wash`、左に `border-l-2 border-accent` (行の `-m-1.5 p-1.5` の輪郭の左端) を持つ行。題名の前に視覚的に隠した `再生中` を置く。操作できないので、ホバーの面は変わらない |

- **区切り**: メンバー一覧と関連動画の間に `border-t border-border` の線を 1 本引き、その上下に `pt-5` と `pb-2` を置く (行間の `gap-3` より 1 段大きい。`UI品質` の「余白のリズム」)。線の下は `h2` の `関連動画` (今の見出し)、続けて今の関連動画 (同じグループのメンバーは含まない。contracts/folder-groups-api.md、[動画のグループと関連動画](contracts/folder-groups-api.md#groups-of-videos-and-related-videos))。関連動画が 0 本なら、区切りも `関連動画` の見出しも現れない。
- `lg` 以上でのスクロール: 012 と同じく、列の最初の見出し行 (ここでは `続けて再生`) は上端にとどまり、その下のすべて (メンバー一覧 → 区切り → `関連動画` → 関連動画) は 1 つのコンテナの中でスクロールする。ページを開いたとき (別のメンバーへの移動を含む)、コンテナだけがスクロールし、現在のメンバーの行をその中に見せる (Edge Case `大きなグループ`、受け入れ条件 `数百本`)。ページと左の列は動かない。`lg` 未満ではページは動かない (プレーヤーが画面の上端から外れてしまう)。
- 描画する行: 読み込んだメンバーのうち見えている範囲の近くだけを、上下にさらに 4 行ずつ加えて描画する。範囲は `lg` 以上ではコンテナを、`lg` 未満ではページを基準に測る (#675)。現在のメンバーの行とフォーカスのある行は描画したまま保つ。
- `3 / 12` の位置はボタンだ。押すと、どの幅でも現在のメンバーの行を見える位置へスクロールする (`lg` 以上ではコンテナ、`lg` 未満ではページ)。遠くまでスクロールした視聴者もそこへ戻れる。
- **窓の外の読み込み**: 順番の番号と `3 / 12` は、窓の中ではなくグループ全体 (`offset` と `total`) で数える。

  | 端 | `lg` 以上 | `lg` 未満 |
  | --- | --- | --- |
  | 読み込んだ最後のメンバーの後 | コンテナをスクロールしていて、末尾が表示範囲の約 600px 以内に来たら次の 100 本を読む | ページのスクロール中に同じく読む |
  | 読み込んだ最初のメンバーの前 | 先頭が約 600px 以内に来たら前の 100 本を読み、加わった高さの分だけコンテナのスクロールをずらして、表示中の行が動かないようにする | ゴーストボタン `Show N earlier videos` で前の 100 本を読む。一覧の先頭はプレーヤーの下ですでに見えているので、スクロールで読むとページを開いた途端に読み込みが始まってしまう |

  読み込みに失敗すると、読み込んだ行を保ち、その端に `Couldn't load more of the group` と `Retry` ボタンを表示する。別のメンバーへ移ると、新しい窓から読み直す。
- メンバーの行は、関連動画の行と同じくホバーで一覧用のプレビューを再生する。
- 読み込み中と失敗の見た目は今の関連動画と同じ (スケルトンの行 6 本。`関連動画を取得できませんでした` と `再試行`)。関連動画の応答が届くまでメンバー一覧は表示できないので、それまで見出しは `関連動画` のままで、届くと `続けて再生` に変わる。
- **ゲスト**: `group.items` は公開されたメンバーだけを持ち、視聴済みのマークも進捗もない (`progress` なし)。番号は公開されたメンバーの中での順番である。

### 隣の動画の矢印 {#neighbor-arrows}

前後の矢印 (012 の「隣の動画の矢印」) は関連動画の応答の `prevId` と `nextId` に従うので、メンバーではグループの中を移動する。最初のメンバーには左の矢印がなく、最後のメンバーには右の矢印がない (要件 28)。アクセシブルネームとツールチップは今の `前の動画: 〈題名〉` と `次の動画: 〈題名〉` のままで、題名は `group.items` から取る。

### 自動再生の通知 {#autoplay-notice}

メンバーの再生が終わり `nextId` があるとき、今の再生終了のレイヤーに代えて通知のレイヤーを出す (要件 27)。レイヤーの重なり順、`bg-overlay`、操作バーを表示したままにすることは 012 の「再生終了」と同じで、一度に表示するレイヤーは 1 つだけである。

- 中央の `bg-navbar`、`rounded-lg`、`p-5`、`max-w-lg` の面に、上から (`gap-3`) 積む:

| 部分 | 形 |
| --- | --- |
| 1 行目 | `text-xs font-semibold text-accent` の `続けて再生`、その右に `text-xs text-fg-muted tabular-nums` の `5 秒後` (残り秒数、1 秒ごとに減る) |
| 次のメンバーへのリンク | サムネイル (`w-56`、`sm` 未満では隠す) と題名 (`text-base font-semibold`、2 行に切り詰め)。今の `次の動画` と同じ形 |
| カウントダウンのバー | 全幅の `h-1 rounded-full bg-fg-subtle/50` の溝で、`bg-accent` の残りが 5 秒かけて右から縮む。動きを減らす設定ではバーは残るが、滑らかな縮みは止まり、秒数が減るたびに段階的に縮む (`motion-reduce:transition-none`。状態は見えたままで、止まるのは動きだけ。[library-ui.md、幅のブレークポイントは CSS に置き、サイドバーは例外とする](../../docs/design-docs/library-ui.md#width-breakpoints-in-css-and-the-sidebar-exception) と 012 の「操作の詳細」) |
| 操作 | **左**に副次的な `取り消す` (lucide の `X`)、その右に主要な `今すぐ再生` (`Play`)。DOM の順も同じなので、Tab は先に `取り消す` に着く (`UI品質` の「操作の優先度」) |

- カウントダウンは通知が現れてから 5 秒である。0 になると次のメンバーを開き (`state.from` を引き継ぐ)、再生を始める。

| 出来事 | 動作 |
| --- | --- |
| **取り消し** (`取り消す`) | 通知のレイヤーが消え、今の再生終了のレイヤー (`次の動画` = 次のメンバー、`次を再生`、`もう一度見る`) が現れる (要件 27)。フォーカスが `取り消す` にあったなら、`次を再生` へ移る |
| **Esc** | 通知の表示中、Esc は取り消しになり、ページは閉じない。取り消した後は、今と同じく Esc でページを閉じる。012 の「操作の詳細」の Esc の例外 (速度メニュー、全画面) がもう 1 つ増える |
| **次のメンバーがなくなった** (Structural Decisions 12 の確認で 404) | 通知が消え、「次の動画なし」の再生終了のレイヤー (`もう一度見る` だけ) が現れる。文言は理由を示さない。開き直すと最新のグループで決まる |
| **最後のメンバー** (`nextId` なし) | 通知なし。`もう一度見る` だけの今のレイヤー (受け入れ条件 16) |
| **自動で開いたメンバーの再生に失敗する** | 今の再生失敗のレイヤー (`PlaybackFailure`) で止まり、それ以上進まない (Edge Case) |
| `最初に戻る` または操作バーの再生 | 今の再生終了と同じく、通知が消えて再生が再開する |

- **読み上げ**: レイヤーが現れると、視覚的に隠した `role="status"` が `再生が終わりました。5 秒後に次の動画「〈題名〉」を再生します` を**一度だけ**読む。秒数の文字とバーは `aria-hidden` なので、毎秒読み直されない (`UI品質` の「アクセシビリティ」)。フォーカスは、プレーヤーの中にあったときだけ `取り消す` へ移る (012 の「再生終了」と同じ)。
- 通知の表示中、タッチ用の中央の操作は隠す (012 の「オーバーレイのレイヤー」)。

## フォルダのまとめ方メニュー {#folder-grouping-menu}

フォルダ画面の `動画 N` 見出し行に、そのフォルダのまとめ方の操作を置く (要件 22、要件 7 と 11)。子フォルダのカードには置かない。カードは開くためのリンクであり、操作を加えると Tab の止まる場所が倍になる (013 の「検索結果」と同じ理由)。

- `Section` の見出し行を `flex items-center justify-between` にし、左に今の `h2` の `動画 N`、右にゴーストの `sm` `Button` のトリガーを置く。トリガーは lucide のアイコン + 文言 + `ChevronDown` (`size-3.5`) を持ち、`FolderSummary.grouping.grouped` で変わる:

  | `grouped` | アイコン | 文言 |
  | --- | --- | --- |
  | true | `Group` | `ライブラリで 1 件` |
  | false | `Ungroup` | `ライブラリで 1 本ずつ` |

  アクセシブルネームは `ライブラリでのまとめ方: 1 件にまとめて表示。メニューを開く` と `…: 1 本ずつ表示。…` である。文言は今の状態を述べ、押すとそれを変える。`grouped` は上書き設定と自動の規則の結果なので、直下の動画が 1 本のフォルダに上書き設定をしても `1 本ずつ` と読め、効果がないことをここで示す。
- トリガーは `text-fg-muted` (ゴーストの既定) で、見出し (`text-xs font-semibold text-fg-muted`) と同じくらい弱く、グリッドより先に目を引かない (`UI品質` の「操作の優先度」)。
- メニュー (`ui/Menu`、`align="end"`) は上から次を持つ:
  - `MenuLabel` の `ライブラリでのまとめ方`
  - `MenuRadioGroup` (今の `grouping.mode`): `自動` (`auto`)、`まとめを解除` (`ungroup`)、`直下をまとめる` (`groupDirect`)。項目の右に説明は置かない。下の行が説明する。
  - `text-xs text-fg-muted` の 1 行 `自動: 登録フォルダより下で、子フォルダが無く動画が 2 本以上のフォルダをまとめる` (`MenuLabel` と同じ余白、操作できない)。要件 2 の 3 つの条件をすべて述べるので、登録フォルダ自身の画面でも、`自動` がそのフォルダをまとめないことが読める。
  - `taggable` が true のときだけ、区切りと `グループをタグに変える` (lucide の `Tag`)。false のときは項目がない (contracts/folder-groups-api.md、[グループをタグに変える](contracts/folder-groups-api.md#turning-a-group-into-a-tag))。無効にした項目を残す案は採らない。登録フォルダそのものについては、理由を 1 行で示せない。
- ラジオを選ぶと `PUT /api/folders/{rootId}/grouping` を送り、応答の `grouping` からトリガーの文言とラジオを更新する。トーストはない。変わった文言が結果である。同じ値を再び選んでも送る (200)。
- `グループをタグに変える` は `POST …/grouping/tag` を送り、トーストで知らせる (「グループの行」と同じ文言)。トリガーは応答の `grouping` (`ungroup`) から更新する。
- どちらも応答でライブラリのスナップショットを破棄する (Structural Decisions 10)。次にライブラリを開くと、再スキャンなしでカードが変わる (受け入れ条件 3、4、5)。
- ラジオの変更ではフォルダ画面の一覧を読み直さない。一覧は引き続き動画を 1 本ずつ表示し、内容は変わらない (`FolderSummary` の `grouping` だけを応答から置き換える)。
- タグへの変換に成功すると、`grouping` を置き換え、フォルダ画面の動画一覧も読み直す (スクロール位置は保つ)。タグができると、中の動画は次の読み込みからフォルダ由来のタグを持つ (data-model.md、[フォルダ由来のタグ](data-model.md#folder-derived-tags)) が、画面上のカードの `tags` は応答に含まれず古いまま残ってしまう (これで要件 11 の結果をその場で示す)。
- 送信中、トリガーは `disabled` で、アイコンは `LoaderCircle` (`animate-spin`) になる。
- 失敗するとトーストを表示する:

| 応答 | トースト |
| --- | --- |
| 400 `invalid_request` | `「〈名〉」はタグの名前に使えないため、タグに変えられません` |
| 409 | `このフォルダはもうグループではありません` (フォルダの一覧を取り直す) |
| 404 | `このフォルダは見つかりません` |
| その他 | `変更できませんでした` |

- `動画` のまとまりがない (直下の動画がない) フォルダには見出し行がないので、メニューもない。登録フォルダそのもの (`path` が空) は同じ行に同じメニューを表示する (`直下をまとめる` は最上位でも働く。要件 7)。
- **ゲスト**には `grouping` がないので、トリガーもない (見出し行は今のまま)。
- 子フォルダのカードにはグループのマークを付けない。求められておらず、カードの下半分に情報を加えると 011 の件数の行と競合する。

## 操作の状態 {#interaction-states}

| 操作 | 状態 |
| --- | --- |
| グループカードと行 | `VideoCard` と `VideoRow` と同じ (ホバーでの浮き上がりと影、`has-[a:focus-visible]` による外側の輪郭、選択時の `ring-2 ring-accent`、`selectionMode` での `select-none`) |
| 破線のチップ | ホバーで文字が `text-fg` になり、枠は `border-border-strong` のまま実線になる (面のない形に `ring` を加えると二重の枠に見える)。フォーカスは全体の `:focus-visible` (カードの中では 014 と同じく内側の輪郭) |
| 「グループの行」のトリガー、「フォルダのまとめ方メニュー」のトリガー | ゴーストの `Button` の状態を引き継ぐ。`disabled` は送信中だけ |
| メンバーの行 | 関連動画の行と同じホバー。現在のメンバーの行は操作できず、ホバーで変わらない |
| 通知のレイヤーの操作 | 副次的と主要の `Button` の状態を引き継ぐ |

## アクセシビリティ {#accessibility}

- アクセシブルネーム:

| 操作 | 名前 |
| --- | --- |
| グループカードのリンク | `〈名〉、〈N〉本のグループ` (所有者で `watchedCount >= 1` のときは `、〈M〉本を視聴済み` が続く) |
| グループカードのチェックボックス | `「〈名〉」のグループを選択` |
| グループカードの進捗 | `視聴済みの本数の割合` |
| 破線のチップ | `〈名〉で絞り込む` + 隠した `（フォルダ名から）` |
| 「グループの行」のトリガー | `グループ「〈名〉」、〈N〉本中〈M〉本目。まとめ方のメニュー` |
| メンバーの行 | 今の関連動画と同じく `〈題名〉 〈長さ〉`。現在のメンバーは `aria-current="true"` と隠した `再生中` を持ち、視聴済みのメンバーは隠した `視聴済み` を持つ |
| 通知のレイヤー | `role="status"` の `再生が終わりました。5 秒後に次の動画「〈題名〉」を再生します` (一度だけ)。`取り消す`、`今すぐ再生` |
| 「フォルダのまとめ方メニュー」のトリガー | `ライブラリでのまとめ方: 1 件にまとめて表示。メニューを開く` または `ライブラリでのまとめ方: 1 本ずつ表示。メニューを開く` |

- まとまり: メンバー一覧は `続けて再生` の `h2` の下の `ul`、関連動画は `関連動画` の `h2` の下の `ul` である。2 つの `ul` は合わせないので、区切りはスクリーンリーダーにも明確である。
- 通知の秒数とバーは `aria-hidden` である。取り消しは、Tab が最初に着くボタンでも Esc でもできる。
- 色の組: 新しい組は使わない。破線のチップの文字は親の面 (`surface`、`bg`、`elevated`) の上の `fg` と `fg-muted`、通知のレイヤーの文字は `navbar` の上の `fg`、`fg-muted`、`accent` で、すべて `pairs` にある。`border-border-strong`、`bg-active-wash`、`bg-fg-subtle/50` は文字ではなく半透明なので、`pairs` の対象外である。新しいトークンは加えない。
