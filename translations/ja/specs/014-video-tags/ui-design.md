# UI 設計: 動画のタグとタグでの絞り込み {#ui-design-video-tags-and-tag-filtering}

**機能**: [親 Issue #193](https://github.com/syudead/vv/issues/193)

出典: 見た目の規則、シェル、一覧の密度は [Library UI: visual rules and list structure](../../docs/design-docs/library-ui.md) と [`web/src/index.css`](../../web/src/index.css) の `@theme` に従う。動画ページの構造は [012 の ui-design.md](../012-video-detail-ia/ui-design.md) に従う。ツールバー、一致なしの状態、`条件を解除` は [013 の ui-design.md](../013-library-search/ui-design.md) に従う。URL の形と履歴は [contracts/list-url.md](contracts/list-url.md) で、エラーの `code` と数は [contracts/tags-api.md](contracts/tags-api.md) で決まっており、この文書は決め直さない。この文書は、カードのタグの行、絞り込み中のタグ、動画ページのタグ、選択バーのタグの操作、タグ管理ページが既存の画面に**加えるもの、または変えるもの**だけを定める。新しい色、角丸、影のトークンは加えない。

## 画面の境界 {#screen-boundary}

| 場所 | この機能が加えるもの |
| --- | --- |
| ライブラリ (`/`) のグリッドのカード | タイトルの下のタグの行。ライブラリのリスト表示の行にはタグの行がない。フォルダの画面のカードにも同じタグの行があり、タグを押すとそのタグで絞り込んだライブラリ (`/?tag=<id>`) に移る |
| ライブラリの本文の上部 | タグで絞り込んでいる間だけ、要約の行の上に絞り込み中のタグの行。ツールバー (トップバーの中) には何も加えない |
| 動画ページ (`/videos/:id`) | タイトルの下のタグの一覧 |
| 選択バー | タグの一括の追加と削除の操作。[library-ui.md、一覧のレイアウト](../../docs/design-docs/library-ui.md#list-layout) に従って置く |
| タグ管理ページ (`/tags`) | `AppShell` の中。サイドバーの `フォルダ` の直後に `タグ` の項目 (lucide `Tags`) がある |

## タグのチップ {#tag-chip}

タグは役割の異なる 3 つの形で現れる。どれも 1 つの見た目の骨格 (`h-5` または `h-6`、`rounded-sm`、`px-1.5` から `px-2`、`text-xs`、省略を伴う 1 行) を共有し、色と印で見分ける。

| 形 | 場所 | 面と文字 | 印 | 押したとき |
| --- | --- | --- | --- | --- |
| 動画のタグ | カード、動画ページ | `bg-elevated`、`text-fg-muted` (動画ページでは `text-fg`) | なし | そのタグで絞り込む |
| 絞り込み中のタグ | 一覧の上 | `bg-accent-soft`、`text-link` (現在の `Chip` のアクセント) | 先頭に lucide `Tag`、末尾に `X` | その絞り込みを外す |
| 候補、まとめ | 候補の一覧、選択バー | 行の形 (下の "Combobox") | 一部にだけ付いているときの文言 | 追加または削除 |

- 長い名前は、チップの文字の `min-w-0 truncate` で末尾が省略され、`title` が名前全体を持つ。チップの最大幅はその行の幅 (`max-w-full`) なので、100 文字の名前でも 360px で横にはみ出さない。
- アクセントの色を持つのは絞り込み中のタグだけである。動画のタグは中立のままなので、色はどのタグで一覧を絞り込んでいるかも伝える。色だけが手がかりではない。絞り込み中のタグには `Tag` のアイコンと行の先頭の文言もある (下の「絞り込み中のタグ」) (`UI品質` の「アクセシビリティ」)。

## ライブラリのカード {#library-card}

### タグの行 {#tag-row}

- タイトルの `h3` の直下、現在メタデータの行がある場所に 1 行置く。タイトルとの間隔は現在の `gap-1`、下の余白は現在の `pb-3` のままにする (`UI品質` の「余白のリズム」)。
- 行は `flex flex-nowrap gap-1 overflow-hidden` である。チップは `gap-1` で等間隔に、API の順序 (名前の自然順) で並ぶ。
- 行とカードの `article` はどちらも内容を切り取るので、グローバルな `:focus-visible` の外側のアウトラインはチップの外で切れてしまう。カードのチップ (と `+N`) だけは、アウトラインをチップの内側に描く (`focus-visible:outline-offset-[-2px]`)。色と幅はグローバルのままである。
- チップは `h-5`、`text-xs` で、タイトル (`text-sm font-medium`) より小さく `text-fg-muted` なので、タイトルより先に目を引かない。視聴済みのカードではタイトルも `text-fg-muted` だが、大きさとチップの面で見分けられる。
- タグのない動画には行がなく、「タグなし」の文字もない。空の行は分類がないことを空白で伝えることになり、何も伝えない。グリッドの各行のカードは今と同じく同じ高さに揃う (`flex-wrap` の既定の `stretch`)。
- 行はカードの下端に置くので、タイトルが 1 行でも 2 行でも、グリッドの行の中でタグの行が揃う。そのために、行ではなくカードのリンクが `flex-1` で伸び、タイトルと行の間の空間はリンクの領域 (押すと開くか選択する) に属する。

### はみ出し {#overflow}

- 1 行に収まらないタグは行の末尾の `+N` のチップに置き換わり、収まるチップだけを表示する (`UI品質` の「情報密度」)。`+N` は動画のタグの形で、文字は `tabular-nums` である。フェードアウトは採用しない。名前が切れたのか、さらにタグがあるのかを示さないからだ。
- `+N` はボタンである。隠れたタグを同じチップとして縦に並べる `ui/Popover` を開く。チップを押すと、カードの行と同じくそのタグで絞り込み、ポップオーバーを閉じる。アクセシブルな名前は `ほかのタグ N 個を表示` である。
- 何個のチップが収まるかは、描画の後に行とチップの幅を測って決める。CSS だけでは数を出せない。library-ui.md の [幅のブレークポイントは CSS に置き、サイドバーは例外とする](../../docs/design-docs/library-ui.md#width-breakpoints-in-css-and-the-sidebar-exception) が避けるのは JavaScript で画面の幅によって分岐することであり、内容が収まるかを測ることとは別である。測る前に行が 1 フレームだけ伸び縮みしないよう、数は描画の前 (レイアウトのエフェクト) に決め、カードの大きさか画面の幅が変わったときに測り直す。一覧は仮想スクロールを使わない (library-ui.md、[仮想スクロールは使わない](../../docs/design-docs/library-ui.md#no-virtual-scrolling)) ので、読み込んだすべてのカードの行を監視する。カードごとに 1 つの監視ではなく、一覧の 1 つの `ResizeObserver` がすべての行を監視する。カードの幅はズームの段階ごとに一定なので、測り直しはズームの段階か画面の幅が変わったとき、またはタグが変わったときだけ実行する。

### カードの構造と押したとき {#card-structure-and-pressing}

- 現在、カード全体が動画ページへの 1 つのリンクである。タグの行はリンクの**外**、タイトルの下の同じ `article` の中に置く (リンクの中に操作できる要素を入れ子にしない)。区切り線はなく、1 つのカードに見えることは変わらない。
- カードのホバーでの浮き上がり、影、ホバーのプレビューは、今と同じくタグの行の上でも動く。
- 各タグのチップはボタンである。押すとそのタグを現在の条件に加え ([list-url.md、タグの追加と削除](contracts/list-url.md#adding-and-removing-a-tag))、動画ページには移らない。すでに絞り込み中のタグを押しても何も変わらず、チップは他と同じに見える (絞り込み中の印は一覧の上にだけ現れる)。
- 16 個が絞り込み中のときに 17 個目のタグを押しても加えず、トーストが `絞り込めるタグは 16 個までです` と伝える。
- **選択中** (1 つ以上の項目を選択している) は、タグのチップをボタンとして描かない。文字と面は残り、押すとカードの選択を切り替える (Edge Case `選択中にタグを押したとき`)。Tab の順序からも外れる。選択中にタグの名前とともに「絞り込む」と読み上げると、押したときの動作と矛盾する。`+N` も操作できなくなる。
- カードの中のキーボードの順序: チェックボックス → リンク (タイトル) → タグ → `+N`。

## 絞り込み中のタグ {#active-tag-filters}

- ライブラリの本文の上部、要約の行の上に 1 行置き、タグで絞り込んでいる間だけ表示する。タグの絞り込みがなければ場所を取らない。
- 行は要約の行と同じく中央に揃える (`flex flex-wrap justify-center items-center gap-1.5`)。`text-xs text-fg-muted` の文言 `タグで絞り込み中` で始まり、名前の自然順で絞り込み中のタグが続き、収まらなければ折り返す。
- 各チップは `Tag` のアイコン、名前、`X` のアイコンを持つ 1 つのボタンで、どこを押してもそのタグだけを外す (`UI品質` の `ワンクリックで届き`)。× だけを小さな的にする案は採用しない。チップ全体が 1 つの操作を持つので、的を小さくする理由がない。ホバーでは内側の `ring-1 ring-inset ring-border-strong` の縁が現れる (動画のタグのチップと同じ)。文字の色を変える案は採用しない。`accent-hover` と `link` は同じ値なので、目に見えて何も変わらない。
- 外した後、フォーカスは次のチップに、なければ前のチップに移り、最後の 1 つだったときは検索ボックスに移る。外したチップは消え、フォーカスの行き先も一緒に消えてしまうからだ (013 の一致なしの状態と同じ)。
- 階層: 行はツールバーの下の本文にあり、ツールバーの部品より小さい (`h-6`、`text-xs`)。グリッドより先に目を引くアクセントの面を持つのはこれだけなので、現在の条件がひと目で読める。
- タグの一覧が読み込まれる前は、各チップは名前の代わりに `Skeleton` (`w-12`) を持ち、URL の `id` ごとに 1 つ置き、読み込まれたら名前に置き換える。
- 絞り込みのメニューの `条件を解除` (013 の "Filter menu") はタグで絞り込んでいる間も現れ、押すとタグの絞り込みも外す。タグは絞り込みのボタンの数には数えない ([list-url.md、タグの追加と削除](contracts/list-url.md#adding-and-removing-a-tag))。
- 要約の行は書式を保ち、タグの名前を含めない。その件数は `tag` を含めた `total` である。
- 一致なしの状態 (013 の "No-match state") は、013 の現在の契約 (PR #262) により、検索語、絞り込み、検索範囲のチップや注記を持たず、`条件を解除` のボタンも持たない。タグの絞り込みも同じに扱い、一致なしの状態の中にチップや外す操作を加えない。絞り込み中のタグは一致なしの状態の上のこの行にだけ見え、ここか、絞り込みのメニューの `条件を解除` (タグを含めてすべてを外す) で外す。
- 検索語、視聴状態、再生できるか、タグを変えると選択を解除するので、異なる条件の一覧で選んだ動画が隠れたまま選択に残ることはない。

## 動画ページのタグ {#video-page-tags}

### 配置 {#placement}

- タイトル (`h1`) の直下。タグは動画を分類するもので、タイトルとともに読まれる。カードでもタイトルの直下に表示するので、一覧から開いたときも順序が同じになる。
- タイトルとタグの一覧は 1 つのグループ (`flex flex-col gap-2`) をなし、グループと区切り線の間隔は現在の `gap-5` である。タイトルとタグの間を `gap-5` にすると、タグが属性の側に属するように見える。
- 012 の「タイトルの下にチップやボタンを置かない」(Visual review criteria の「情報密度」) は、この機能がタグの一覧についてだけ改める。タイトルの下の要約の行、ボタン、その他のチップは置かないままである。
- 階層は、小さなチップ (`h-6`、`text-xs`) と中立の面で保つ。タイトル (`text-xl` から `text-2xl`、`font-semibold`) より先に目を引かない (`UI品質` の「視覚的な階層」)。
- ラベル (`TAGS` など) は置かない。チップの形でタグだとわかり、タイトルの直下のラベルの行は煩雑にする。グループの見出しは視覚的に隠した `h2` の `タグ` である。
- 一覧は `flex flex-wrap items-center gap-1.5` である。付いているタグのチップの後に、同じ行に `タグを追加` の入力を置く。行は折り返す。

### チップ {#chip}

- `h-6`、`text-xs`、`bg-elevated`、`text-fg`。名前の部分 (リンク) と × の部分 (ボタン) に分かれ、間に `bg-border-strong` の縦線 (`w-px h-3.5`) がある。

| 部分 | 要素 | 押したとき | アクセシブルな名前 |
| --- | --- | --- | --- |
| 名前 | `/?tag=<id>` への `Link`。移動するのでボタンではなくリンクであり、新しいタブで開ける (管理ページの名前と同じ) | このタグ 1 つで絞り込んだライブラリの一覧を開く | `〈名〉で絞り込む` |
| × | `size-6` の正方形、lucide `X` (`size-3`) | この動画からタグを外す | `〈名〉をこの動画から外す`。絞り込み中のタグの `〈名〉の絞り込みを外す` とは文言で区別する (`UI品質` の「アクセシビリティ」) |

- 外した後、フォーカスは次のチップの × に、なければ前のチップの × に移り、最後の 1 つだったときは `タグを追加` の入力に移る。
- チップはサーバーが応答した後に加わり、または消える。待つ間、その × は `disabled` で、入力は "Combobox" に書く送信中の状態になる。

### 追加の入力 {#add-input}

- コンポーネントは下の "Combobox" である。入力は `h-6`、`w-40`、`bg-field`、`border-border`、`rounded-sm`、`text-xs` で、左に lucide `Plus` (`size-3`、`text-fg-muted`)、プレースホルダーは `タグを追加` である。フォーカスで `border-accent` になる (検索ボックスと同じ)。
- 確定すると入力は空になってフォーカスを保つので、すぐに別のタグを加えられる。新しいチップは名前順の位置に入る。
- 入力にフォーカスがある間、動画ページのキー (Space、←→、F、M、0、Esc) は動作しない (`keyboard.ts` の現在の `isEditable`)。Esc は、候補の一覧が開いていれば閉じ、そうでなければ入力を空にする。空の入力での Esc は何もしない。ページを閉じるのは入力の外で押した Esc だけである。

### 状態 {#states}

| 状態 | 画面に表示するもの |
| --- | --- |
| 詳細の読み込み中 | タグの一覧なし (タイトルと同じくスケルトンの中) |
| タグなし | タイトルの下に `タグを追加` の入力だけ |
| 追加または削除の失敗 | 一覧のすぐ下に `text-xs text-danger` の 1 行 (`role="alert"`): `タグを付けられませんでした` または `タグを外せませんでした`。入力の文字は残り、Enter で再試行する。次の操作で消える |
| タグがもう存在しない (`tag_not_found`) | トースト `タグ「〈名〉」はもう無いため、一覧を取り直しました`。タグの一覧とこの動画を取り直す |

## Combobox {#combobox}

動画ページの `タグを追加`、選択バーの `タグを付ける` と `タグを外す`、管理ページの統合先の選択は、1 つのコンポーネント (`web/src/ui/legacy/Combobox.tsx`) を使う。ARIA 1.2 のコンボボックス (入力 + リストボックス、`aria-activedescendant`) である。

- 候補の一覧は入力の下 (選択バーでは上) に、`ui/Popover` と同じ面 (`bg-elevated`、`shadow-elevated`、`rounded-md`) で現れる。幅は `w-64` で、8 行を超えるとスクロールする。フォーカスで開き、入力が空のときはすべての候補を表示する。
- 候補の行は `h-8`、`px-2.5`、`text-sm` である。名前は `text-fg` で 1 行に省略し、右に補助の情報を `text-xs text-fg-muted tabular-nums` で置く (管理ページと同じく数。選択バーの削除の候補では、下の「一部」の印)。アクティブな行は `bg-hover-wash` である (メニューの項目と同じ)。
- 絞り込み: 名前か同義語が入力を含むタグを、大文字と小文字を区別せずに残す (管理ページの検索と同じ)。前方一致を先に、次に名前の自然順で並べる。同義語で一致したタグは、名前の下に `text-xs text-fg-muted` で `シノニム: アニメ` を表示する。表示する名前は常に元の名前である (要件 7)。
- 動画にすでに付いているタグは `タグを追加` の候補に出さない。
- 入力の綴りに完全に一致する名前も同義語もないとき、一覧の末尾に `「〈入力〉」を作成` の行 (lucide `Plus`) を置く。`Anime` があるとき、`anime` と入力するとこの行が出る (要件 4)。完全に一致するものがあれば出ない。

キー:

| キー | 動作 |
| --- | --- |
| ↓、↑ | 行の間を移動する。端で止まる |
| Enter、行がアクティブ | その行を確定する |
| Enter、アクティブな行なし | 入力の綴り (前後の空白を除く) を確定する。名前か同義語が一致するタグ、なければ新しいタグ。作成の行を持たない形 (選択バーの `タグを外す`、統合先) は、綴りが候補の名前か同義語に完全に一致するときだけ確定し、それ以外は何もしない |
| Tab | 確定せずに一覧を閉じて次へ移る |
| Esc | 一覧が開いていれば一覧だけを閉じる。ポップオーバーやダイアログの中のコンボボックスでは、一覧が閉じていればそのポップオーバーかダイアログだけを閉じる。どちらの場合も Esc はそこで止まり、外側 (選択の解除、動画ページを閉じること) には届かない。動画ページの入力での Esc は上の「追加の入力」のとおりに動く |

- 名前の検証 (要件 4): 入力のたびに確かめる。名前を作れないとき、入力の下の `text-xs text-danger` の 1 行が理由を示し、Enter を受け付けない。理由は `改行やタブは使えません` と `100 文字以内にしてください（今 101 文字）` である。空または空白だけの入力は、入力中には理由を示さない (確定の後や開いたときの空の入力は正常である)。その状態で Enter を押したときだけ `名前を入力してください` を示す。文字数は、JavaScript の `length` (UTF-16 の単位) ではなく、サーバーと同じく前後の空白を除いた名前のコードポイントで数える ([data-model.md、Name rules](data-model.md#name-rules))。入力は `maxLength` を持たない。理由を示す手段なしに 101 文字目を黙って落とすからだ。入力の `aria-describedby` は理由の行を指す。
- 改行は入力の値の中には見つからない。1 行の `input` は値に届く前に改行 (LF、CR) を取り除くので、`旅行\n2024` を貼り付けると `旅行2024` になり、別の名前を確定してしまう。そのため、元の文字列を貼り付け (`paste` の `clipboardData`) とドロップ (`beforeinput` の `insertFromDrop`) の時点で確かめる。改行を含むときは入力に取り込まず (`preventDefault`)、値は元のままで、理由 `改行やタブは使えません` が現れる。理由は入力が次に変わるまで残り、それまでは Enter も確定のボタン (`作成`、`追加` など) も受け付けない。貼り付けの前の名前がまだ入力にあり、確定するとユーザーが貼り付けた名前ではなくその名前を確定してしまうからだ。入力が変わると理由は消え、新しい値は確定を受け付ける前に上の検証を通る。改行を除いた部分だけを取り込む案は採用しない。貼り付けたものと異なる名前が黙って入力に入ってしまう。タブとその他の制御文字は値に残り、入力ごとの検証で捕まる。この扱いは、タグの名前を入力するすべての入力 ("Combobox" と、管理ページの作成、名前の変更、同義語の追加) で同じである。
- 送信中、入力は `aria-busy="true"` を持ち、Enter を受け付けない。入力の右端に `LoaderCircle` (`size-3`、`animate-spin`) を表示する。

## 選択バー {#selection-bar}

2 つのタグの操作は 1 つのメニューにまとめない。狭い幅では手順が 1 つ増えるからだ。

### 追加 {#add}

- 押すとバーの上に "Combobox" を持つ `ui/Popover` を開く (現在の `PopoverContent` は向きを取らないので、上に開くための `side` プロパティを加える)。フォーカスは入力に移る。候補はすべてのタグで、それぞれ右に数を持つ。確定するとタグを選択したすべての動画に加え、ポップオーバーを閉じ、トーストが `N 件に「〈名〉」を付けました` と伝える。フォーカスは `タグを付ける` に戻る。
- 追加の後も選択は残るので、続けて別のタグを加えたり外したりできる。

### 削除 {#remove}

- 押すと同じ種類のポップオーバーを開き、選択した動画のタグのまとめを取得する。届くまで、ポップオーバーは `読み込み中…` (`text-xs text-fg-muted`、`role="status"`) を表示する。
- 内容は作成の行のない "Combobox" で、候補はまとめのタグだけである。各行の右に、すべての動画に付いているタグは `3 件` を、一部にだけ付いているタグは lucide `CircleDashed` (`size-3`) と `一部 1 / 3 件` を表示する (要件 2)。色は変えない。`一部` という言葉とアイコンで見分け、行のアクセシブルな名前は `一部の動画だけ、3 件中 1 件` を含む。
- 確定するとタグを選択したすべての動画から外し、トーストが `N 件から「〈名〉」を外しました` と伝える。
- 選択した動画のどれにもタグがないとき、ポップオーバーは `選んだ動画にタグはありません` を表示する。
- まとめを取得できないとき、ポップオーバーは `text-xs text-danger` の 1 行 (`role="alert"`) `タグを取得できませんでした` と、ghost の `sm` の `Button` `再試行` を表示する。選択は残る。

### 失敗 {#failure}

- 失敗したとき、ポップオーバーは開いたままで、入力の下に `text-xs text-danger` の 1 行 (`role="alert"`) を表示する: `付けられませんでした。もう一度お試しください` または `外せませんでした。もう一度お試しください`。選択と入力の文字は残り、Enter で再試行する (Edge Case `一括操作の途中失敗`)。
- `tag_not_found` はトースト `タグ「〈名〉」はもう無いため、一覧を取り直しました` を表示し、ポップオーバーの候補は取り直したタグの一覧から作り直す。選択は残る。

## タグ管理ページ {#tag-management-page}

### レイアウト {#layout}

- 本文の幅と余白は設定ページと同じ (`mx-auto max-w-4xl px-4 py-6 sm:px-6 sm:py-8`)。上から、`h1` の `タグ`、操作の行、件数の行、タグの一覧。トップバーには何も置かない。
- 操作の行は、左に検索の入力 (ライブラリの `SearchBox` と同じ見た目。プレースホルダーとアクセシブルな名前は `タグを検索`。`flex-1 sm:max-w-sm`)、右に secondary の `Button` `新しいタグ` (lucide `Plus`) を持つ。検索の入力は本文の最初の Tab の停止位置である (`UI品質` の「管理ページでは検索の入力にキーボードだけで届く」)。ライブラリの検索ボックスと同じく、`/` キーで検索の入力に移る。
- 件数の行は `text-xs text-fg-muted tabular-nums`、`role="status"`、`aria-live="polite"` で、`12 個のタグ`、検索中は `3 / 12 個のタグ` である。

### 行 {#rows}

- 一覧は `divide-y divide-border` の行で (設定ページのメディアフォルダと同じ)、周りに枠もカードもない。各行は `py-2` で、多くのタグを見渡せる密度である (`UI品質` の「情報密度」)。
- 行は左から、名前の列 (`flex-1 min-w-0`)、数、操作を持つ。

| 部分 | 形 |
| --- | --- |
| 名前 | `text-sm font-medium text-fg`、1 行に省略し、名前全体は `title`。`/?tag=<id>` へのリンク (要件 6 の「ナビゲーション」)。ホバーで `text-link`。アクセシブルな名前は `〈名〉で絞り込んだライブラリを開く` |
| 同義語 | 名前の下に `text-xs text-fg-muted` の 1 行、`シノニム: anime · アニメ`。なければ行はない。1 行に省略し、全文は `title` |
| 数 | `text-sm text-fg-muted tabular-nums`、右揃えの `w-16`、`12 本`。0 は `0 本` と表示する |
| 操作 | `IconButton` (ghost、`sm`) の `改名` (`Pencil`) と `シノニム` (lucide `Tags`)、その後に `別のタグへ統合…` (`Merge`)、区切り線、`削除…` (`Trash2`、`text-danger`) を持つ `その他の操作` のメニュー (lucide `Ellipsis`) |

- 削除と統合は取り消せないので、行ではなくメニューに置く (`UI品質` の「削除と統合を作成と名前の変更より目立たせない」)。設定ページのメディアフォルダは削除を行に表示するが、その行の操作は 2 つだけである。ここでは 4 つあるので、行を軽く保つことを優先する。
- 階層: 名前が主で、数と同義語は従である (`UI品質` の「視覚的な階層」)。

### 作成と名前の変更 {#create-and-rename}

- `新しいタグ` は一覧の先頭に入力の行を挿入し、フォーカスをそこへ移す。入力は "Combobox" と同じく検証して理由を示すが、候補の一覧はない。Enter で作成し、Esc か `キャンセル` で閉じる。行の右に primary の `sm` の `Button` `作成` と ghost の `sm` の `キャンセル` がある。作成すると、行は名前順の位置に入り、フォーカスはその名前に移る。
- `改名` は行の名前を同じ入力に置き換え、現在の名前を選択してフォーカスする。Enter で確定し、Esc で元に戻す。確定の後、フォーカスは `改名` に戻る。
- 名前が既存の名前か同義語と衝突するとき (`tag_name_taken`)、サーバーの `message` (`「anime」は「Anime」のシノニムです` の形) が入力の下に `text-xs text-danger` で現れ、入力は残る。

### 同義語 {#synonyms}

- `シノニム` は `ModalFrame` のダイアログ `「Anime」のシノニム` を開く。
  - 上部に、現在の同義語を × を加えた `Chip` として表示する。ダイアログの面は `bg-elevated` で、中立の `Chip` と同じ色なのでチップの面が消えてしまう。そのため、これらのチップだけは `bg-bg` を使う (`bg` の上の `fg` は `pairs` にある)。× のアクセシブルな名前は `シノニム「アニメ」を解除` である。外すことは確認なしにすぐ行われる (名前を解放するだけで、動画のタグは変わらない)。
  - その下に `シノニムを追加` の入力 ("Combobox" と同じく検証し、候補はない) と secondary の `Button` `追加`。
  - 名前が別のタグの同義語と衝突するとき、`message` (どのタグの同義語か) が入力の下に現れる (Edge Case `シノニム名の衝突`)。
- 加える名前が既存のタグの名前のとき (要件 6 の「同義語の追加」)、同じダイアログが確認に切り替わる。
  - 文言: `「anime」は 10 本の動画に付いているタグです。「Anime」に統合すると、その 10 本に「Anime」が付き、「anime」とそのシノニムは「Anime」のシノニムになります。「anime」はタグの一覧から消えます。` 同義語のないタグでは `とそのシノニム` を省く (Edge Case `統合とシノニム`)。数は `GET /api/tags` の `videoCount` である (受け入れ条件 17)。
  - 操作: secondary の `Button` `戻る` (最初のフォーカス) と danger の `統合する`。`戻る` は変更なしに入力に戻り、入力の文字を保つ。
  - `tag_merge_required` のとき、タグの一覧を取り直し、新しい数で確認をもう一度表示する。

### 統合と削除 {#merge-and-delete}

- `別のタグへ統合…` は `ModalFrame` のダイアログ `「X」を統合` を開く。統合元は行のタグで、統合先は "Combobox" で選ぶ (統合元を除くすべてのタグ、作成の行なし)。選ぶと、確認 `「X」が付いた 5 本の動画に「Y」が付きます。「X」とそのシノニムは「Y」のシノニムになり、「X」はタグの一覧から消えます。この操作は取り消せません。` が下に現れる。操作は secondary の `キャンセル` と danger の `統合する` で、`統合する` は統合先を選ぶまで `disabled` である。
- `削除…` は、文言 `12 本の動画からこのタグが外れます。この操作は取り消せません。` (受け入れ条件 11)、動画が 0 本なら `このタグはどの動画にも付いていません。` を持つダイアログ `「X」を削除` を開く。操作は secondary の `キャンセル` (最初のフォーカス) と danger の `削除する` である。
- 実行中は両方のボタンが `disabled` で、danger のボタンは `LoaderCircle` を表示する (設定ページのフォルダの変更の確認と同じ)。
- 終わるとダイアログを閉じ、トーストが `統合しました` または `削除しました` と伝える。フォーカスは、統合の後は統合先の行の名前に、削除の後は次の行の `改名` に、なければ前の行のものに、行が残っていなければ `新しいタグ` に移る。

### 状態 {#states-1}

| 状態 | 画面に表示するもの |
| --- | --- |
| 読み込み中 | 件数の行 `読み込み中…`。一覧の場所に `Skeleton` の行 (`h-10`) を 6 つ |
| 読み込みの失敗 | `EmptyState` (danger、`AlertCircle`) `タグを取得できません`、`Button` `再試行` |
| タグなし | `EmptyState` (lucide `Tags`) `タグはまだありません`、説明 `動画の再生画面や、ライブラリの選択バーから付けられます。ここで先に作っておくこともできます。`、primary の `Button` `新しいタグ`。検索の入力は見えたままで `disabled` である |
| 検索に一致なし | `EmptyState` (`SearchX`) `「〈入力〉」に一致するタグはありません`、`Button` `検索をクリア`。押すと入力を空にしてフォーカスをそこへ移す。「タグなし」とは見出しとアイコンで見分ける |
| 操作の失敗 | ダイアログの中か入力の下に `text-sm text-danger` の 1 行 (`role="alert"`)。ダイアログと入力は開いたまま |
| タグがもう存在しない (`tag_not_found`) | ダイアログを閉じ、トーストが `このタグはもう無いため、一覧を取り直しました` と伝える。一覧を取り直す |

## 他の画面の古いタグ {#stale-tags-in-other-screens}

- すべて選択の応答に `missingTagIds` があるとき、選択は作らない。削除されたタグを絞り込みから外して伝える。ユーザーは直った一覧でもう一度すべて選択を押す ([tags-api.md、List filter and Select all](contracts/tags-api.md#list-filter-and-select-all))。
- ライブラリの URL の `tag` がもう存在しないタグを含むとき (`missingTagIds`、またはスナップショットから復元するときの確認)、トーストが `削除されたタグを絞り込みから外しました` と伝え、チップは絞り込み中のタグの行から消える ([list-url.md、Parameters](contracts/list-url.md#parameters))。外したタグの名前はタグの一覧からわからないことがあるので、文言には含めない。
- カードと動画ページのタグは、一覧か動画を次に取得するまで古い名前のままのことがある。押して `tag_not_found` か `missingTagIds` になったとき、画面は上のとおりに伝えて直す。

## 操作の状態 {#interaction-states}

加えるコントロール (チップ、`+N`、候補の行、選択バーのボタン、管理ページの行の操作) は、ホバー、focus-visible、押下中、無効を元のコンポーネント (`Button` の ghost と secondary、`IconButton`、`ui/Menu` の項目、`Chip`) から受け継ぐ。独自の状態の色は作らない。動画のタグのチップはホバーで文字を `text-fg` にし、内側の `ring-1 ring-inset ring-border-strong` の縁を表示する。`elevated` より明るい不透明な面のトークンがないので、面の色は変えない。フォーカスはグローバルな `:focus-visible` (`link` の色の外側のアウトライン) である。カードの中のタグにフォーカスがあるとき、カードの外側のアウトライン (`has-[a:focus-visible]`) は現れず、チップのものだけが現れるので、リンクとタグのどちらにフォーカスがあるかがはっきりする。

## アクセシビリティ {#accessibility}

- アクセシブルな名前:

| コントロール | 名前 |
| --- | --- |
| 動画のタグ (カード、動画ページ、`+N` の中) | `〈名〉で絞り込む` |
| 絞り込み中のタグ | `〈名〉の絞り込みを外す` |
| 動画ページの × | `〈名〉をこの動画から外す` |
| `+N` | `ほかのタグ N 個を表示` |
| 管理ページの名前のリンク | `〈名〉で絞り込んだライブラリを開く` |
| 選択バーの一部だけの候補 | `〈名〉、一部の動画だけ、N 件中 M 件` |

- まとまり: カードのタグは `aria-label="タグ"` の `ul`、絞り込み中のタグは `aria-label="絞り込み中のタグ"` の `ul`、動画ページは隠した `h2` の `タグ` の下の `ul` である。
- 検証の理由は入力の `aria-describedby` を、操作の失敗は `role="alert"` を、件数の変化は `role="status"` (`polite`) を使う。
- 色の組: 文字に使う組のうち、`elevated` の上の `fg` と `fg-muted` (チップ、候補)、`bg` の上の `fg` (ダイアログの同義語のチップ)、`bg` の上の `danger` (動画ページと管理ページの本文の理由と失敗の行) は、すでに `tokens.test.ts` の `pairs` にある。`elevated` の上の `danger` は `pairs` にない (計算で約 5.9 で、4.5 を満たす)。これは選択バーのポップオーバーと管理ページのダイアログの中 (`ModalFrame` は `bg-elevated`) の理由と失敗の行に使う。この選択バーの組を `pairs` に加える。絞り込み中のタグの `accent-soft` の上の `link` は、現在の `Chip` のアクセントと同じ組である。`accent-soft` は半透明なので `pairs` の外にある (`tokens.test.ts` は 6 桁の 16 進の値だけを読む)。新しいトークンは加えない。
