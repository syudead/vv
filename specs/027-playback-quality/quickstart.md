# Quickstart: 遅い回線での画質の選択と警告を確かめる

`task check` が走らせる単体テスト・ffmpeg 付きの Go テストと、`task test-e2e` の e2e で確かめられない
ことをここで確かめる。回線を絞った再生（親 Issue #521 受け入れ条件 9・10）と、ハードウェアの方式での
上限（Edge Case 6）は実機で見る。結果は実装 PR の本文に残す。

## 前提

- `task dev` か `task preview` で VVMDM が動いていること。1080p 以上で、直接再生できる動画
  （H.264 の MP4）を 1 本以上取り込んでおく（`web/e2e/media-fixtures.mjs` の生成物を流用してよい）。
- Chrome か Firefox の開発者ツール（ネットワークの速さを絞る機能）。
- Edge Case 6 のために、ハードウェアエンコーダーのあるホスト
  （[specs/025-hardware-encoding/quickstart.md](../025-hardware-encoding/quickstart.md) の前提）。

## 手順

1. 1080p の動画を開き、操作バーの画質メニューを開く。「元の画質」「720p」「480p」「360p」だけが
   あり、`1080p` が無いこと（受け入れ条件 1）。
2. 再生中に「480p」を選ぶ。同じ位置から再生が続き、「変換して再生中」の表示から 480p で変換して
   いることが分かること（受け入れ条件 2）。開発者ツールのコンソールで
   `document.querySelector("video").videoHeight` が `480` であること。
3. 止めた状態で「360p」を選ぶ。止まったまま同じ位置にいること（受け入れ条件 4）。
4. 「480p」のまま再生バーでシークする。シークした位置から 480p のまま続き、`videoHeight` が `480`
   のままであること（受け入れ条件 7）。
5. ビットレート（受け入れ条件 3）: `curl --max-time 20 -o out.mp4 --cookie "<セッション>" "http://localhost:8080/api/videos/<id>/transcode.mp4?startMs=0&quality=480p"`
   で 20 秒分ほど受け取る。途中で止めた fragmented MP4 は `format`・`stream` の `bit_rate` を出さない
   ことがあるので、受け取ったパケットから求める。
   `ffprobe -v error -select_streams v:0 -show_entries stream=width,height -of csv=p=0 out.mp4`
   で映像の短辺が 480 であること。
   `ffprobe -v error -show_entries packet=pts_time,size -of csv=p=0 out.mp4 | awk -F, '$1!="N/A"{if(n==0||$1<a)a=$1;if($1>b)b=$1;s+=$2;n++} END{printf "%.0f kbps\n", s*8/(b-a)/1000}'`
   で、映像と音声を合わせた平均が 1300 kbps 程度以下であること
   （[contracts/transcode-quality-api.md §2](contracts/transcode-quality-api.md#2-画質ごとの変換の約束)）。
   ffmpeg は実時間より速く変換するので、受け取った時間ではなくパケットの時刻の幅で割る。
6. 別の動画（480p より大きいもの）を開く。「480p」で始まること。ページを読み直しても同じ。
   480p 以下の動画を開くと「元の画質」で始まり、メニューには「元の画質」だけがあること
   （受け入れ条件 5、Edge Case 1・2）。
7. 「元の画質」に戻す。直接再生できる動画は直接再生に戻る（「変換して再生中」が消える。
   受け入れ条件 6）。
8. ゲストで開き（所有者のセッションを持たないブラウザ）、画質を選べて選んだ画質で再生できる
   こと（受け入れ条件 8）。
9. 警告（受け入れ条件 9〜11）: 「元の画質」で 1080p の動画を再生し、開発者ツールで回線を
   元のビットレートより遅い速さ（例: 「Slow 3G」や 1 Mbps の自作の設定）に絞る。60 秒の間に
   データ待ちが 3 回起きる（または 1 回が 10 秒を超える）と、プレイヤーの上に警告が出ること。
   再生は止まらず、操作バーと中央の操作（タッチの端末）が使えること。警告に画質を切り替える
   操作が無く、画質が変わっていないこと。閉じると、同じ動画の再生の間は出ないこと。
   別の動画を開いて同じ条件にすると、また出ること。
10. 回線を絞ったままシーク・一時停止・再開し、その直後の読み込み待ちだけでは警告が出ないこと
    （Edge Case 8）。
11. Edge Case 6（ハードウェアのあるホストだけ）: 設定画面でハードウェアの方式を選び、手順 5 を
    繰り返す。短辺とパケットから求めた平均が同じ範囲に収まること。ホストのプロセス一覧で
    `-maxrate 1200k` が見えること。
