# Contract: タグを押したときの検索語

親 Issue: #193。Plan: [plan.md](../plan.md)。

カードや再生画面でタグを押すと、そのタグ名を検索欄の語にしたライブラリ一覧になる
（要件 5）。検索の書き方と URL の `q` は #195 の
[list-api.md §1](../../013-library-search/contracts/list-api.md#1-検索語の書き方) と
[list-url.md](../../013-library-search/contracts/list-url.md) が正本で、この文書は、タグ名を
その書き方の語に直す規則と、今の検索語への足し方だけを書く。URL のパラメータも API も
足さない。

## 1. タグ名から語を作る

`web/src/library/` の1つの関数で、タグの元の名前から語を作る。

1. 名前に空白が無く、`"` と `-` で始まらず、`OR` と `|` のどちらでもなければ、名前を
   そのまま語にする（`旅行` → `旅行`）。
2. 1 に当たらず、名前に `"` を含まなければ、`"` で囲んだフレーズにする
   （`夏 旅行` → `"夏 旅行"`、`-1` → `"-1"`、`OR` → `"OR"`）。
3. 名前に空白と `"` の両方を含むなど、1つの語で名前を表せないときは、空白で区切った
   各部分を 1 と 2 の規則で語にし、空白で並べる（AND）。部分の先頭の `"` は取り除く。
   名前そのものの並びには当たらなくなるが、その名前のタグを持つ動画には必ず当たる。

どの規則でも、作った語は #195 の書き方で解釈すると、名前の文字（3 では各部分の文字）を
字面どおりに探す語になる。照合形（`FoldForMatch`）は検索の側で掛かるので、ここでは掛けない。

## 2. 今の検索語への足し方

- ライブラリ一覧で押したときは、今の `q` の後ろに空白を1つはさんで語を足す。
- 今の `q` を空白で区切った部分（`"…"` の中は区切らない）に、作った語と同じ文字列が
  あれば、足さずにそのままにする（受け入れ条件 8）。
- 足した結果が `q` の上限（100 符号位置）か語の数の上限（16 語、
  `domain.MaxSearchTerms`）を超えるときは、`q` を変えずに、足せないことを伝える
  （Edge Case「検索欄の上限」）。
- 再生画面と管理画面から開くときは、作った語だけを `q` にした `/?q=…` を開く。視聴状態・
  再生可否・並べ替えの条件は付けない。並べ替えは #195 の規則どおり端末に保存したものに
  なる。
- `q` を変えるときの履歴の扱いは、#195 の「条件を変えて履歴を増やす」と同じで、1回押す
  ごとに1つ増える。

## 3. 検索が始まった後

- 足した語は検索欄のふつうの文字である。利用者は検索欄で消したり書き換えたりでき、
  「条件を解除」でも消える。
- タグが改名・削除されたあとも、`q` に残った語はふつうの検索語として扱う。当たる動画が
  あれば出し、無ければ #195 の一致なしの状態になる。
