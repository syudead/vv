# Feature Specification: MP4 ライブ変換による動画再生

**Feature Branch**: `codex/live-mp4-playback-feature`

**Created**: 2026-09-22

**Status**: Draft

**Parent Issue**: #100

**Input**: User description: "直接配信、無理なら MP4 ライブ変換、失敗したらエラー表示"

## Original Request

要求者が 2026-09-22 に示した要求を、そのまま保持する。

```text
直接配信
↓ 無理なら
MP4ライブ変換
↓ 失敗したら
エラー表示
```

この要求は、特定の拡張子だけではなく、ライブラリへ取り込める動画全体に適用する（以下、
この引用を **OR-001** と呼ぶ）。Issue #100 で明示された既存体験の維持、すなわちシーク、
続きからの再生、元ファイルを変更しないことも要求に含む（以下 **OR-002** と呼ぶ）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 形式を意識せず動画を再生する (Priority: P1)

利用者は、一覧から動画を選ぶだけで再生を始められる。ブラウザが元ファイルを直接扱える
場合はそのまま再生され、直接扱えない場合は、利用者がファイルを変換したり外部プレイヤーを
開いたりしなくても、再生可能な MP4 へライブ変換して同じプレイヤー内で再生される。

**Why this priority**: ファイル形式を理由にライブラリ内の動画を見られない状態をなくすことが、
OR-001 の中心的な価値である。

**Independent Test**: ブラウザが直接再生できる動画と直接再生できない動画を1本ずつ一覧から
開き、どちらも事前変換や外部アプリなしで同じ再生画面から再生できることを確認する。

**Acceptance Scenarios**:

1. **Given** ブラウザが元ファイルを直接再生できる動画、**When** 利用者が一覧から選ぶ、
   **Then** 元ファイルが直接配信され、映像と音声を再生できる
2. **Given** 解析済みで直接再生できないと判定された動画、**When** 利用者が一覧から選ぶ、
   **Then** 事前の手作業なしに MP4 ライブ変換が開始され、同じプレイヤーで映像と音声を
   再生できる
3. **Given** 直接再生できると判定されたが実際のブラウザでは再生に失敗する動画、**When**
   プレイヤーがその失敗を検出する、**Then** 利用者の追加操作なしに MP4 ライブ変換へ1度だけ
   切り替わる
4. **Given** 容器だけを変えればブラウザで再生できる動画、**When** MP4 ライブ変換で再生する、
   **Then** 不要な品質劣化を加えずに再生できる

---

### User Story 2 - ライブ変換中も通常どおり視聴する (Priority: P2)

利用者は、ライブ変換されているかを意識せず、任意の位置へ移動し、途中で閉じた動画を次回
その続きから視聴できる。直接配信の動画とライブ変換の動画で、基本的な再生操作が変わらない。

**Why this priority**: 再生できてもシークと続きからの再生が失われれば、既存の再生体験を
置き換えられず、OR-002 を満たさない。

**Independent Test**: ライブ変換される動画を途中まで再生し、離れた位置へシークしたあとに
再生が続くことを確認する。画面を閉じて同じ動画を開き直し、中断位置から再開することも確認する。

**Acceptance Scenarios**:

1. **Given** ライブ変換で再生中の動画、**When** 利用者が未再生の位置へ移動する、**Then**
   その位置から変換と再生が続き、先頭まで待ち直す必要がない
2. **Given** ライブ変換で途中まで視聴した動画、**When** 利用者が再生画面を閉じてから同じ動画を
   開き直す、**Then** 保存された中断位置からライブ変換と再生を再開できる
3. **Given** ライブ変換中の動画、**When** 利用者が再生画面を離れる、**Then** その視聴のための
   不要な処理は終了し、ほかの動画の閲覧や再生を妨げない

---

### User Story 3 - 再生失敗を確認する (Priority: P3)

直接配信にも MP4 ライブ変換にも失敗した場合、利用者は終わらない読み込みや切り替えの繰り返し
ではなく、再生できなかったことが分かるエラー表示を見る。ライブラリ全体はそのまま使い続けられる。

**Why this priority**: すべての破損・未知形式を再生できる保証はできないため、最終的な失敗を
明確かつ有限に扱うことが OR-001 の最後の段階である。

**Independent Test**: 直接配信とライブ変換の両方が失敗する動画を開き、切り替えが繰り返されず、
再生失敗が表示され、一覧へ戻って別の動画を再生できることを確認する。

**Acceptance Scenarios**:

1. **Given** 直接配信に失敗した動画、**When** MP4 ライブ変換にも失敗する、**Then** プレイヤーは
   自動切り替えを終了し、再生できなかったことを利用者へ表示する
2. **Given** 再生失敗が表示された状態、**When** 利用者が一覧へ戻る、**Then** ライブラリの閲覧と
   ほかの動画の再生を続けられる
3. **Given** ライブ変換の開始後に元ファイルが失われる、**When** 再生に必要なデータを取得できなく
   なる、**Then** 終わらない待機をせず再生失敗を表示する

### Edge Cases

- 映像は直接再生可能だが、音声だけがブラウザ非対応の場合は、音声を含めて再生可能な MP4 として
  再生する
- 音声のない動画は、無音の動画として再生し、音声がないこと自体を失敗理由にしない
- 直接配信の開始後にデコードエラーが起きた場合は、MP4 ライブ変換へ切り替えるのは1度だけとし、
  同じ2経路を循環しない
- 破損ファイル、映像ストリームのないファイル、ライブ変換で読み取れないファイルは、当該動画の
  再生だけを失敗させる
- 短い動画、非常に長い動画、可変フレームレートの動画でも、再生時間とシーク位置が利用者から見て
  不自然に飛ばない
- 複数タブで異なる動画または同じ動画を再生しても、一方の終了がもう一方の再生を終了させない
- 再生画面を閉じる、再読み込みする、通信が切れる場合も、終了した視聴の処理が残り続けない

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、動画の直接再生が可能な場合、元ファイルを変更せず直接配信しなければ
  ならない
- **FR-002**: システムは、取り込み時の解析で直接再生不可と判定された動画を、利用者による事前
  変換なしに、ブラウザで再生可能な MP4 へライブ変換して再生しなければならない
- **FR-003**: システムは、直接再生可能と判定した動画が実際の再生で失敗した場合、利用者の追加
  操作なしに MP4 ライブ変換へ1度だけ切り替えなければならない
- **FR-004**: システムは、直接再生と MP4 ライブ変換のどちらを利用している場合も、同じ再生画面と
  基本操作を提供しなければならない
- **FR-005**: システムは、MP4 と互換性のある映像または音声を不必要に再圧縮して品質を劣化させては
  ならない
- **FR-006**: システムは、ライブ変換中の動画で任意の位置へ移動でき、移動先から再生を続けられる
  ようにしなければならない
- **FR-007**: システムは、直接配信とライブ変換のどちらでも、既存の再生位置保存、続きからの再生、
  視聴済み判定を維持しなければならない
- **FR-008**: システムは、ライブ変換のために元動画を書き換えてはならず、再生終了後も残る代替動画を
  利用者のライブラリ内へ作成してはならない
- **FR-009**: システムは、再生画面から離れる、接続が切れる、再生対象を切り替えるなど、その視聴に
  ライブ変換が不要になった場合、不要な処理を終了しなければならない
- **FR-010**: システムは、直接配信と MP4 ライブ変換の両方が失敗した場合、自動切り替えを終了し、
  再生できなかったことを利用者へ表示しなければならない
- **FR-011**: システムは、個別動画の再生失敗によって、ライブラリの閲覧やほかの動画の再生を妨げては
  ならない
- **FR-012**: システムは、特定の拡張子だけをライブ変換対象とせず、取り込み時に内容を解析できた
  動画に対して同じ再生経路の選択を適用しなければならない

### Key Entities

- **再生候補**: 1本の動画に対して試せる再生経路。元ファイルの直接配信を先とし、MP4 ライブ変換を
  その次に持つ。各候補は未試行、再生中、失敗の状態を持つ
- **ライブ変換セッション**: 1回の視聴中にだけ存在する変換。対象動画、開始位置、継続中か終了済みかを
  表し、再生画面を離れたあとに永続的な動画として残らない
- **再生位置**: 動画をどこまで見たかを示す既存の利用者データ。再生経路が変わっても同じ動画の位置
  として扱う

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 代表的なブラウザ対応動画の100%が、一覧で選択してから3秒以内に、品質を変えず直接
  再生を開始できる（対応: OR-001 の「直接配信」）
- **SC-002**: 「容器だけが非対応」「映像だけが非対応」「音声だけが非対応」「映像と音声の両方が
  非対応」「音声なし」を各1本以上含む試験動画の100%が、利用者による事前変換や外部アプリなしに、
  選択してから3秒以内に再生を開始できる（対応: OR-001 の「無理なら MP4ライブ変換」）
- **SC-003**: 直接再生可能と判定した試験動画で再生時エラーを発生させた場合、100%の試行で利用者の
  追加操作なしに1度だけライブ変換へ切り替わる（対応: OR-001 の再生経路順序）
- **SC-004**: ライブ変換中の動画で任意の位置を選択してから2秒以内に、その位置を基準として再生が
  再開する（対応: OR-002 のシーク）
- **SC-005**: ライブ変換で途中まで見た動画を開き直した試験の100%で、保存位置から5秒以内の誤差で
  再開する（対応: OR-002 の続きからの再生）
- **SC-006**: 直接配信とライブ変換を意図的に失敗させた試験の100%で、自動切り替えが循環せず、
  10秒以内に再生失敗が1回表示される（対応: OR-001 の「失敗したらエラー表示」）
- **SC-007**: ライブ変換中の再生画面を閉じた試験の100%で、10秒以内にその視聴専用の処理が終了し、
  ほかの動画を再生できる（対応: OR-002 の既存再生体験維持）
- **SC-008**: 本機能の利用前後で、試験対象となる元動画の内容変更が0件、既存の再生位置の消失が0件で
  ある（対応: OR-002 の元ファイルと利用者データの保護）

## Settled Without Asking

- 元ファイルを直接扱える動画は現在の直接配信を第一候補として維持する — Issue #100 の再生順序と
  [002 コア動画ライブラリ仕様](../002-core-video-library/spec.md) User Story 2
- 解析時に直接再生不可と分かる動画も、再生画面を開いた時点で拒否せずライブ変換を試す — Issue
  #100。本仕様は 002 の User Story 2 Acceptance Scenario 5、FR-003、FR-020、SC-007、および
  「形式変換を行わない」という Assumption の該当部分を置き換える
- 実際のブラウザで直接再生が失敗した場合も、同じ順序でライブ変換へ1度だけ切り替える — Issue
  #100 の要件
- 再生位置保存、続きからの再生、シーク、視聴済み判定を再生経路にかかわらず維持する — Issue
  #100 と 002 の FR-017〜FR-019
- 再生画面の構成や操作を作り直さず、既存プレイヤー内で経路を切り替える — Issue #100 の「利用者の
  追加操作なし」と既存の再生画面
- 元動画を変更せず、ライブ変換後の代替動画をライブラリへ永続化しない — Issue #100 の要件と 002
  の FR-009
- 再生開始3秒以内、シーク後2秒以内、再開位置の誤差5秒以内を維持する — 002 の SC-004、SC-005
- 利用者は単一で、家庭内の信頼できるネットワークから利用する — 002 の Assumptions
