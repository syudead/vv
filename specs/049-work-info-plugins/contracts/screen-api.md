# Contract: Work-info plugin screen API

Source of truth: [api/openapi.yaml](../../../api/openapi.yaml); Go and
TypeScript are generated by `task generate`. Every operation below is owner
only (no `security` key), so a guest gets `401` `unauthenticated`, as for the
other owner routes. Errors use `Error` and its `code`
([023 error-api](../../023-english-i18n/contracts/error-api.md)). The
external API and MCP do not change.

## `WorkInfoPlugin`

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | integer | Row id |
| `name` | string, optional | Manifest name; absent when the manifest could not be read |
| `fileName` | string | The uploaded file's name |
| `version`, `description` | string, optional | From the manifest |
| `operations` | `search` / `fetch` array | From the manifest; empty for an invalid plugin |
| `digest` | string | SHA-256 of the module, sent back when approving ([R-7](../research.md#r-7-approving-names-the-digest-the-owner-saw)) |
| `state` | `approved` / `unapproved` / `invalid` | [data-model.md, State transitions](../data-model.md#state-transitions) |
| `problem` | string enum, optional | Present for `invalid` ([data-model.md](../data-model.md#work_info_plugins)) |
| `settings` | array | One entry per declared setting: `key`, `label`, `secret`, `required`, `set` (whether a value is stored), and `value` only when `secret` is false ([R-13](../research.md#r-13-plugin-settings-are-declared-in-the-manifest-and-passed-only-in-that-plugins-request)) |
| `network` | boolean | Always `true` in contract 1: the plugin can reach internet sites (requirement 2) |
| `updatedAt` | integer | Unix seconds |

## `GET /api/work-info-plugins`

Lists every plugin, ordered by name, then file name. The settings screen and
the video page read it
([R-11](../research.md#r-11-the-video-page-reads-the-plugin-list-to-decide-whether-to-show-the-fetch-action)).

**Response**: `200` with `{"plugins": [WorkInfoPlugin]}`.

## `POST /api/work-info-plugins`

Adds a plugin, or replaces the one with the same manifest name.

| Field | In | Type | Required | Meaning |
| --- | --- | --- | --- | --- |
| `module` | multipart part | file | Yes | The `.wasm` file; its file name is kept |

**Response**: `201` with the new `WorkInfoPlugin`, or `200` with the replaced
one. An unusable file is still stored and comes back with `state: invalid`.

| Status | `code` | When |
| --- | --- | --- |
| 400 | `invalid_request` | No `module` part, or more than one |
| 413 | `plugin_too_large` (`limit`) | The part exceeds 16 MiB |

## `PUT /api/work-info-plugins/{id}/approval`

Approves the module the owner saw.

| Field | In | Type | Required | Meaning |
| --- | --- | --- | --- | --- |
| `digest` | body | string | Yes | The `digest` from the list |

**Response**: `200` with the `WorkInfoPlugin`.

| Status | `code` | When |
| --- | --- | --- |
| 404 | `not_found` | No such plugin |
| 409 | `plugin_changed` | The stored digest differs |
| 409 | `plugin_unusable` | The plugin is `invalid` |

## `DELETE /api/work-info-plugins/{id}/approval`

Revokes the approval. **Response**: `200` with the `WorkInfoPlugin`; `404`
`not_found`.

## `PUT /api/work-info-plugins/{id}/settings`

Writes setting values. Approval does not change.

| Field | In | Type | Required | Meaning |
| --- | --- | --- | --- | --- |
| `values` | body | object of string or null | Yes | Key to new value; `null` deletes the value; keys left out keep theirs |

**Response**: `200` with the `WorkInfoPlugin`, whose secret entries show only
`set`.

| Status | `code` | When |
| --- | --- | --- |
| 400 | `invalid_request` | A key the manifest does not declare, or a value over 2000 characters |
| 404 | `not_found` | No such plugin |
| 409 | `plugin_unusable` | The plugin is `invalid` |

## `DELETE /api/work-info-plugins/{id}`

Deletes the plugin. **Response**: `204`; `404` `not_found`.

## `POST /api/work-info-plugins/{id}/search`

Runs the plugin's `search` and returns its candidates.

| Field | In | Type | Required | Meaning |
| --- | --- | --- | --- | --- |
| `query` | body | string | Yes | 1 to 200 characters after trimming |

**Response**: `200` with `{"candidates": [{"id", "title", "detail"?}]}`
([R-10](../research.md#r-10-search-candidates-are-text-only)); `id` is the
work's ID that a fetch of the candidate sends unchanged.

Errors: [Run failures](#run-failures), plus `409` `operation_unsupported` when
the manifest lacks `search`.

## `POST /api/videos/{id}/work-info-fetches`

Runs the plugin's `fetch` with `id` for this video and keeps the
result for 10 minutes
([R-8](../research.md#r-8-a-fetched-result-lives-in-memory-for-10-minutes-bound-to-the-video-and-the-plugins-digest)).
The video is not changed.

| Field | In | Type | Required | Meaning |
| --- | --- | --- | --- | --- |
| `pluginId` | body | integer | Yes | An approved plugin |
| `id` | body | string | Yes | The work's ID, such as the product code or a candidate's `id`, 1 to 200 characters without surrounding spaces; the plugin builds the page URL from it. A string that looks like a URL is still the ID: VVMDM passes it unchanged and never fetches it (parent Issue #1232, requirement 14) |

A body without `id`, or with an `id` outside the rule, is `400`
`invalid_request`.

**Response**: `201` with:

| Field | Type | Meaning |
| --- | --- | --- |
| `fetchId` | string | The result's id |
| `expiresAt` | integer | Unix seconds |
| `title` | string, optional | The fetched title after the display-name rule; absent when the plugin returned none or it breaks the rule |
| `tags` | string array | The fetched tag names, possibly empty |

The screen compares these with the video it already holds; a field with no
value cannot be selected.

Errors: [Run failures](#run-failures), `404` `not_found` for the video, and
`409` `operation_unsupported` when the manifest lacks `fetch`.

## `POST /api/videos/{id}/work-info-fetches/{fetchId}/apply`

Applies the selected fields of a fetched result
([R-9](../research.md#r-9-the-title-and-the-tags-are-applied-in-one-transaction-and-skipped-names-are-reported)).

| Field | In | Type | Required | Meaning |
| --- | --- | --- | --- | --- |
| `fields` | body | `title` / `tags` array | Yes | Non-empty; each must have a value in the result |

**Response**: `200` with `{"video": Video, "skippedTags": [{"name", "reason": "rejected" | "invalid"}]}`.
The result is consumed.

| Status | `code` | When |
| --- | --- | --- |
| 400 | `invalid_request` | `fields` empty, or names a field without a value |
| 404 | `not_found` | No such video, or the result belongs to another video |
| 409 | `work_info_fetch_stale` | The result expired or is unknown, or the plugin was replaced, revoked or deleted since the fetch, checked again inside the apply's transaction |

## Run failures

Search and fetch answer a failed run with these. The video is never changed.
`Error.message` stays vv's own English sentence
([023 error-api](../../023-english-i18n/contracts/error-api.md#every-message-in-english)),
so `Error` gains three optional fields: `pluginMessage` (the first 300 characters of the plugin's own error
message), `host` (the host that was refused or unreachable) and
`settingKeys` (the missing setting keys).

| Status | `code` | `reason` | When |
| --- | --- | --- | --- |
| 404 | `not_found` | — | No such plugin |
| 409 | `plugin_not_approved` | — | The plugin is not approved |
| 409 | `plugin_settings_missing` | — | A `required` setting has no value; `Error.settingKeys` lists the keys, and the module did not run |
| 502 | `plugin_failed` | — | The plugin reported an error (`pluginMessage`), exited non-zero or wrote an invalid response |
| 502 | `plugin_failed` | `blocked_address` | The plugin tried to reach vv, the LAN or another non-public address (`host`) |
| 502 | `plugin_failed` | `network_error` | A request failed to connect and the plugin failed (`host`) |
| 504 | `plugin_timed_out` | — | The run exceeded 30 s |
| 502 | `plugin_failed` | `memory_exceeded` | The run exceeded 128 MiB |
| 502 | `plugin_failed` | `output_too_large` | The output exceeded 1 MiB |
| 503 | `plugin_busy` | — | Another run held the slot for 10 s |
