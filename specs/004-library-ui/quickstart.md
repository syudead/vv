# Quickstart / 受け入れ検証: 現在の機能を前提とした UI の実装

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-09-13

この機能が「できた」と言える状態を、実行して確かめる手順。各シナリオは
[spec.md](./spec.md) の成功基準に対応する。実装の詳細は書かない（`plan.md` と実装で
扱う）。

本機能は**画面の作り込み**なので、機械で確かめられるもの（S1・S2）と、人が見て確かめる
もの（S3〜S8）が混ざる。どちらに属するかを各シナリオの見出しに示す。

## S0: 検証用の動画をつくる

[002 の S0](../002-core-video-library/quickstart.md) をそのまま実行する。本機能の検証には
次の 3 本を**追加で**用意する。画面の端の条件を作るためである。

```bash
# 題名が極端に長い（省略と全文の確認手段を見る。FR-011）
ffmpeg -f lavfi -i testsrc=size=640x360:rate=30:duration=5 \
       -c:v libx264 -pix_fmt yuv420p -y \
       "./media/とても長い題名の動画で一覧の枠に収まりきらないことを確かめるためのものです.mp4"
# 音声が無い（情報欄の「なし」を見る。FR-013）
ffmpeg -f lavfi -i testsrc=size=1920x1080:rate=30:duration=6 \
       -c:v libx264 -pix_fmt yuv420p -y "./media/音の無い動画.mp4"
# 途中まで見た状態を作るための長め（2 分）の動画（TD-006 の回避も兼ねる）
ffmpeg -f lavfi -i testsrc=size=1280x720:rate=30:duration=150 \
       -f lavfi -i sine=frequency=440:duration=150 \
       -c:v libx264 -pix_fmt yuv420p -c:a aac -y "./media/長い動画.mp4"
```

**期待**: `./media` に 002 の 3 本 + 上の 3 本が並ぶ。

## S3: 一覧が「自分のライブラリ」に見える（人）

```bash
MDM_MEDIA_HOST_DIR=./media make up
```

ブラウザで `http://localhost:8080` を開く。

**期待**:

1. 動画は 16:9 の枠で並び、サムネイルが主役である（FR-005）
2. 題名・長さ・視聴状況がそれぞれ決まった位置にある（FR-006）
3. 「探す」「並べ替える」「取り込む」の 3 つが画面上部の帯にあり、**一覧を下まで
   スクロールしても見えている**（FR-007）
4. 件数の文言が「N 本」で、検索すると「「<語>」に一致 N 本」に変わる（FR-008）
5. 題名が長い動画は 2 行で省略され、狙いを合わせると全文が出る（FR-011）

**SC-003 の確認**: 取り込み直後（サムネイル生成中）に一覧を開き、画面を触らずに
30 秒待つ。**すでに見えている項目の位置が 1px も動かない**こと。サムネイルは枠の中で
差し替わるだけである。

**SC-001 の確認**: この画面を初めて見る人に「探す・並べ替える・取り込むはどこか」と
尋ね、10 秒以内に 3 つとも指させるか。5 人中 4 人以上で成功とする。

**空の確認**: `./media` を空にして再取り込みすると、置き場所と「取り込む」への案内が
出る。検索語を入れて該当が 0 になると、**別の文言**（検索語と「検索語を消す」）が出る
（FR-009）。

**失敗の確認**: サーバーを止めてから一覧を再読み込みすると、失敗の枠が出るが、
**帯は残り操作できる**（FR-002）。

## S4: 画面幅（人）

ブラウザの開発者ツールで幅を **360px・768px・1280px・2560px** に変えて、一覧と再生画面を
それぞれ開く。

**期待**（SC-004 / FR-022）:

- どの幅でも**横方向のスクロールバーが出ない**
- 帯の中の 4 つが重ならない（狭いときは 2 行に折り返す）
- 押せる要素が 44px 四方以上ある（開発者ツールで寸法を確認する）
- 列数が [contracts/design-tokens.md](./contracts/design-tokens.md) 3. の表の目安どおりで、
  幅 360px でも 1 列にならない
- 再生画面では映像が画面幅に収まり、比率が保たれ、情報は映像の下に縦に並ぶ

## S5: キーボードと読み上げ（人）

**マウスに触らずに**次を行う。

1. `http://localhost:8080` を開く
2. Tab で帯の 4 つを順に通る。**どこに狙いを合わせているかが常に見える**（FR-003）
3. さらに Tab で一覧の項目へ移る。狙いを合わせた項目は題名の全文が出る
4. Enter で再生画面へ移る
5. Space で再生・一時停止する
6. Tab で「一覧へ戻る」に達し、Enter で戻る

**期待**: 6 まで**マウス操作 0 回**で到達できる（SC-005 / FR-020）。戻ったとき、
一覧は**離れたときの位置・検索語・並び順**のままである（FR-016）。

**読み上げの確認**（FR-021）: OS の読み上げを入れて一覧を移動する。

- 項目の名前として題名の**全文**が読まれる（省略された形ではない）
- 視聴済みの項目で「視聴済み」が読まれる
- 途中の項目で「N% まで再生済み」が読まれる
- サムネイル未生成の項目で理由が読まれる

## S6: 表示設定（人）

1. 密度を「細かい」に変える → 1 行の本数が増える（FR-017）
2. 変える直前に画面上端にあった動画が、変更後も画面上端付近にある（US3 受け入れ 1）
3. **画面を再読み込みする** → 「細かい」のまま（FR-018 / SC-007）
4. 再生画面へ移り、戻る → 「細かい」のまま（SC-007）
5. 並び順を「題名順」に変え、再読み込みする → 「題名順」のまま
6. **別のブラウザ**（またはプライベートウィンドウ）で開く → 既定（「標準」「追加が
   新しい順」）で表示される（FR-018 / US3 受け入れ 3）

**壊れた値の確認**（FR-019）: 開発者ツールのコンソールで次を実行し、再読み込みする。

```js
localStorage.setItem("vv.view.v1", "{壊れた");
```

**期待**: 画面は既定の設定で普通に表示される。エラー画面にならない。

`localStorage` を無効にしたプライベートウィンドウでも同様に表示される。

## S7: 規模と反応（人 + 計測）

1万本の一覧を作る。

```bash
# 小さな動画を 1 本作り、ハードリンクで数を増やす（内容が同じでも別ファイルとして数える）
mkdir -p ./media/bulk
ffmpeg -f lavfi -i testsrc=size=320x180:rate=15:duration=2 \
       -c:v libx264 -pix_fmt yuv420p -y ./media/bulk/seed.mp4
for i in $(seq 1 10000); do cp ./media/bulk/seed.mp4 "./media/bulk/動画$i.mp4"; done
```

**期待**:

- **SC-002**: 一覧を開いてから最初の画面が出るまで **2 秒以内**（開発者ツールの
  Network で、1 ページ目の応答から描画までを見る）。1 ページ 60 件しか読まないことは
  002 のままで、本機能で変わらない
- **SC-008**: 下へスクロールして **1000 件以上**を読み込んだ状態で、検索欄に文字を
  入れる・密度を変える・項目に狙いを合わせる。いずれも**反応が 100ms 以内に始まる**
  （開発者ツールの Performance で入力から最初の描画更新までを見る）

## S8: 再生画面と「動きを減らす」（人）

「長い動画.mp4」を 30 秒ほど再生して一覧へ戻り、もう一度開く。

**期待**:

1. 映像が主役として表示され、題名・長さ・解像度・形式・映像・音声・大きさが映像の外に
   まとまって並ぶ（FR-012 / FR-013）
2. 「N:NN から再開しました」と「先頭から見直す」が、**映像を隠さない位置**に出る
   （FR-014）
3. 「音の無い動画.mp4」を開くと、音声が「なし」と出る（空欄ではない。FR-013）
4. 「対応外の動画.mkv」を開くと、**再生を試みる前に**理由が警告として出て、画面の
   ほかの部分は普通に使える（FR-015）
5. 「一覧へ戻る」が常に見えている（FR-016）

**動きを減らす設定**（FR-023）: OS またはブラウザで「視差効果を減らす」を有効にして
一覧と再生画面を開く。

**期待**: ホバーの遷移・骨組みの明滅・進捗帯の伸びといった装飾的な動きが起きない。
狙いを合わせた印は**変わらず出る**。
