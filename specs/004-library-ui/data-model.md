# Data Model: 現在の機能を前提とした UI の実装

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-09-13

本機能は**永続化する情報を1つも増やさない**。SQLite の表も、`api/openapi.yaml` の
スキーマも変わらない（FR-024）。ここで定義するのは、画面が自分の中だけで持つ 2 つの
状態と、サーバーから受け取った値を画面が読み替える規則である。

| 名前 | 置き場所 | 寿命 | 失われたときの振る舞い |
| --- | --- | --- | --- |
| [表示設定](#1-表示設定-viewpreferences) | `localStorage`（`vv.view.v1`） | 端末・ブラウザに永続 | 既定値で表示する（FR-019） |
| [一覧の復元状態](#2-一覧の復元状態-listsnapshot) | メモリ（モジュール変数） | タブを開いている間 | 一覧の先頭から読み直す |
| [視聴状況](#3-視聴状況-watchstate読み替え) | 導出のみ（保存しない） | — | — |

## 1. 表示設定 (ViewPreferences)

spec の Key Entities「表示設定」に対応する。利用者がその端末で選んだ一覧の見せ方で、
**サーバー側の保存対象ではない**。

### 項目

| 項目 | 型 | 既定値 | 取りうる値 | 対応する要求 |
| --- | --- | --- | --- | --- |
| `density` | 列挙 | `"standard"` | `"dense"` / `"standard"` / `"relaxed"` | FR-017 |
| `sort` | 列挙 | `"addedDesc"` | `"addedDesc"` / `"titleAsc"` | Key Entities「並び順の初期値」 |

`sort` の取りうる値は `api/openapi.yaml` の `VideoSort` と同じである。生成された型
（`web/src/api/gen/openapi.ts`）をそのまま使い、ここで列挙を書き写さない。契約に値が
増えたときに型検査で気付けるようにするためである。

`density` は本機能が新しく決める列挙で、サーバーは知らない。値と最小列幅の対応は
[contracts/design-tokens.md](./contracts/design-tokens.md) にある。

### 保存の形

```json
{ "density": "standard", "sort": "addedDesc" }
```

鍵は `vv.view.v1`。版（`v1`）を鍵に含め、項目を変えるときは新しい鍵にする（R-407）。
古い鍵は読まず、消しもしない（消す処理が失敗しても画面は動くべきで、残骸は無害である）。

### 検証と既定値への落ち方（FR-019）

読み出しは次の順で判断し、**どの段でも例外を外へ出さない**。

1. `localStorage` にアクセスできない（プライベートウィンドウ、設定で無効）→ 既定値
2. 鍵が無い → 既定値
3. `JSON.parse` に失敗する → 既定値
4. オブジェクトでない（配列・`null`・数値）→ 既定値
5. 項目ごとに検証し、**不正な項目だけ**を既定値へ落とす（`density` が壊れていても
   `sort` が正しければ `sort` は活かす）

書き込みは失敗を握りつぶす（容量超過・無効化）。設定が保存できないことは、画面を
止める理由にならない。

### 「並び順」の 2 つの役割

`sort` は**初期値**であって、いま表示している並び順そのものではない。いま表示している
並び順は URL のクエリ（`?sort=`）が持つ（R-403）。

| 場面 | 並び順の決まり方 |
| --- | --- |
| `/` を開く（クエリ無し） | 表示設定の `sort` |
| `/?sort=titleAsc` を開く | URL の値（表示設定より優先） |
| 画面で並び順を変える | URL を書き換え、同時に表示設定にも書く（次回の初期値になる） |

こうすると、共有されたリンクは送った人の並びで開き（URL が勝つ）、自分で開くときは
自分の好みで開く（表示設定が効く）。

## 2. 一覧の復元状態 (ListSnapshot)

再生画面から一覧へ戻ったときに、読み込み済みの項目とスクロール位置を戻すための状態
（FR-016、R-403）。**メモリにしか置かない。**

### 項目

| 項目 | 型 | 用途 |
| --- | --- | --- |
| `key` | 文字列 | 鍵。`q` と `sort` を正規化して連結したもの |
| `items` | `Video[]` | 読み込み済みの項目（ページをまたいで連結済み） |
| `total` | 数値 | 総件数（FR-008 の文言に使う） |
| `cursor` | 文字列 \| 未設定 | 次のページの続き位置 |
| `hasMore` | 真偽 | 次のページがあるか |
| `scrollY` | 数値 | 離れる直前のスクロール位置 |

### 規則

- 保持するのは**直近の1件だけ**である。鍵が違う一覧へ移ったら捨てる。数千件の
  `Video` を鍵ごとに溜めない。
- 書くのは一覧を離れる瞬間（再生画面への遷移）だけ、読むのは一覧を開く瞬間だけである。
- 鍵が一致しなければ無視して 1 ページ目から読む。**復元できないことは異常ではない。**
- 取り込みが終わって一覧を読み直したとき（`ScanStatus` の `onFinished`）は破棄する。
  古い一覧に戻してはならない。
- 全体の再読み込み（F5）では当然失われ、先頭から読む。FR-016 が求めているのは
  「戻ったとき」であって「再読み込みしたとき」ではない。

### 復元の順序

位置を戻すのは **項目を描いたあと**でなければならない。中身が無いうちに `scrollTo` を
呼んでも、文書の高さが足りず途中で止まる。`useLayoutEffect` で、項目を描いた同じ
フレームのうちに戻す（R-403）。ブラウザ自身の復元は `history.scrollRestoration =
"manual"` で止める。

## 3. 視聴状況 (WatchState、読み替え)

FR-006 は一覧の各項目に「未視聴・途中・視聴済み」を出すことを求めている。これは
**サーバーが返す `Progress` から導く**もので、新しく受け取る項目ではない。

| 状態 | 条件 | 一覧での見せ方 |
| --- | --- | --- |
| 視聴済み | `progress.completed === true` | 印（文言つき） |
| 途中 | `progress` があり `completed` が偽で、`durationMs > 0` かつ `positionMs > 0` | 残りの量が分かる帯 + 読み上げ向けの割合 |
| 未視聴 | `progress` が無い、または上のいずれにも当たらない | 何も出さない |

`durationMs` が取れていない（解析待ち・解析失敗）動画は、途中まで見ていても帯を描けない。
この場合は**未視聴と同じ見せ方にする**（割合を偽らない）。既存の `partialRatio` が
すでにこの規則で書かれており、本機能で変えない。

### 取れていない値の扱い（FR-013・Edge Cases）

再生画面の情報欄は、取れていない項目を**空欄にしない**。`probeState` で言い分けを変える。

| `probeState` | 長さ・解像度・形式・映像・音声の見せ方 |
| --- | --- |
| `pending` | 「確認中」 |
| `failed` | 「読み取れませんでした」（`probeError` があれば併記） |
| `done` で値が無い | 「なし」（音声が無い動画など、値が無いこと自体が情報である） |

`sizeBytes` と `addedAt` は必須項目なので、この分岐に入らない。
