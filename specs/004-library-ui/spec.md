## User Scenarios & Testing *(mandatory)*

本機能の利用者は、[002](../002-core-video-library/spec.md) で作った動画ライブラリを
日常的に開く個人である。機能はすでに揃っている — 置いた動画は自動で並び、ブラウザで
再生でき、続きから見られ、題名で探せる。足りないのは**画面そのもの**である。現在の一覧は
既定の書式に近い見た目で、題名・操作・状態が同じ高さに並び、どこを見れば何が分かるのかが
掴みにくい。再生画面も同様で、「手持ちの動画を眺める場所」としては貧しい。

本仕様は、**取得できる情報・保存する情報を1つも増やさずに**、いま取れている情報だけで
画面を作り込む。すなわち一覧・再生・検索・取り込みの4つを、一貫した見た目と操作の規則の
上に載せ直す。画面案にある整理機能（タグ・お気に入り・コレクション・未整理）と画像の
管理は、裏側の機能が無いので**画面にも出さない**（「スコープ外」を参照）。

### User Story 1 - 一覧が「自分のライブラリ」に見える (Priority: P1)

利用者は一覧を開いた瞬間に、ここが自分の動画置き場だと分かる。動画の静止画が主役として
並び、題名・長さ・視聴状況はそれを邪魔しない位置にある。探す・並べ替える・取り込むの
3つの操作は常に同じ場所にあり、一覧をどれだけスクロールしても見失わない。

**Why this priority**: 一覧は本製品でいちばん長く見る画面であり、ここが整うだけで
「フォルダを開く代わりに開く場所」として成立する。ほかの画面はこの画面の見た目の規則を
借りるので、ここが先に決まらないと後続が決まらない。

**Independent Test**: 動画を数十本置いた状態で一覧を開く。静止画・題名・長さ・視聴状況が
それぞれ決まった位置にあり、探す／並べ替える／取り込むの入口が説明なしに見つけられ、
スクロールしても操作の入口を見失わなければ成功。

**Acceptance Scenarios**:

1. **Given** 取り込み済みのライブラリ、**When** 一覧を開く、**Then** 動画は静止画を主役と
   した一定の比率の枠で並び、題名・長さ・視聴状況（未視聴・途中・視聴済み）がそれぞれ
   決まった位置に表示される
2. **Given** 一覧を下までスクロールした状態、**When** 探す・並べ替える・取り込むのどれかを
   行いたくなる、**Then** その入口はスクロール位置によらず画面上に見えている
3. **Given** 静止画がまだ生成されていない動画を含む一覧、**When** 静止画が後から届く、
   **Then** 項目の位置と大きさは変わらず、ほかの動画の見えている位置がずれない
4. **Given** 一覧、**When** ある動画に狙いを合わせる（触れる・キーボードで移動する）、
   **Then** どれを選んでいるかが見た目で分かり、そのまま選ぶと再生画面へ移る
5. **Given** 一覧、**When** 総件数・絞り込みの有無を確認したい、**Then** いま何本が
   並んでいるのか、検索で絞られているのかが画面上の文言から分かる

---

### User Story 2 - 再生画面が同じ規則で整い、見ることに集中できる (Priority: P2)

利用者が動画を選ぶと、映像が画面の主役になる。題名・長さ・解像度などの情報は映像の下に
整理され、再生の邪魔をしない。続きから始まったこと、再生できない形式であることといった
「知らせ」は、映像と同じ画面の決まった場所に出る。一覧へ戻る道はいつでも見えている。

**Why this priority**: 再生は一覧の次に長くいる画面である。US1 で決めた見た目の規則を
そのまま適用すれば単独で完成し、単独で検証できる。

**Independent Test**: 一覧から動画を1本選んで再生する。映像・題名・情報・戻る道が
それぞれ決まった位置にあり、途中まで見た動画では中断位置から始まり、再開したことを
示す通知が出なければ成功。

**Acceptance Scenarios**:

1. **Given** 再生可能な動画、**When** 一覧から選ぶ、**Then** 映像が画面の主役として表示され、
   題名・長さ・解像度・形式・大きさが映像の外の決まった場所にまとまって並ぶ
2. **Given** 途中まで見た動画、**When** 開く、**Then** 続きから始まったことと「先頭から
   見直す」操作が、映像を隠さない位置に出る
3. **Given** ブラウザで再生できない形式の動画、**When** 開く、**Then** 再生を試みる前に
   その旨と理由が警告として出て、それでも画面のほかの部分は普通に使える
4. **Given** 再生画面、**When** 一覧へ戻る、**Then** 戻る道は常に見えており、戻ったときに
   直前に見ていた一覧の位置から再開する
5. **Given** 再生中、**When** 画面の幅が変わる（窓の大きさを変える・端末を回す）、
   **Then** 映像は画面からはみ出さず、比率も保たれる

---

### User Story 3 - 表示の仕方を自分で選べる (Priority: P3)

利用者は一覧の見せ方を選べる。静止画を大きく見たいときは粗く、たくさん見渡したいときは
細かく並べられる。選んだ設定は次に開いたときも保たれ、毎回選び直す必要はない。

**Why this priority**: 無くても一覧は使えるが、手持ちの本数と目的（眺める／探す）によって
最適な密度は変わる。裏側の機能を増やさずに実現でき、単独で足せる。

**Independent Test**: 一覧で表示の密度を変え、並びが変わることを確認する。画面を再読み込み
しても選んだ密度が保たれれば成功。

**Acceptance Scenarios**:

1. **Given** 一覧、**When** 表示の密度を変える、**Then** 1行に並ぶ本数が変わり、
   スクロール位置は見ていた動画を見失わない範囲に保たれる
2. **Given** 密度を変えた状態、**When** 画面を再読み込みする、または再生画面から戻る、
   **Then** 選んだ密度のまま表示される
3. **Given** 密度を変えた状態、**When** 別の端末・別のブラウザから開く、**Then** その端末の
   既定の密度で表示される（設定はその端末に閉じる）

---

### User Story 4 - 手元の小さな画面でも破綻しない (Priority: P4)

利用者は同じ家の中でスマートフォンやタブレットからも開く。狭い画面でも一覧は読める形で
並び、操作は指で押せる大きさがあり、再生画面は映像が主役のまま収まる。

**Why this priority**: 自宅の据え置き機だけで使う想定なら後回しでよいが、手元の端末から
開けないと「フォルダを開く代わり」にはなりきらない。US1・US2 が済んでいれば追加の
機能なしに満たせる。

**Independent Test**: 画面幅 360px 相当で一覧と再生画面を開く。横方向のスクロールが出ず、
操作要素が指で押せる大きさで、文字が読める大きさであれば成功。

**Acceptance Scenarios**:

1. **Given** 幅の狭い画面、**When** 一覧を開く、**Then** 横方向のスクロールは発生せず、
   静止画・題名・長さは読める大きさで並ぶ
2. **Given** 幅の狭い画面、**When** 探す・並べ替える・取り込むを使う、**Then** それぞれの
   操作要素は指で押せる大きさがあり、互いに重ならない
3. **Given** 幅の狭い画面、**When** 再生画面を開く、**Then** 映像は画面幅に収まり、情報は
   その下に縦に並ぶ

---

### Edge Cases

- 静止画がまだ無い／生成に失敗した動画が混じるとき、枠は保たれ、理由が枠の中で分かるか
- 題名が極端に長い、または改行を含むとき、隣の項目へはみ出さず、全文を確認する手段があるか
- 長さ・解像度などが取れていない動画（解析待ち・解析失敗）で、空欄が「壊れている」ように
  見えないか
- 取り込みが進行中のあいだ、一覧と再生が普通に使えて、進行と残りが画面から分かるか
- 一覧が0本のとき、検索の結果が0本のとき、それぞれ「次に何をすればよいか」が示されるか
- 一覧や動画の取得に失敗したとき、画面全体が白くならず、失敗した範囲だけが伝わるか
- 数千〜1万本規模で最下部までスクロールしたとき、操作が重くならないか
- 文字の拡大設定（200%）や、動きを減らす設定を使っている利用者でも読める・使えるか
- キーボードだけ、あるいは読み上げだけで一覧から再生まで到達できるか

## Requirements *(mandatory)*

### Functional Requirements

**画面共通の規則**

- **FR-001**: 一覧と再生の両画面は、同一の配色・余白・文字の大きさ・角の丸みの規則に従う
  こと。規則は1か所に定義し、画面ごとに別の値を持たないこと
- **FR-002**: すべての画面は、通信中・成功・空・失敗の4状態に対して、それぞれ決まった
  見た目を持つこと。失敗時も画面全体が使えなくならないこと
- **FR-003**: 操作できる要素（押せる・入力できる・選べる）は、狙いを合わせている状態が
  見た目で分かること。キーボードで移動したときも同様であること
- **FR-004**: 本文の文字と背景の対比は 4.5:1 以上、大きな文字と境界線は 3:1 以上であること

**一覧画面**

- **FR-005**: 一覧は動画の静止画を主役とした一定比率（16:9）の枠で並べ、静止画の有無に
  よって枠の大きさが変わらないこと
- **FR-006**: 各項目は題名・長さ・視聴状況（未視聴・途中・視聴済み）・再生可否を示すこと。
  途中の動画はどこまで見たかが見た目で分かること
- **FR-007**: 探す・並べ替える・取り込むの3つの入口は、一覧のスクロール位置によらず常に
  画面上にあること
- **FR-008**: 一覧は、いま並んでいる総件数と、検索で絞られているかどうかを文言で示すこと
- **FR-009**: 1本も無いとき、検索の該当が無いときは、それぞれ原因の違いが分かる文言と、
  次に取れる操作を示すこと
- **FR-010**: 取り込みが進行中のあいだ、進行していることと残りの規模を一覧上で示し、
  終わったら一覧を最新の状態にすること
- **FR-011**: 題名が枠に収まらない場合は省略して表示し、全文を確認する手段を持つこと

**再生画面**

- **FR-012**: 映像は画面の主役として、画面幅に収まり比率を保って表示されること
- **FR-013**: 題名・長さ・解像度・形式・映像と音声の種類・ファイルの大きさは、映像の外に
  まとまって並ぶこと。取れていない項目はその旨が分かる形で扱うこと
- **FR-014**: 途中まで見た動画は中断位置から始まり、再開したことを示す通知は出ないこと
- **FR-015**: 再生できない形式であることは、再生を試みる前に理由とともに示すこと
- **FR-016**: 一覧へ戻る道は常に見えていること。戻ったときは直前に見ていた一覧の位置と
  絞り込み・並び順が保たれること

**表示の設定**

- **FR-017**: 利用者は一覧の表示密度を選べること
- **FR-018**: 選んだ表示設定は、同じ端末の同じブラウザで開き直したときに保たれること。
  ほかの端末へは持ち越さないこと
- **FR-019**: 表示設定が読み出せない・壊れている場合でも、既定の設定で画面が表示されること

**操作性**

- **FR-020**: 一覧から動画を選び、再生・一時停止し、一覧へ戻るまでを、キーボードだけで
  到達できること
- **FR-021**: 静止画・状態を示す印・進捗の帯など、見た目だけで意味を伝える要素には、
  読み上げでも同じ意味が伝わる代替が付くこと
- **FR-022**: 画面幅 360px から 2560px の範囲で、横方向のスクロールが発生しないこと。
  指で押す操作要素は 44px 四方以上の当たり判定を持つこと
- **FR-023**: 動きを減らす設定を使っている利用者には、装飾的な動きを適用しないこと

**境界**

- **FR-024**: 本機能は、いま取得できている情報だけを使うこと。新しい情報の取得・保存や、
  サーバーとの取り決めの変更を伴わないこと（表示設定の端末内保存を除く）
- **FR-025**: 既存の受け入れ検証（[002 quickstart](../002-core-video-library/quickstart.md)
  S1〜S10）で確認した振る舞いは変わらないこと

### Key Entities

- **表示設定**: 利用者がその端末で選んだ一覧の見せ方（密度、並び順の初期値）。利用者ごと・
  端末ごとに閉じた設定で、失われても既定値で画面が成立する。サーバー側の保存対象ではない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初めて開いた利用者が、説明なしに「探す」「並べ替える」「取り込む」の3つの
  入口を 10 秒以内に指し示せる（5 人中 4 人以上）
- **SC-002**: 1万本のライブラリでも、一覧を開いてから最初の画面が表示されるまで 2 秒以内
  （既存の基準を維持する）
- **SC-003**: 静止画が後から届いても、すでに表示されている項目の位置は動かない
  （レイアウトのずれ 0）
- **SC-004**: 画面幅 360px・768px・1280px・2560px のいずれでも横方向のスクロールが発生せず、
  操作要素が重ならない
- **SC-005**: キーボードだけで、一覧を開いてから任意の動画を再生し、一覧へ戻るまで到達できる
  （マウス操作 0 回）
- **SC-006**: 一覧・再生の両画面で、文字と背景の対比が基準（本文 4.5:1、大きな文字と境界
  3:1）を満たす割合が 100%
- **SC-007**: 選んだ表示設定は、再読み込み・画面遷移のあとも 100% の確率で保たれる
- **SC-008**: 一覧を 1000 件までスクロールしても、操作に対する画面の反応が 100ms 以内に
  始まる
- **SC-009**: 002 の受け入れ検証 S1〜S10 が引き続きすべて成功する

## スコープ外

画面案に含まれるが、裏側の機能が無いため**画面にも出さない**ものを明示する。無効化した
入口を置くと、利用者からは「壊れている」ように見えるためである。

- タグ・お気に入り・コレクション・未整理といった整理のための機能と、その一覧・絞り込み
- 画像（静止画ファイル）の管理と、動画／画像の切り替え
- 複数選択と一括操作
- 認証・利用者ごとの画面（Phase 3 の範囲）
- 字幕、シークのプレビュー画像、変換による再生（いずれも裏側が未実装）
- 取得する情報を増やす変更（撮影日時・フォルダ階層・タグなどの新しい項目）

## Assumptions

- **画面案の配色（暗い背景）を採用する。** 画面案は仕様の入力として受け取った将来像で
  あり、動画の静止画を主役にする画面では暗い背景のほうが映像が沈まない。明暗の切り替えは
  本仕様では扱わない（必要になった時点で別機能とする）
- **画面案の左の一覧（ライブラリ・コレクション・タグ）は置かない。** 今ある区分は
  「すべての動画」だけで、区分が1つしかない案内は場所を取るだけになる。整理機能が
  入る時点で改めて検討する
- **表示設定はその端末の中だけに残す。** 利用者ごとの保存には認証が要り、それは Phase 3 の
  範囲である
- **利用者は1人で、同時に複数の画面から使う場合でも設定の共有は期待しない**
- **対象のブラウザは、現行版の主要なブラウザ（デスクトップとモバイル）とする**
- **画面が使う情報は今あるもので足りると判断している。** サーバーとの取り決め（どんな
  情報を受け取れるか）は変えない。もし不足が見つかった場合は、その時点で別途決める
- 動作確認用の動画はその場で生成して用意し、実データを使わない（002 と同じ方針）
