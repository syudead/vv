# Feature Specification: 動画シーク時のサムネイルプレビュー

**Feature Branch**: `codex/seek-thumbnail-preview-feature`

**Created**: 2026-09-22

**Status**: Draft

**Parent Issue**: #117

## Original Request

要求者が 2026-09-22 に示した要求を、そのまま保持する。

```text
動画シーク時のサムネイルプレビューが欲しい
```

以下、この要求を **OR-001** と呼ぶ。

同日、要求者は隣接機能との境界について次のように示した。

```text
一覧画面でのプレビュー再生も実装したいが無関係か？無関係なら別でやる
```

一覧画面でのプレビュー再生は別機能として扱い、本仕様には含めないという合意を **OR-002**
と呼ぶ。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 移動先の映像を先に確認する (Priority: P1)

利用者は再生画面のシークバー上で位置を探すとき、その時刻の映像と時刻を移動前に確認できる。
長い動画でも、時刻だけを手掛かりに何度も移動し直さず、目的の場面を選べる。

**Why this priority**: 移動前に映像を確認できることが OR-001 の中心的な価値であり、この体験だけで
独立して利用者の場面探索を改善する。

**Independent Test**: 内容が時刻ごとに明確に異なる動画を開き、シークバーの複数位置をポイントして、
移動前にそれぞれの位置に対応する映像と時刻を確認できることを検証する。

**Acceptance Scenarios**:

1. **Given** 再生可能で長さが分かっている動画、**When** 利用者がシークバー上の位置をポイントする、
   **Then** その位置に対応する映像のサムネイルと時刻が表示される
2. **Given** サムネイルプレビューが表示されている状態、**When** 利用者がシークバー上を移動する、
   **Then** 表示位置、映像、時刻が現在ポイントしている位置に追従する
3. **Given** 利用者が目的の映像をプレビューで確認した状態、**When** その位置を選択する、**Then**
   通常のシークが行われ、その位置から再生を続けられる

---

### User Story 2 - ドラッグ中も移動先を確認する (Priority: P2)

利用者はマウスやタッチでシーク位置をドラッグしている間も、指またはポインターの位置に対応する
映像と時刻を確認できる。直接配信かライブ変換かを意識せず、動画全体の同じ時間軸で場面を探せる。

**Why this priority**: タッチ端末にはポイントだけの状態がなく、ドラッグ中の確認がなければ OR-001
の価値を端末によって得られないためである。

**Independent Test**: 直接配信の動画とライブ変換される動画を、ポインター端末とタッチ相当の端末で
それぞれドラッグし、同じ時刻に同じ内容のプレビューが出ることを確認する。

**Acceptance Scenarios**:

1. **Given** ポインターで操作する再生画面、**When** 利用者がシーク位置をドラッグする、**Then**
   ドラッグを終えるまで移動先のサムネイルと時刻が追従する
2. **Given** タッチで操作する再生画面、**When** 利用者がシーク位置をドラッグする、**Then** 指で
   シークバーが隠れていても移動先のサムネイルと時刻を確認できる
3. **Given** 直接配信またはライブ変換で再生している動画、**When** 利用者が同じ論理時刻を指す、
   **Then** 再生方式にかかわらず元動画のその時刻に対応するプレビューが表示される

---

### User Story 3 - プレビュー失敗時も視聴を続ける (Priority: P3)

サムネイルをすぐに取得できない場合でも、利用者は対象時刻を確認し、再生やシークをそのまま
続けられる。補助機能の失敗によって動画視聴そのものが止まらない。

**Why this priority**: プレビューは場面探索を助ける補助情報であり、既存の再生機能を不安定にしては
OR-001 がもたらす改善より大きな不利益になるためである。

**Independent Test**: サムネイルを利用できない状態を作り、時刻表示、再生、シーク、画面離脱が
いずれも利用できることを確認する。

**Acceptance Scenarios**:

1. **Given** 対象位置のサムネイルを取得中、**When** 利用者が別の位置へ移動する、**Then** 現在の
   対象時刻が表示され、以前の位置の映像を現在の結果として表示しない
2. **Given** 対象位置のサムネイルを取得できない動画、**When** 利用者がシーク位置を選択する、
   **Then** サムネイルの失敗に妨げられず、その位置へ移動できる
3. **Given** プレビュー表示中の動画、**When** 利用者が再生画面を離れる、**Then** プレビューが
   ほかの画面へ残らず、通常どおり一覧へ戻れる

### Edge Cases

- 動画の先頭と末尾を指した場合も、有効な動画範囲の時刻と映像を表示する
- プレビューが画面の左右端に近い場合も、表示全体を画面内に保つ
- 非常に短い動画、非常に長い動画、可変フレームレートの動画でも、表示時刻と映像の対応を保つ
- シークバー上を短時間で往復した場合は、現在指している位置より前の結果へ表示を巻き戻さない
- 同じ時刻付近を繰り返し指した場合は、利用可能な直近の結果を再利用して表示のちらつきや遅延を
  増やさない
- 動画の解析が未完了、長さが不明、元ファイルが移動・削除済み、または映像を取り出せない場合も、
  再生画面全体をプレビューのエラーで置き換えない
- 再生中、一時停止中、ミュート中のいずれでも、プレビューの表示によって再生状態を変更しない
- キーボードによる既存の再生・シーク操作とフォーカス表示を妨げない

## Scope

### Included

- 再生画面のシークバー上での静止画と時刻のプレビュー
- ポイント、ポインタードラッグ、タッチドラッグへの追従
- 直接配信とライブ変換に共通する元動画の時間軸
- 取得中、取得失敗、利用不能時にも既存の再生とシークを維持する縮退動作

### Out of Scope

- 動画一覧画面でのホバー再生、自動再生、動画クリップ表示
- 音声のプレビュー
- 動画本体の再生方式、変換品質、再生位置保存ルールの変更
- シーク操作とは独立した場面一覧、チャプター、タイムライン編集

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、再生画面のシークバー上で利用者が示している位置に対応する静止画と
  時刻を、実際に移動する前に表示しなければならない
- **FR-002**: システムは、シークバー上の位置を動画全体の論理時刻へ対応付け、表示する静止画と
  時刻を同じ対象位置にしなければならない
- **FR-003**: システムは、ポインターで位置を示している間、およびポインターまたはタッチで
  ドラッグしている間、プレビューを表示しなければならない
- **FR-004**: システムは、利用者が示す位置の変化にプレビューを追従させ、古い位置の結果を新しい
  位置の結果として表示してはならない
- **FR-005**: システムは、先頭、末尾、画面端を含むすべての有効位置で、プレビュー全体を表示領域内に
  保たなければならない
- **FR-006**: システムは、直接配信とライブ変換のどちらで再生している場合も、元動画の同じ論理時刻に
  対して同じ意味のプレビューを提供しなければならない
- **FR-007**: システムは、同じ時刻付近を繰り返し示す操作で利用可能な結果を再利用し、操作量に比例して
  表示の遅延や不安定さが増えないようにしなければならない
- **FR-008**: システムは、静止画の取得中または取得失敗時にも対象時刻を表示し、通常の再生とシークを
  継続できるようにしなければならない
- **FR-009**: システムは、長さが不明、対象位置が無効、動画または元ファイルが利用不能、映像を取得不能な
  場合を、再生画面全体を停止させずに扱わなければならない
- **FR-010**: システムは、利用者がシークバーから離れる、ドラッグを終える、対象動画を切り替える、
  または再生画面を離れるとき、不要になったプレビューを残してはならない
- **FR-011**: システムは、プレビューの表示または失敗によって、動画の再生状態、保存済み再生位置、
  視聴済み状態を変更してはならない
- **FR-012**: プレビューは補助表示として扱い、独立した操作対象やキーボードのフォーカス先を増やさず、
  既存のシーク操作とそのフォーカス表示を維持しなければならない
- **FR-013**: プレビューは、既存プレイヤー内で動画と再生操作を主役に保ち、映像、時刻、シーク位置の
  対応が一目で分かる視覚的階層、密度、余白、文字、操作優先順位で表示されなければならない

### UI Acceptance Criteria

- **視覚的階層**: 動画が常に最大の表示領域であり、プレビューはポインターで位置を示している間、
  またはポインター・タッチでドラッグしている間だけ現れる。プレビューはシーク位置との対応が
  分かる場所に置き、動画の中心や主要な再生操作を恒常的に覆わない
- **情報密度**: プレビュー内に表示するのは対象位置の静止画と時刻だけとし、題名、ファイル情報、
  説明文、独立した操作を追加しない
- **余白のリズム**: 静止画と時刻は一つの補助表示として近接させ、その外側には映像との境界を判別できる
  余白を保つ。シークバーや隣接する操作との間隔を失って一体化して見える状態を不合格とする
- **タイポグラフィ**: 時刻は既存プレイヤーの操作表示と同じ書体・階層の一行表示とし、静止画上でも
  判読できる。切り詰め、省略、折り返しによって時刻を読み違える状態を不合格とする
- **操作の優先順位**: シークバーと既存の再生操作が先に操作でき、プレビュー自身はクリック、タップ、
  フォーカスの対象にならない。プレビューがポインターまたはタッチのシーク操作を遮る状態を不合格とする
- **視覚レビュー**: 360px、768px、1280pxの各表示幅で、動画の先頭、中央、末尾にプレビューを出し、
  上記5観点、画面外へのはみ出し、映像・時刻・シーク位置の対応、操作との重なりを確認する

### Key Entities

- **プレビュー対象位置**: 利用者がシークバー上で現在示している、元動画全体の論理時刻。表示位置と
  時刻表記の基準になる
- **プレビュー内容**: 対象位置に対応する映像の静止画と時刻。再生位置や視聴済み状態とは別の補助情報
- **プレビュー状態**: 非表示、取得中、表示中、利用不能のいずれか。利用不能でも既存の再生とシークは
  継続する

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 通常の利用環境で位置を示してから1秒以内に、95%以上の試行でその位置の時刻と
  サムネイルが表示される（対応: OR-001 の「サムネイルプレビュー」）
- **SC-002**: 内容を時刻で照合できる試験動画の先頭付近、中央、末尾付近を各10回示したとき、100%の
  表示で時刻が対象位置から1秒以内、映像内容がその時刻に対応する（対応: OR-001 の「動画シーク時」）
- **SC-003**: 10秒間に100回以上対象位置を変える試験でも、最後の操作から1秒以内に最新位置の
  プレビューが表示され、その後に古い位置の表示へ戻る事象が0件である（対応: OR-001 の場面確認）
- **SC-004**: サムネイルを取得不能にした試験の100%で、対象時刻を確認でき、再生とシークを継続できる
  （対応: OR-001 のシーク体験）
- **SC-005**: 直接配信とライブ変換の試験動画について同じ10か所を示したとき、100%の表示で対象となる
  元動画の論理時刻が一致する（対応: OR-001 の動画シーク時プレビュー）
- **SC-006**: 360px、768px、1280pxの各表示幅で、先頭、中央、末尾のプレビューが画面外へはみ出す、
  またはシーク操作を妨げる事象が0件である（対応: OR-001 の利用可能なプレビュー）
- **SC-007**: 初めて本機能を使う試験参加者の90%以上が、内容の異なる3つの指定場面を、説明なしで
  各1回のシーク選択によって目標時刻から5秒以内に選べる（対応: OR-001 の場面探索改善）
- **SC-008**: 一覧画面で新たに動画再生または動画クリップ表示が始まる箇所が0件である
  （対応: OR-002 の別機能として扱う境界）
- **SC-009**: 360px、768px、1280pxの視覚レビューで、UI Acceptance Criteria の5観点をすべて満たし、
  不合格条件に該当する表示が0件である（対応: OR-001 の利用可能なプレビュー）

## Settled Without Asking

- プレビューはシークバーの対象位置に近接して表示し、中央揃えを基本に画面端で内側へ収める —
  動画プレイヤーで一般化しているシークプレビューの形と Issue #117 の画面端要件
- 静止画と時刻を一緒に表示する — Issue #117 の目的と要件
- ポインターではシークバー上に位置を示している間、タッチではドラッグ中に表示し、操作終了後は
  隠す — Issue #117 の操作要件と、ホバー状態を持たないタッチ端末で一般化している操作
- キーボード操作のためにプレビュー自体を新しいフォーカス先にはせず、既存のシーク操作を維持する —
  Issue #117 のアクセシビリティ要件
- 直接配信とライブ変換のどちらでも元動画全体の論理時刻を基準にする — Issue #117 および
  [008 MP4 ライブ変換仕様](../008-live-mp4-playback/spec.md) User Story 2
- 位置を示してから1秒以内の表示を目標とし、時刻と映像は対象位置から1秒以内で一致させる —
  既存のシーク再開目標が2秒以内である [002 コア動画ライブラリ仕様](../002-core-video-library/spec.md)
  SC-004 と、移動前に確認するシークプレビューで一般化している即時応答
- 取得中または失敗時は時刻だけでも確認でき、シークを妨げない — Issue #117 の失敗時要件
- 既存プレイヤーの暗い配色、役割ベースの色、8px以下の角丸、既存の文字階層を維持する —
  [UI 見た目の規則](../../docs/design-docs/library-ui-design-system.md) と現行再生画面
- プレビューは動画と再生操作に従属する一時的な補助表示とし、ページ区画や常設情報へ広げない —
  Issue #117 の目的および現行再生画面の情報階層
- 一覧画面でのホバー再生、自動再生、動画クリップ表示は含めない — OR-002 と Issue #117 の対象外
- 本機能は以前から Phase 2 へ送られていたシークプレビューを製品要件として具体化する —
  [技術選定](../../docs/design-docs/tech-stack-selection.md)「8. 実装の進め方」と
  [002 の調査記録](../002-core-video-library/research.md)「未解決のまま Phase 2 以降へ送る論点」
