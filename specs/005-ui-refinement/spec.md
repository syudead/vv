# Feature Specification: 原案デザインに合わせた UI の再構築

**Feature Directory**: `specs/005-ui-refinement`

**Created**: 2026-09-14

**Status**: Draft

**Input**: User description: "UIを最低限の張りぼてからまともにする"

**原案**: [002 の assets/ui-mockup.webp](../002-core-video-library/assets/ui-mockup.webp)
**現状**: [docs/screenshots/](../../docs/screenshots/) の `20260914-p7-*`

原案と現在の実装が大きく乖離している。その差分を**機能を変えずに**埋める。
サーバーの API も、保存するデータも、利用者が行える操作も一切変えない。変えるのは
レイアウトと UI コンポーネントだけである。

## 1. レイアウト構造

現状はヘッダーもサイドバーも無く、ツールバーとグリッドが直接ページに置かれている。
原案は 3 領域に分かれている。

| 領域 | 位置・サイズ | 中身 | 現状 |
| --- | --- | --- | --- |
| サイドバー | 左、固定幅 240px、スクロールしない | ロゴ、ナビゲーション | **無い** |
| ヘッダー | 上、固定高 56px、スクロールしない | タブ | **無い** |
| コンテンツ | 残り全体、ここだけスクロールする | ツールバー、動画グリッド | ページ全体がこれ |

幅 640px 未満ではサイドバーを非表示にし、ロゴをヘッダーへ移す。コンテンツは全幅になる。
サイドバーを開くボタンは置かない（操作が増えるため。「スコープ外」を参照）。

## 2. 作る UI コンポーネント

「現状」が「無し」のものは新規作成、それ以外は既存の作り直しである。

| # | コンポーネント | 役割 | 現状 |
| --- | --- | --- | --- |
| C1 | Sidebar | 左の固定領域そのもの | 無し |
| C2 | Logo | 製品アイコン + 製品名の 2 段 | 小さなテキスト 1 行 |
| C3 | NavItem | アイコン + ラベル + 件数バッジ。選択状態を持つ | 無し |
| C4 | Header | 上の固定領域そのもの | 無し |
| C5 | Tab | ヘッダー内のタブ。選択中は下線 | 無し |
| C6 | SearchInput | 虫眼鏡アイコン付きの検索欄 | アイコン無しの素の入力欄 |
| C7 | Select | ソート用のドロップダウン | ブラウザ既定の `select` |
| C8 | DensitySlider | 表示密度を変えるスライダー | ブラウザ既定の `select` |
| C9 | VideoCard | サムネイル + タイトル行を 1 つの枠にまとめる | サムネイルとタイトルが直置き |
| C10 | DurationBadge | 再生時間。サムネイル右下 | 位置は同じ、体裁が違う |
| C11 | QualityBadge | 4K / HD。サムネイル左下 | 無し |
| C12 | ProgressBar | 視聴位置。サムネイル下端 | あり（流用） |
| C13 | Notice | 情報 / 警告 / エラーの 3 段階の通知 | 場所ごとにバラバラ |

### 各コンポーネントの状態

C3・C5・C6・C7・C8・C9 は操作できる。いずれも次の 4 状態を視覚的に区別する。

| 状態 | 表現 |
| --- | --- |
| 通常 | 既定の配色 |
| hover | 背景を 1 段明るく |
| focus | アクセントカラーの輪郭。キーボード操作でも見える |
| active | 背景を 1 段暗く |

C3 と C5 は加えて「選択中」を持ち、アクセントカラーで示す。

## 3. デザイントークン

| トークン | 現状 | 変更後 |
| --- | --- | --- |
| アクセントカラー | 青 | 原案のシアン系 |
| カードの角丸 | サムネイルのみ | カード全体に統一 |

文字色と背景色のコントラスト比は 4.5:1 以上（大きな文字は 3:1 以上）とする。

## 4. 既存機能との対応

新しい UI コンポーネントは、すべて既存の機能・データに接続する。新規の API も
保存項目も作らない。

| コンポーネント | 接続先 |
| --- | --- |
| C3 NavItem「すべての動画」 | 既存の一覧。件数は既存の総件数 |
| C5 Tab「動画」 | 既存の一覧。タブは 1 つだけ |
| C6 SearchInput | 既存の題名検索 |
| C7 Select | 既存のソート（`addedDesc` / `titleAsc`） |
| C8 DensitySlider | 既存の表示密度 3 段階（`dense` / `standard` / `relaxed`） |
| C11 QualityBadge | 既存の解像度（`width` × `height`）から算出。1920×1080 超で 4K、1280×720 以上で HD、それ未満とデータ無しは非表示 |
| C12 ProgressBar | 既存の再生位置 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - レイアウトが 3 領域に分かれる (Priority: P1)

一覧を開くと、左にサイドバー、上にヘッダー、残りがコンテンツという構造になっている。
グリッドをスクロールしてもサイドバーとヘッダーは動かない。

**Why this priority**: 他のコンポーネントはすべてこの構造の中に置かれる。先に決まらないと
配置が決まらない。

**Independent Test**: 幅 1280 で一覧を開き、3 領域が指定のサイズで存在し、グリッドを
スクロールしてもサイドバーとヘッダーが動かなければ成功。

**Acceptance Scenarios**:

1. **Given** 幅 1280 の一覧、**When** 開く、**Then** 左に幅 240px のサイドバー、上に高さ
   56px のヘッダーがあり、残りがコンテンツである
2. **Given** 幅 1280 の一覧、**When** グリッドを下までスクロールする、**Then** サイドバーと
   ヘッダーは動かず、コンテンツだけがスクロールする
3. **Given** 幅 360 の一覧、**When** 開く、**Then** サイドバーは非表示になり、ロゴは
   ヘッダー内にあり、コンテンツは全幅である
4. **Given** 幅 640 の一覧、**When** 開く、**Then** サイドバーが表示される（640 が境界）
5. **Given** 再生画面、**When** 開く、**Then** 一覧と同じ 3 領域の中に置かれ、一覧との
   行き来で構造が変わらない

---

### User Story 2 - 動画カードが原案の形になる (Priority: P2)

動画 1 本がカードとして表示される。サムネイルの上に再生時間と画質のバッジが乗り、
下にタイトル行が付く。

**Why this priority**: 画面の面積の大半を占める。数が多いので、ここが変わると見た目の
印象が最も大きく変わる。

**Independent Test**: 4K・HD・SD・解像度不明の動画を含む一覧を表示し、各カードの 4 要素
（サムネイル・タイトル行・時間バッジ・画質バッジ）が原案どおりに配置されていれば成功。

**Acceptance Scenarios**:

1. **Given** 一覧、**When** カードを見る、**Then** サムネイルとタイトル行が 1 つの枠に
   まとまり、枠全体に角丸が付く
2. **Given** 1920×1080 を超える動画、**When** 一覧に並ぶ、**Then** サムネイル左下に「4K」が出る
3. **Given** 1280×720 以上 1920×1080 以下の動画、**When** 一覧に並ぶ、**Then**「HD」が出る
4. **Given** 1280×720 未満、または解像度が取得できていない動画、**When** 一覧に並ぶ、
   **Then** 画質バッジは出ない
5. **Given** 任意の動画、**When** 一覧に並ぶ、**Then** サムネイル右下に再生時間のバッジが出る
6. **Given** サムネイルが白い動画、**When** 2 つのバッジを見る、**Then** どちらも読める
7. **Given** タイトルが長い動画、**When** 一覧に並ぶ、**Then** 2 行で切られ、末尾が省略される

---

### User Story 3 - ツールバーのコンポーネントを作り直す (Priority: P3)

検索欄・ソート・密度の 3 つが、ブラウザ既定の見た目ではなく原案の体裁になる。
機能は今までと同じ。

**Why this priority**: 機能が既にあるので、見た目の差し替えだけで差分が閉じる。

**Independent Test**: 3 つのコンポーネントを操作し、見た目が原案どおりで、動作が
変更前と同じであれば成功。

**Acceptance Scenarios**:

1. **Given** ツールバー、**When** 検索欄を見る、**Then** 左端に虫眼鏡アイコンがある
2. **Given** ツールバー、**When** ソートを見る、**Then** ブラウザ既定の `select` ではなく
   原案の体裁のドロップダウンで、選択肢は従来どおり 2 つである
3. **Given** ツールバー、**When** 密度を変える、**Then** スライダーで 3 段階を選べ、
   結果は従来の `select` と同じである
4. **Given** ツールバー、**When** 件数を見る、**Then** 右端に「N本」と出る
5. **Given** 任意の設定を変えた後、**When** 再読み込みする、**Then** 従来どおり設定が残る

---

### User Story 4 - 通知の見た目を 3 段階に統一する (Priority: P4)

「0:11 から再開しました」「この形式は再生できません」「読み取れませんでした」
「画像を準備中」が、情報 / 警告 / エラーの 3 段階のいずれかとして同じ体裁で出る。

**Why this priority**: 数は少ないが、今は場所ごとに体裁が違う。他のコンポーネントの
配色が決まってから揃える。

**Independent Test**: 4 つの通知を順に発生させ、3 段階のいずれかの体裁になっていれば成功。

**Acceptance Scenarios**:

1. **Given** 任意の通知、**When** 表示される、**Then** 情報 / 警告 / エラーのどれかが
   色と形から判別できる
2. **Given** 再生位置がある動画、**When** 再生画面を開く、**Then** 再開の通知は情報段階で、
   動画プレーヤーを画面外へ押し出さない高さである
3. **Given** サムネイル生成中の動画と生成失敗の動画、**When** 一覧に並ぶ、**Then** 前者は
   情報段階、後者はエラー段階として区別できる

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 画面は「1. レイアウト構造」の 3 領域で構成すること
- **FR-002**: サイドバーとヘッダーは、コンテンツのスクロールで移動しないこと
- **FR-003**: 幅 640px 未満ではサイドバーを非表示にし、ロゴをヘッダーへ移すこと。
  ロゴはどの幅でも画面上に存在すること
- **FR-004**: 「2. 作る UI コンポーネント」の C1〜C13 をすべて実装すること
- **FR-005**: C3・C5・C6・C7・C8・C9 は、通常 / hover / focus / active の 4 状態を
  視覚的に区別すること
- **FR-006**: focus はキーボード操作時にも見えること
- **FR-007**: 画質バッジの判定は「4. 既存機能との対応」の規則に従うこと
- **FR-008**: サムネイル上のバッジは、サムネイルの明暗によらず読めること
- **FR-009**: アクセントカラーを原案のシアン系に変更すること
- **FR-010**: 文字色と背景色のコントラスト比は 4.5:1 以上（大きな文字は 3:1 以上）とすること
- **FR-011**: 動きを減らす設定（`prefers-reduced-motion`）の利用者には遷移アニメーションを
  省くこと。ただし操作結果は判別できること
- **FR-012**: 利用者が行える操作の種類と数を変えないこと。並べ替え・密度変更・検索・
  取り込み・再生・再開はすべて従来どおり行えること
- **FR-013**: サーバーの API と保存するデータを変えないこと
- **FR-014**: [004](../004-library-ui/spec.md) の受け入れ基準を引き続き満たすこと

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: C1〜C13 の 13 コンポーネントがすべて実装され、原案と並べて差分が無いこと
- **SC-002**: 幅 1280・768 でサイドバーとヘッダーが表示され、スクロールしても動かない。
  幅 360 でサイドバーが非表示になり、ロゴがヘッダーに残る
- **SC-003**: 本仕様の前後で、利用者が行える操作の種類と数が変わらない
- **SC-004**: 一覧 → 再生 → 一覧の往復をキーボードだけで行える
- **SC-005**: コントラスト比 4.5:1 を下回る配色の組み合わせが 0 件
- **SC-006**: 幅 360 で横スクロールが発生しない
- **SC-007**: [004](../004-library-ui/spec.md) の受け入れ基準がすべて通る

## スコープ外

原案にあるが、対応する機能が無いため作らない。押せない UI を置くと壊れて見えるため、
グレーアウトでも表示しない。

| 原案の要素 | 理由 |
| --- | --- |
| NavItem「お気に入り」「未整理」 | 該当機能が無い |
| サイドバーの「コレクション」「タグ」セクション | 該当機能が無い |
| Tab「画像」「コレクション」「タグ」 | 該当機能が無い |
| フィルタボタン（漏斗アイコン） | 該当機能が無い |
| 設定ボタン（歯車アイコン） | 設定画面が無い。置くと操作が 1 つ増え FR-012 に反する |
| カードの「その他の操作」（縦三点） | メニューに入れる操作が無い |
| 複数選択のチェックボックス | 一括操作が無い |
| サイドバーを開くボタン（幅 640 未満） | 操作が 1 つ増え FR-012 に反する。サイドバーの中身が NavItem 1 つのみで、隠しても到達できない画面は無い |
| グリッド / リストの表示切替 | 表示形式を 1 つ増やすことにあたる。骨格が入った後に別途判断する |

## Assumptions

- 原案の暗い配色を維持する。明るいテーマへの切り替えは扱わない
- 004 で定義済みのデザイントークン（色・タイポグラフィ・スペーシング）を土台に、
  不足分を追加する。作り直しではない
- 再生画面の情報項目（長さ・解像度・形式・映像・音声・サイズ）の内容は変えない。
  表示形式のみ変更する
- サイドバーの NavItem は当面「すべての動画」1 つだけである
- ヘッダーの Tab は当面「動画」1 つだけである
- 対象ブラウザは現行版の主要ブラウザ（デスクトップ・モバイル）
- 動作確認用の動画はその場で生成し、実データは使わない（002・004 と同じ）
