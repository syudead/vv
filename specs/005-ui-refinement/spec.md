# Feature Specification: 張りぼての UI を実用に耐える画面にする

**Feature Directory**: `specs/005-ui-refinement`

**Created**: 2026-09-14

**Status**: Draft

**Input**: User description: "UIを最低限の張りぼてからまともにする"

**現状の画面**: [docs/screenshots/](../../docs/screenshots/) の `20260914-p7-*`
（[004](../004-library-ui/spec.md) の完了時点の姿）

**画面案**: [002 の assets/ui-mockup.webp](../002-core-video-library/assets/ui-mockup.webp)

## User Scenarios & Testing *(mandatory)*

[004](../004-library-ui/spec.md) で、一覧・再生・検索・取り込みの 4 画面は**配置と規則**を
得た。動画の静止画が主役になり、暗い背景が定まり、狭い画面でも崩れなくなった。

しかし画面は**まだ張りぼてである**。「それらしく見える枠」までは出来たが、枠の中に
入っている部品の多くが**ブラウザの既定のまま**で、作り込まれた製品の画面になっていない。
現状の画面から読み取れる具体は次のとおりである。

| 場所 | いまの姿 | 何が張りぼてか |
| --- | --- | --- |
| 再生画面の「← 一覧へ戻る」 | 既定のリンク色（青）の文字 | 暗い背景の画面に、ブラウザ既定の青リンクだけが浮いている |
| 再生画面の再生操作 | ブラウザに元から付いている再生操作の列 | 配色も形も製品と無関係で、ここだけ別の製品に見える |
| 再生画面の動画の情報 | 等幅文字の 6 行の羅列 | 開発者向けの出力の見た目で、読み物になっていない |
| 再生画面の再開の知らせ | 高さのある枠に短い文が 1 行 | 主役であるはずの映像を押し下げている |
| 一覧の並び替え・表示 | ブラウザ既定の選択欄 | 既定の下向き三角と枠のままで、周りの作りと揃っていない |
| 全体 | 触れたとき・選ばれたときの返りが乏しい | 押せるのかどうかが見た目から分からない |

本仕様は、**取得する情報も保存する情報も 1 つも増やさずに**、この「既定のまま／作りかけ
のまま」を潰し切る。新しい画面は増やさない。増やすのは**部品の質**だけである。

### User Story 1 - 再生画面が作り込まれた画面になる (Priority: P1)

利用者が動画を選ぶと、そこは「ブラウザで動画ファイルを開いた画面」ではなく、本製品の
再生画面に見える。戻る道も、再生の操作も、動画の情報も、一覧と同じ設計の言葉で描かれて
いる。映像がいちばん大きく、そのほかは映像を邪魔しない。

**Why this priority**: 張りぼてがいちばん露骨に出ているのがこの画面である。既定の青リンク・
既定の再生操作・等幅の情報という 3 つが同時に並んでおり、ここを直すだけで「作りかけ」の
印象が最も大きく減る。

**Independent Test**: 途中まで見た動画を 1 本開く。画面上にブラウザ既定の見た目のままの
部品が 1 つも無く、戻る道・再生操作・動画の情報がいずれも一覧と同じ配色・字送り・
角の丸みで描かれていれば成功。

**Acceptance Scenarios**:

1. **Given** 再生画面、**When** 開く、**Then** 「一覧へ戻る」は既定のリンク色ではなく、
   本製品の配色で描かれ、文字だけでなく押せる範囲として十分な大きさを持つ
2. **Given** 再生画面、**When** 動画の情報（長さ・解像度・形式・映像・音声・大きさ）を見る、
   **Then** 等幅の羅列ではなく、項目名と値が読み分けられる体裁で並ぶ
3. **Given** 途中まで見た動画、**When** 開く、**Then** 再開した旨と「先頭から見直す」は
   映像を画面の下へ押しやらない大きさで出る
4. **Given** 再生画面、**When** 映像の大きさを見る、**Then** 映像は画面の主役として、
   画面の縦の大半を占める
5. **Given** 再生できない形式の動画、**When** 開く、**Then** その知らせは US3 で定める
   共通の体裁で出る

---

### User Story 2 - 一覧の操作列が道具らしくなる (Priority: P2)

一覧の上にある探す・並べ替える・表示・取り込むの 4 つが、ひとそろいの道具に見える。
既定の選択欄のままの部品は無く、どれが入力でどれが実行なのかが形から分かる。

**Why this priority**: 一覧はいちばん長く見る画面で、操作列はその一覧で唯一触る場所で
ある。US1 の次に目につく既定部品（選択欄 2 つ）がここに集まっている。

**Independent Test**: 一覧を開き、4 つの入口それぞれについて、既定の見た目のままでないこと
と、触れた／選ばれた／押した の返りがあることを確かめる。

**Acceptance Scenarios**:

1. **Given** 一覧、**When** 並び替え・表示の入口を見る、**Then** ブラウザ既定の選択欄の
   見た目ではなく、本製品の配色と形で描かれている
2. **Given** 一覧、**When** 取り込みの状態（前回の取り込みの結果）を見る、**Then** それは
   実行の入口と読み分けられる体裁で置かれている
3. **Given** 一覧、**When** キーボードだけで操作列を辿る、**Then** いまどれが選ばれて
   いるかが見た目で分かり、順序は画面の並びと一致する
4. **Given** 一覧、**When** 操作列のどれかに触れる、**Then** 触れたことが見た目で返る

---

### User Story 3 - 知らせと状態が同じ体裁で出る (Priority: P3)

「0:11 から再開しました」「映像の形式 (hevc) は再生できません」「読み取れませんでした」
「画像を準備中」といった知らせが、画面をまたいで同じ形・同じ配色の段階で出る。利用者は
色と形だけで、それが情報なのか警告なのか失敗なのかを見分けられる。

**Why this priority**: いまは知らせごとに置き場所も体裁も違い、同じ重さのことが違って
見える。US1・US2 が整ったあとに、その規則をそのまま知らせへ広げる。

**Independent Test**: 知らせが出る 4 つの状況を順に作り、体裁が同じ規則から選ばれて
いることと、情報／警告／失敗が見分けられることを確かめる。

**Acceptance Scenarios**:

1. **Given** 知らせが出る任意の画面、**When** 見る、**Then** 情報・警告・失敗のどれで
   あるかが、文言を読まなくても色と形から分かる
2. **Given** 静止画がまだ無い項目、**When** 一覧に並ぶ、**Then** 「準備中」は失敗とは
   違う見た目で示される
3. **Given** 静止画を作れなかった項目、**When** 一覧に並ぶ、**Then** 「作れなかった」は
   準備中とは違う見た目で示される
4. **Given** 知らせが静止画に重なる場合、**When** 見る、**Then** 知らせの下の静止画が
   透けて読みにくくなることがない

---

### User Story 4 - 触れたときに画面が応える (Priority: P4)

押せるものは押せるように見え、触れれば返りがあり、切り替わるときは唐突に飛ばない。
動きが苦手な利用者の設定は尊重される。

**Why this priority**: 「まとも」と「張りぼて」を分ける最後の差だが、US1〜US3 が
無いと載せる先が無い。

**Independent Test**: 押せる要素それぞれについて 4 つの状態を出し分け、動きを減らす
設定を入れた状態でも操作が成立することを確かめる。

**Acceptance Scenarios**:

1. **Given** 押せる要素、**When** 触れる・選ぶ・押す・使えない、**Then** 4 つの状態が
   それぞれ見分けられる
2. **Given** 動きを減らす設定を入れた利用者、**When** 画面を操作する、**Then** 動きは
   省かれるが、操作の結果は同じように分かる
3. **Given** 一覧の項目、**When** 狙いを合わせる、**Then** どれを選んでいるかが、
   静止画が暗いか明るいかによらず分かる

---

### Edge Cases

- 題名が長く、一覧の枠にも再生画面の見出しにも収まらないとき、どこで切るか
- 動画の情報の一部が取れていない（解像度が不明など）とき、その行をどう見せるか
- 知らせが同時に 2 つ以上出る条件が揃ったとき、どちらを優先するか
- 静止画がほぼ白い／ほぼ黒いとき、その上に重なる知らせと選択の印が読めるか
- 動きを減らす設定と、狙いを合わせた印の両方が要るとき、印は動き以外で示せるか
- 極端に狭い画面で、操作列の 4 つが 1 行に収まらないとき、どう畳むか

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 画面上の操作できる部品は、ブラウザ既定の見た目のままであってはならない。
  対象は少なくとも、並び替えの選択欄・表示の選択欄・検索の入力欄・取り込みの実行・
  再生画面の戻る道である
- **FR-002**: 再生画面の「一覧へ戻る」は、本製品の配色で描かれ、文字よりも広い範囲で
  押せなければならない
- **FR-003**: 動画の情報は、項目名と値が読み分けられる体裁で示されなければならない。
  等幅文字による羅列であってはならない
- **FR-004**: 再生の操作（再生・一時停止・位置の移動・音量・全画面）は
  [NEEDS CLARIFICATION: 既定の操作列を本製品の見た目に置き換えるか、既定のまま残して
  周辺だけを整えるか]
- **FR-005**: 再開の知らせは、映像が画面の主役であることを損なわない大きさでなければ
  ならない
- **FR-006**: 押せる要素はすべて、触れている・選ばれている・押されている・使えない の
  4 つの状態を見分けられなければならない
- **FR-007**: 選ばれていることの印は、キーボードだけで操作する利用者にも見えなければ
  ならない
- **FR-008**: 文字の大きさ・太さ・行間は、あらかじめ決めた段階の中からのみ選ばれ
  なければならない
- **FR-009**: 余白は、あらかじめ決めた刻みの中からのみ選ばれなければならない
- **FR-010**: 知らせは、情報・警告・失敗 の 3 つの段階のいずれかに割り当てられ、
  段階ごとに決まった体裁で示されなければならない
- **FR-011**: 静止画に重なる知らせと選択の印は、静止画の明暗によらず読めなければならない
- **FR-012**: 動きを減らす設定を入れた利用者に対しては、動きを省かなければならない。
  ただし操作の結果は動き以外の手段で分からなければならない
- **FR-013**: 文字と背景の明暗の差は 4.5:1 以上でなければならない（大きな文字は 3:1 以上）
- **FR-014**: 本機能は、サーバーから受け取る情報も、端末に残す情報も増やしてはならない
- **FR-015**: [004](../004-library-ui/spec.md) の受け入れ（SC-001〜）は、引き続き
  満たされなければならない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一覧・再生の 2 画面において、ブラウザ既定の見た目のままで残っている操作
  部品が **0 個**である
- **SC-002**: 本製品を初めて見る 5 人のうち 4 人が、説明なしに 30 秒以内で、探す・
  並べ替える・表示を変える・取り込む の 4 つの入口を指し示せる
- **SC-003**: 再生画面で、利用者が動画の長さと解像度を読み取るまでに **5 秒以内**で
  到達できる
- **SC-004**: 一覧から動画を選び、再生し、一覧へ戻るまでを、**キーボードだけで**
  最後まで行える
- **SC-005**: 画面上の文字と背景の組み合わせのうち、明暗の差が 4.5:1 に満たないものが
  **0 組**である
- **SC-006**: 動きを減らす設定を入れた状態で、SC-002 と SC-004 が同じように成立する
- **SC-007**: [004](../004-library-ui/spec.md) の受け入れ基準が引き続きすべて通る

## スコープ外

いずれも「張りぼてを潰す」という本仕様の目的の外にあるか、裏側の機能を要するものである。

- タグ・お気に入り・コレクション・未整理といった整理の機能とその画面
  （裏側が無い。[004](../004-library-ui/spec.md) から引き続き対象外）
- 複数選択と一括操作
- 明るい配色への切り替え（暗い配色は 004 の前提。切り替えは別機能とする）
- 字幕、位置を動かすときの下見画像、変換による再生（いずれも裏側が未実装）
- サーバーから受け取る情報を増やす変更（撮影日時・フォルダ階層など）
- 認証と利用者ごとの画面
- 新しい画面の追加

## Assumptions

- **暗い配色を引き続き前提とする。** 004 が画面案から採り、静止画を主役にする画面に
  合っているためである
- **004 が定めた見た目の決まり（色・字・間隔の token）を土台にし、足りない段階を
  足す形で進める。** 作り直しではない
- **再生画面の情報の並び（長さ・解像度・形式・映像・音声・大きさ）は変えない。**
  変えるのは見せ方だけである
- **対象のブラウザは、現行版の主要なブラウザ（デスクトップとモバイル）とする**
- **SC-002 の利用者試験は、実際の 5 人が用意できない場合、同等の観点での確認記録を
  もって代える**
- 動作確認用の動画はその場で生成して用意し、実データを使わない（002・004 と同じ方針）
