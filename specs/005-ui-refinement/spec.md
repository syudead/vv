# Feature Specification: 原案デザインに合わせた UI コンポーネントの再構築

**Feature Directory**: `specs/005-ui-refinement`

**Created**: 2026-09-14

**Status**: Draft

**Input**: User description: "UIを最低限の張りぼてからまともにする"

**原案**: [002 の assets/ui-mockup.webp](../002-core-video-library/assets/ui-mockup.webp)
**現状**: [docs/screenshots/](../../docs/screenshots/) の `20260914-p7-*`

原案と現在の実装が乖離している。そのうち**コンテンツ領域のコンポーネント**の差分を、
機能を変えずに埋める。サーバーの API も、保存するデータも、利用者が行える操作も
一切変えない。

**レイアウト構造（サイドバー・ヘッダー）は今回のスコープ外**である。現状どおり、
ツールバーと動画グリッドがページに直接置かれた構成のまま進める。

## 1. 作る UI コンポーネント

「現状」が「無し」のものは新規作成、それ以外は既存の作り直しである。

| # | コンポーネント | 役割 | 現状 |
| --- | --- | --- | --- |
| C1 | VideoCard | サムネイルとタイトル行を 1 つの枠にまとめる | サムネイルとタイトルが直置き |
| C2 | DurationBadge | 再生時間。サムネイル右下 | 位置は同じ、体裁が違う |
| C3 | SearchInput | 虫眼鏡アイコン付きの検索欄 | アイコン無しの素の入力欄 |
| C4 | Select | ソート用のドロップダウン | ブラウザ既定の `select` |
| C5 | DensitySlider | 表示密度を変えるスライダー | ブラウザ既定の `select` |
| C6 | Notice | 情報 / 警告 / エラーの 3 段階の通知 | 場所ごとにバラバラ |

### 各コンポーネントの状態

C1・C3・C4・C5 は操作できる。いずれも次の 4 状態を視覚的に区別する。

| 状態 | 表現 |
| --- | --- |
| 通常 | 既定の配色 |
| hover | 背景を 1 段明るく |
| focus | アクセントカラーの輪郭。キーボード操作でも見える |
| active | 背景を 1 段暗く |

## 2. デザイントークン

| トークン | 現状 | 変更後 |
| --- | --- | --- |
| アクセントカラー | 青 | 原案のシアン系 |
| カードの角丸 | サムネイルのみ | カード全体に統一 |

文字色と背景色のコントラスト比は 4.5:1 以上（大きな文字は 3:1 以上）とする。

## 3. 既存機能との対応

新しい UI コンポーネントは、すべて既存の機能・データに接続する。新規の API も
保存項目も作らない。

| コンポーネント | 接続先 |
| --- | --- |
| C3 SearchInput | 既存の題名検索 |
| C4 Select | 既存のソート（`addedDesc` / `titleAsc`） |
| C5 DensitySlider | 既存の表示密度 3 段階（`dense` / `standard` / `relaxed`） |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 動画カードが原案の形になる (Priority: P1)

動画 1 本がカードとして表示される。サムネイルの上に再生時間と画質のバッジが乗り、
下にタイトル行が付く。

**Why this priority**: 画面の面積の大半を占め、数も多い。ここが変わると見た目の印象が
最も大きく変わる。

**Independent Test**: 一覧を表示し、各カードの 3 要素（サムネイル・タイトル行・時間
バッジ）が原案どおりに配置されていれば成功。

**Acceptance Scenarios**:

1. **Given** 一覧、**When** カードを見る、**Then** サムネイルとタイトル行が 1 つの枠に
   まとまり、枠全体に角丸が付く
2. **Given** 任意の動画、**When** 一覧に並ぶ、**Then** サムネイル右下に再生時間のバッジが出る
3. **Given** サムネイルが白い動画、**When** 時間バッジを見る、**Then** 読める
4. **Given** タイトルが長い動画、**When** 一覧に並ぶ、**Then** 2 行で切られ、末尾が省略される

---

### User Story 2 - ツールバーのコンポーネントを作り直す (Priority: P2)

検索欄・ソート・密度の 3 つが、ブラウザ既定の見た目ではなく原案の体裁になる。
機能は今までと同じ。

**Why this priority**: 機能が既にあるので、見た目の差し替えだけで差分が閉じる。

**Independent Test**: 3 つのコンポーネントを操作し、見た目が原案どおりで、動作が
変更前と同じであれば成功。

**Acceptance Scenarios**:

1. **Given** ツールバー、**When** 検索欄を見る、**Then** 左端に虫眼鏡アイコンがある
2. **Given** ツールバー、**When** ソートを見る、**Then** ブラウザ既定の `select` ではなく
   原案の体裁のドロップダウンで、選択肢は従来どおり 2 つである
3. **Given** ツールバー、**When** 密度を変える、**Then** スライダーで 3 段階を選べ、
   結果は従来の `select` と同じである
4. **Given** 任意の設定を変えた後、**When** 再読み込みする、**Then** 従来どおり設定が残る

---

### User Story 3 - 通知の見た目を 3 段階に統一する (Priority: P3)

「0:11 から再開しました」「この形式は再生できません」「読み取れませんでした」
「画像を準備中」が、情報 / 警告 / エラーの 3 段階のいずれかとして同じ体裁で出る。

**Why this priority**: 数は少ないが、今は場所ごとに体裁が違う。他のコンポーネントの
配色が決まってから揃える。

**Independent Test**: 4 つの通知を順に発生させ、3 段階のいずれかの体裁になっていれば成功。

**Acceptance Scenarios**:

1. **Given** 任意の通知、**When** 表示される、**Then** 情報 / 警告 / エラーのどれかが
   色と形から判別できる
2. **Given** 再生位置がある動画、**When** 再生画面を開く、**Then** 再開の通知は情報段階で、
   動画プレーヤーを画面外へ押し出さない高さである
3. **Given** サムネイル生成中の動画と生成失敗の動画、**When** 一覧に並ぶ、**Then** 前者は
   情報段階、後者はエラー段階として区別できる

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 「1. 作る UI コンポーネント」の C1〜C6 をすべて実装すること
- **FR-002**: C1・C3・C4・C5 は、通常 / hover / focus / active の 4 状態を視覚的に
  区別すること
- **FR-003**: focus はキーボード操作時にも見えること
- **FR-004**: サムネイル上のバッジは、サムネイルの明暗によらず読めること
- **FR-005**: アクセントカラーを原案のシアン系に変更すること
- **FR-006**: 文字色と背景色のコントラスト比は 4.5:1 以上（大きな文字は 3:1 以上）とすること
- **FR-007**: 動きを減らす設定（`prefers-reduced-motion`）の利用者には遷移アニメーションを
  省くこと。ただし操作結果は判別できること
- **FR-008**: 利用者が行える操作の種類と数を変えないこと。並べ替え・密度変更・検索・
  取り込み・再生・再開はすべて従来どおり行えること
- **FR-009**: サーバーの API と保存するデータを変えないこと
- **FR-010**: ページ全体のレイアウト構造を変えないこと。サイドバーとヘッダーは追加しない
- **FR-011**: [004](../004-library-ui/spec.md) の受け入れ基準を引き続き満たすこと

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: C1〜C6 の 6 コンポーネントがすべて実装され、原案の該当部分と並べて
  差分が無いこと
- **SC-002**: 本仕様の前後で、利用者が行える操作の種類と数が変わらない
- **SC-003**: 一覧 → 再生 → 一覧の往復をキーボードだけで行える
- **SC-004**: コントラスト比 4.5:1 を下回る配色の組み合わせが 0 件
- **SC-005**: 幅 360 で横スクロールが発生しない
- **SC-006**: [004](../004-library-ui/spec.md) の受け入れ基準がすべて通る

## スコープ外

### レイアウト構造

サイドバーとヘッダーは今回作らない。原案にはあるが、中身として置ける項目が
「すべての動画」1 つと「動画」タブ 1 つしか無く、機能が増えた時点で改めて判断する。
これに伴い、次も対象外になる。

| 原案の要素 | 備考 |
| --- | --- |
| サイドバー全体（ロゴ・ナビゲーション項目） | 別途判断 |
| ヘッダー全体（タブ） | 別途判断 |

### 機能が無いため作らないもの

押せない UI を置くと壊れて見えるため、グレーアウトでも表示しない。

| 原案の要素 | 理由 |
| --- | --- |
| フィルタボタン（漏斗アイコン） | 該当機能が無い |
| 設定ボタン（歯車アイコン） | 設定画面が無い。置くと操作が 1 つ増え FR-008 に反する |
| カードの「その他の操作」（縦三点） | メニューに入れる操作が無い |
| 複数選択のチェックボックス | 一括操作が無い |
| グリッド / リストの表示切替 | 表示形式を 1 つ増やすことにあたる |
| 画質バッジ（4K / HD） | 今回は作らない |
| 視聴位置の進捗線の作り直し | 既存のものをそのまま使う |

## Assumptions

- 原案の暗い配色を維持する。明るいテーマへの切り替えは扱わない
- 004 で定義済みのデザイントークン（色・タイポグラフィ・スペーシング）を土台に、
  不足分を追加する。作り直しではない
- 再生画面の情報項目（長さ・解像度・形式・映像・音声・サイズ）の内容は変えない。
  表示形式のみ変更する
- 対象ブラウザは現行版の主要ブラウザ（デスクトップ・モバイル）
- 動作確認用の動画はその場で生成し、実データは使わない（002・004 と同じ）
