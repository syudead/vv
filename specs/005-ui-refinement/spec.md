# Feature Specification: 原案デザインに合わせた UI の再構築

**Feature Directory**: `specs/005-ui-refinement`

**Created**: 2026-09-14

**Status**: Draft

**Input**: User description: "UIを最低限の張りぼてからまともにする"

**原案**: [002 の assets/ui-mockup.webp](../002-core-video-library/assets/ui-mockup.webp)
**現状**: [docs/screenshots/](../../docs/screenshots/) の `20260914-p7-*`

原案と現在の実装が乖離している。その差分を**機能を変えずに**埋め、画面の見た目を
原案に一致させる。サーバーの API も、保存するデータも、利用者が実際に行える操作も
変えない。

裏側の機能が無い要素は、**表示のみのプレースホルダとして配置する**（「3. 表示のみの
要素」を参照）。原案の構図を再現することが目的であり、機能の有無で要素を省くと
構図が変わってしまうためである。

## 1. レイアウト構造

現状はヘッダーもサイドバーも無く、ツールバーとグリッドが直接ページに置かれている。
原案は 3 領域に分かれている。

| 領域 | 位置・サイズ | 中身 | 現状 |
| --- | --- | --- | --- |
| サイドバー | 左、固定幅 240px、独立してスクロール | ロゴ、ナビゲーション | 無し |
| ヘッダー | 上、固定高 56px、スクロールしない | タブ、設定ボタン | 無し |
| コンテンツ | 残り全体 | ツールバー、動画グリッド | ページ全体がこれ |

幅 640px 未満ではサイドバーを非表示にし、ロゴをヘッダーへ移す。

## 2. 作る UI コンポーネント

| # | コンポーネント | 役割 | 現状 |
| --- | --- | --- | --- |
| C1 | Sidebar | 左の固定領域そのもの | 無し |
| C2 | Logo | 製品アイコン + 製品名の 2 段 | 小さなテキスト 1 行 |
| C3 | NavItem | アイコン + ラベル + 件数。選択状態を持つ | 無し |
| C4 | SidebarSection | 「コレクション」「タグ」の見出しと項目群 | 無し |
| C5 | Header | 上の固定領域そのもの | 無し |
| C6 | Tab | ヘッダー内のタブ。選択中は下線 | 無し |
| C7 | IconButton | フィルタ・設定・表示切替のアイコンボタン | 無し |
| C8 | VideoCard | サムネイルとタイトル行を 1 つの枠にまとめる | サムネイルとタイトルが直置き |
| C9 | DurationBadge | 再生時間。サムネイル右下 | 位置は同じ、体裁が違う |
| C10 | SearchInput | 虫眼鏡アイコン付きの検索欄 | アイコン無しの素の入力欄 |
| C11 | Select | ソート用のドロップダウン | ブラウザ既定の `select` |
| C12 | DensitySlider | 表示密度を変えるスライダー | ブラウザ既定の `select` |
| C13 | Notice | 情報 / 警告 / エラーの 3 段階の通知 | 場所ごとにバラバラ |
| C14 | InfoPanel | 再生画面の右に置く縦長のパネル。タイトルと動画の情報を収める | 無し |
| C15 | CloseButton | パネル右上の × 。押すと一覧へ戻る | 動画の外のブラウザ既定のリンク |
| C16 | MetaList | 動画の情報（長さ・解像度・形式・映像・音声・サイズ） | 等幅フォントの 6 行の羅列 |

### 操作できるコンポーネントの状態

C8・C10・C11・C12・C15 と、「3.」で機能すると定めた C3・C6 は次の 4 状態を区別する。

| 状態 | 表現 |
| --- | --- |
| 通常 | 既定の配色 |
| hover | 背景を 1 段明るく |
| focus | アクセントカラーの輪郭。キーボード操作でも見える |
| active | 背景を 1 段暗く |

## 3. 表示のみの要素

原案の構図を再現するため配置するが、裏側の機能が無いため**押しても何も起きない**。
利用者を誤解させないよう、機能する要素より淡く表示し、件数は出さない。

| 要素 | 状態 |
| --- | --- |
| NavItem「すべての動画」 | **機能する。** 既存の一覧。件数は実数 |
| NavItem「最近追加」 | 表示のみ。押せるようにすると並べ替えの入口が C11 Select と 2 つになり、FR-013 に反する |
| NavItem「お気に入り」「未整理」 | 表示のみ |
| SidebarSection「コレクション」（旅行・ライブ・資料） | 表示のみ |
| SidebarSection「タグ」（風景・旅行・海ほか） | 表示のみ |
| Tab「動画」 | **機能する。** 既存の一覧 |
| Tab「画像」「コレクション」「タグ」 | 表示のみ |
| IconButton 設定（歯車） | 表示のみ |
| IconButton フィルタ（漏斗） | 表示のみ |
| IconButton 表示切替（グリッド / リスト） | 表示のみ |

表示のみの要素は、支援技術に対しても「利用できない」ことが伝わるようにする。

## 4. デザイントークン

| トークン | 現状 | 変更後 |
| --- | --- | --- |
| アクセントカラー | 青 | 原案のシアン系 |
| カードの角丸 | サムネイルのみ | カード全体に統一 |

文字色と背景色のコントラスト比は 4.5:1 以上（大きな文字は 3:1 以上）とする。
表示のみの要素は淡く表示するため、この基準の対象外とする。

## 5. 既存機能との対応

| コンポーネント | 接続先 |
| --- | --- |
| C3 NavItem「すべての動画」 | 既存の一覧。件数は既存の総件数 |
| C6 Tab「動画」 | 既存の一覧 |
| C10 SearchInput | 既存の題名検索 |
| C11 Select | 既存のソート（`addedDesc` / `titleAsc`） |
| C12 DensitySlider | 既存の表示密度 3 段階（`dense` / `standard` / `relaxed`） |

## User Scenarios & Testing *(mandatory)*

### User Story 1 - レイアウトが原案の 3 領域になる (Priority: P1)

一覧を開くと、左にサイドバー、上にヘッダー、残りがコンテンツという構造になっている。
グリッドをスクロールしてもサイドバーとヘッダーは動かない。

**Why this priority**: 原案の構図を決めている要素であり、ほかのコンポーネントはすべて
この中に置かれる。

**Independent Test**: 幅 1280 で一覧を開き、3 領域が指定のサイズで存在し、グリッドを
スクロールしてもサイドバーとヘッダーが動かなければ成功。

**Acceptance Scenarios**:

1. **Given** 幅 1280 の一覧、**When** 開く、**Then** 左に幅 240px のサイドバー、上に高さ
   56px のヘッダーがあり、残りがコンテンツである
2. **Given** 幅 1280 の一覧、**When** グリッドを下までスクロールする、**Then** サイドバーと
   ヘッダーは動かず、コンテンツだけがスクロールする
3. **Given** 幅 360 の一覧、**When** 開く、**Then** サイドバーは非表示になり、ロゴは
   ヘッダー内にあり、コンテンツは全幅である
4. **Given** 幅 640 の一覧、**When** 開く、**Then** サイドバーが表示される（640 が境界）
5. **Given** 再生画面、**When** 開く、**Then** サイドバーとヘッダーは表示されず、
   動画と情報パネルの 2 分割になる（US5）

---

### User Story 2 - サイドバーとヘッダーが原案どおりに並ぶ (Priority: P2)

サイドバーにロゴ、ライブラリ、コレクション、タグが原案と同じ順序で並ぶ。ヘッダーには
タブと設定ボタンがある。機能があるものは動き、無いものは淡く表示されて押せない。

**Why this priority**: 原案の情報量の多くがここにある。US1 の枠が決まってから中身を置く。

**Independent Test**: 原案と並べ、サイドバーとヘッダーの項目が同じ順序・同じ体裁で
並んでいること、および「3.」の表のとおりに機能する / しないが分かれていれば成功。

**Acceptance Scenarios**:

1. **Given** サイドバー、**When** 見る、**Then** 最上部にアイコンと製品名が 2 段で並び、
   その下にライブラリ・コレクション・タグの 3 つの区画が原案と同じ順序である
2. **Given** サイドバー、**When**「すべての動画」を見る、**Then** 実際の総件数が右端に出て、
   選択中としてアクセントカラーで示される
3. **Given** サイドバー、**When**「お気に入り」を押す、**Then** 何も起きず、押す前から
   淡く表示されていて機能しないことが分かる
5. **Given** ヘッダー、**When** 見る、**Then**「動画」タブが選択中として下線付きで表示され、
   ほかのタブと設定ボタンは淡く表示される
6. **Given** 支援技術の利用者、**When** 表示のみの要素に到達する、**Then** 利用できない
   ことが伝わる

---

### User Story 3 - 動画カードが原案の形になる (Priority: P3)

動画 1 本がカードとして表示される。サムネイルの右下に再生時間のバッジが乗り、
下にタイトル行が付く。

**Why this priority**: 面積が大きく数も多い。US1・US2 で配色が決まってから適用する。

**Independent Test**: 一覧を表示し、各カードの 3 要素（サムネイル・タイトル行・時間
バッジ）が原案どおりに配置されていれば成功。

**Acceptance Scenarios**:

1. **Given** 一覧、**When** カードを見る、**Then** サムネイルとタイトル行が 1 つの枠に
   まとまり、枠全体に角丸が付く
2. **Given** 尺が取得できている動画、**When** 一覧に並ぶ、**Then** サムネイル右下に
   再生時間のバッジが出る
3. **Given** 尺がまだ取得できていない動画、**When** 一覧に並ぶ、**Then** 再生時間の
   バッジは出ない
4. **Given** サムネイルが白い動画、**When** 時間バッジを見る、**Then** 読める
5. **Given** タイトルが長い動画、**When** 一覧に並ぶ、**Then** 2 行で切られ、末尾が省略される

---

### User Story 4 - ツールバーと通知を整える (Priority: P4)

検索欄・ソート・密度がブラウザ既定の見た目でなくなり、通知が 3 段階で統一される。

**Why this priority**: 機能が既にあるので見た目の差し替えだけで済む。数も少ない。

**Independent Test**: 3 つのコンポーネントを操作して動作が変更前と同じであること、
4 つの通知が 3 段階のいずれかの体裁になっていれば成功。

**Acceptance Scenarios**:

1. **Given** ツールバー、**When** 検索欄を見る、**Then** 左端に虫眼鏡アイコンがある
2. **Given** ツールバー、**When** ソートを見る、**Then** 原案の体裁のドロップダウンで、
   選択肢は従来どおり 2 つである
3. **Given** ツールバー、**When** 密度を変える、**Then** スライダーで 3 段階を選べ、
   結果は従来と同じである
4. **Given** 任意の設定を変えた後、**When** 再読み込みする、**Then** 従来どおり設定が残る
5. **Given** 任意の通知、**When** 表示される、**Then** 情報 / 警告 / エラーのどれかが
   色と形から判別できる
6. **Given** 再生位置がある動画、**When** 再生画面を開く、**Then** 再開の通知は情報段階で、
   動画プレーヤーを画面外へ押し出さない高さである

---

### User Story 5 - 再生画面が動画と情報パネルの 2 分割になる (Priority: P5)

再生画面は左が動画、右が情報パネルの 2 分割になる。サイドバーもヘッダーも見出し文字も
出さない。パネルにはタイトルと動画の情報が縦に並び、右上の × で一覧へ戻る。

**Why this priority**: 一覧とは別の構図を持つ画面であり、US1〜US4 で配色と部品が
確定してから作る。

**Independent Test**: 動画を 1 本開き、左に動画、右にパネルが並び、パネル内にタイトルと
情報があり、× で一覧へ戻れれば成功。

**Acceptance Scenarios**:

1. **Given** 再生画面、**When** 開く、**Then** サイドバー・ヘッダー・画面の見出し文字は
   表示されず、左に動画、右に情報パネルが並ぶ
2. **Given** 再生画面、**When** 動画を見る、**Then** パネルを除いた領域いっぱいに広がり、
   操作列はブラウザ標準のものが下端に出る
3. **Given** パネル、**When** 上から見る、**Then** 右上に × があり、その下にタイトル、
   動画の情報の順に並ぶ
4. **Given** パネル、**When** 動画の情報を見る、**Then** 等幅フォントの羅列ではなく、
   ラベルと値が読み分けられる体裁で並ぶ
5. **Given** 再生画面、**When** × を押す、**Then** 一覧へ戻り、従来どおり直前の
   スクロール位置から再開する
6. **Given** 視聴途中の動画、**When** 開く、**Then** 再開の通知はパネル内に出て、
   動画の大きさを変えない
7. **Given** 幅 640 未満の再生画面、**When** 開く、**Then** パネルは動画の下へ回り、
   横に並ばない

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 画面は「1. レイアウト構造」の 3 領域で構成すること
- **FR-002**: サイドバーとヘッダーは、コンテンツのスクロールで移動しないこと
- **FR-003**: 幅 640px 未満ではサイドバーを非表示にし、ロゴをヘッダーへ移すこと。
  ロゴはどの幅でも画面上に存在すること
- **FR-004**: 「2. 作る UI コンポーネント」の C1〜C16 をすべて実装すること
- **FR-005**: 「3. 表示のみの要素」の表のとおり、機能する要素と表示のみの要素を
  分けること。表示のみの要素は押しても何も起きず、淡く表示され、件数を出さないこと
- **FR-006**: 表示のみの要素は、支援技術に対しても利用できないことが伝わること
- **FR-007**: 操作できるコンポーネントは、通常 / hover / focus / active の 4 状態を
  視覚的に区別すること
- **FR-008**: focus はキーボード操作時にも見えること
- **FR-009**: サムネイル上のバッジは、サムネイルの明暗によらず読めること
- **FR-010**: アクセントカラーを原案のシアン系に変更すること
- **FR-011**: 文字色と背景色のコントラスト比は 4.5:1 以上（大きな文字は 3:1 以上）と
  すること。表示のみの要素は対象外とする
- **FR-012**: 動きを減らす設定（`prefers-reduced-motion`）の利用者には遷移アニメーションを
  省くこと。ただし操作結果は判別できること
- **FR-013**: 利用者が**実際に行える**操作の種類と数を変えないこと。並べ替え・密度変更・
  検索・取り込み・再生・再開はすべて従来どおり行えること。表示のみの要素は何も起こさない
  ため、操作を増やしたことにならない
- **FR-014**: サーバーの API と保存するデータを変えないこと
- **FR-015**: 再生画面はサイドバー・ヘッダー・画面の見出し文字を表示せず、左に動画、
  右に情報パネル（C14）を並べること。幅 640 未満ではパネルを動画の下へ回すこと
- **FR-016**: 動画の情報は等幅フォントの羅列であってはならず、項目名と値が読み分け
  られる体裁で示すこと
- **FR-017**: 一覧へ戻る導線はパネル右上の × とし、動画に重ねないこと
- **FR-018**: [004](../004-library-ui/spec.md) の受け入れ基準を引き続き満たすこと

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 実装した画面と原案を並べたとき、原案に写っている要素のうち本仕様の
  対象となるものが**同じ領域に・同じ順序で**存在すること。判定は要素の有無と並び順だけで
  行い、色・寸法・余白の画素単位の一致は求めない（それらはデザイントークンが決める）。
  原案に無い画面（再生画面）は対象外とする
- **SC-002**: C1〜C16 の 16 コンポーネントがすべて実装されていること
- **SC-003**: 幅 1280・768 でサイドバーとヘッダーが表示され、スクロールしても動かない。
  幅 360 でサイドバーが非表示になり、ロゴがヘッダーに残る
- **SC-004**: 本仕様の前後で、利用者が実際に行える操作の種類と数が変わらない
- **SC-005**: 一覧 → 再生 → 一覧の往復をキーボードだけで行える
- **SC-006**: 機能する要素のうち、コントラスト比が基準を下回る配色の組み合わせが
  0 件（通常の文字は 4.5:1、大きな文字は 3:1）
- **SC-007**: 幅 360 で横スクロールが発生しない
- **SC-008**: 再生画面に、ブラウザ既定の見た目のまま残っている要素が動画の操作列
  だけであること（それ以外は 0 件）
- **SC-009**: [004](../004-library-ui/spec.md) の受け入れ基準がすべて通る

## スコープ外

| 原案の要素 | 理由 |
| --- | --- |
| 画質バッジ（4K / HD） | 今回は作らない |
| 視聴位置の進捗線の作り直し | 既存のものをそのまま使う |
| カードの「その他の操作」（縦三点） | 今回は作らない |
| 複数選択のチェックボックス | 今回は作らない |
| 表示のみの要素に機能を持たせること | 裏側の機能が無い。別機能として扱う |
| 動画の操作列の作り替え | ブラウザ標準のものをそのまま使う |
| 前後の動画への移動 | 該当機能が無い。標準の操作列にも無いため、置き場所ごと発生しない |
| 視聴回数・公開日・チャンネルなどの新しい情報 | サーバーが持っていない。パネルには既存の情報だけを置く |
| パネル内のほかの動画の一覧 | 再生画面から別の動画へ移る手段が今は無く、置くと機能が 1 つ増える |
| おすすめ・関連動画 | 推薦の仕組みが無い |

## Assumptions

- 原案の暗い配色を維持する。明るいテーマへの切り替えは扱わない
- 004 で定義済みのデザイントークンを土台に、不足分を追加する。作り直しではない
- 表示のみの要素のラベルは原案のものをそのまま使う（コレクションの「旅行」「ライブ」
  「資料」、タグの「風景」「旅行」「海」など）
- 製品名は原案の「MDM / My Digital Media」ではなく本リポジトリの名前を使う。
  原案からは名前の置き方（アイコン + 2 段）だけを採る
- 再生画面の動画の情報（長さ・解像度・形式・映像・音声・サイズ）は残し、情報パネルに
  置く。画面案には写っていないが、いま表示している情報を落とすと機能が減るためである。
  内容は変えず、表示形式だけ変更する
- 対象ブラウザは現行版の主要ブラウザ（デスクトップ・モバイル）
- 動作確認用の動画はその場で生成し、実データは使わない（002・004 と同じ）
