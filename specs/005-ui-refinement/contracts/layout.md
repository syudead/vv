# 契約: 画面の骨格

**Feature**: [../spec.md](../spec.md) | **Plan**: [../plan.md](../plan.md) |
**Research**: [R-501](../research.md) / [R-502](../research.md) / [R-505](../research.md)

FR-001〜FR-003 と FR-015 は、画面が 3 領域で構成されること、サイドバーとヘッダーが
スクロールで動かないこと、640px 未満でサイドバーが消えること、再生画面が 2 分割で
あることを求めている。本書はその**寸法・境界・スクロールの持ち主**を定める。

実装はこの表を満たしていればよく、クラス名の書き方までは定めない。

## 1. 一覧画面 `/` の 3 領域

| 領域 | 位置 | 寸法 | スクロール |
| --- | --- | --- | --- |
| サイドバー（C1） | 左、画面に固定（`position: fixed`） | 幅 `--size-sidebar`（240px）、高さ 100dvh | 中身が溢れたら**独立して**流れる（`overflow-y: auto`） |
| ヘッダー（C5） | 上、画面に固定 | 高さ `--size-header`（56px）、左端はサイドバーの右（幅 640px 未満では画面の左端） | しない |
| コンテンツ | 残り全体 | 上に `--size-header`、左に `--size-sidebar` の余地を取る | **文書（ウィンドウ）が流れる** |

**スクロールの持ち主はウィンドウのままである**（[R-501](../research.md)）。コンテンツを
内側のスクロール容器に入れない。004 が積んだ一覧の復元・密度変更後の位置合わせ・
無限スクロールは、すべて `window.scrollY` とビューポート基準の `IntersectionObserver` の
上に載っており、持ち主を移すと 3 つとも書き換えになる。

### 重なりの順序

| 要素 | 前後関係 |
| --- | --- |
| サイドバー・ヘッダー | コンテンツより前 |
| ツールバー（既存の `Toolbar`、`position: sticky`） | コンテンツより前、ヘッダーより後ろ |
| 一覧の項目 | いちばん後ろ |

ツールバーは**ヘッダーの下端に粘る**（`top` がヘッダーの高さになる）。ヘッダーの裏へ
潜らせない。

### 固定領域の下端

```text
固定領域の下端 = --size-header + ツールバーの実測高
```

ツールバーは狭い画面で折り返して高くなるので、**実測**（`getBoundingClientRect()`）で
取る。004 がこの値をツールバー単体で使っていた箇所は、ヘッダーの分を足す
（[R-501](../research.md) の「1 つの例外」）。

| 使う場所 | いまの値 | 005 の値 |
| --- | --- | --- |
| 密度を変えたあとに項目を戻す位置 | ツールバーの実測高 | `--size-header` + ツールバーの実測高 |
| `topmostId` の「上端に最も近い項目」の判定 | ビューポートの上端（`bottom > 0`） | 固定領域の下端 |

足さないと、戻した項目がヘッダーの裏に 56px ぶん隠れる。

### 器の幅と列数

一覧の格子の式は変えない（[004 の contracts/design-tokens.md](../../004-library-ui/contracts/design-tokens.md) 3.）。
変わるのは**器の幅**で、幅 640 以上ではサイドバーの 240px が引かれる。コンテンツの器は
004 のまま `max-w-6xl`（1152px）+ 左右の余白 `1rem` を保つ。

```text
器の幅 = min(画面幅 - (画面幅 >= 640 なら 240), 1152) - 32
列数 n = n * min(--tile-min, (器 - 16) / 2) + (n - 1) * 16 <= 器 を満たす最大の n
```

**期待値は実装を見ずにこの式から決まる。**下の表が受け入れの基準であり、実装後の実測を
ここへ書き写すのではなく、**実測がこの表と一致することを確かめる**（[quickstart.md](../quickstart.md) S2）。

| 画面幅 | 器 | 細かい | 標準 | ゆったり | 004 では |
| --- | --- | --- | --- | --- | --- |
| 360px | 328 | 2 | 2 | 2 | 2 / 2 / 2（同じ — サイドバーが無い） |
| 768px | 496 | **3** | **2** | 2 | 4 / 3 / 2 |
| 1280px | 1008 | **6** | 5 | **3** | 7 / 5 / 4 |
| 2560px | 1120 | 7 | 5 | 4 | 7 / 5 / 4（同じ — 器が上限で頭打ち） |

この式は **004 の実測表を完全に再現する**（サイドバーの項を 0 にすると 2/2/2・4/3/2・
7/5/4・7/5/4 になる）。004 の表がブラウザでの実測値なので、式が実際の描画と一致することは
それで確かめられている。

幅 360 と 2560 で 004 と同じなのは、前者はサイドバーが出ず、後者は器が上限に達するため
である。変わるのは 768 と 1280 だけである。

## 2. 幅の境界（FR-003）

境界は 1 つだけである。**Tailwind の `sm:`**（`@media (width >= 40rem)` = 640px）を
そのまま使い、独自のブレークポイントを定義しない（[R-502](../research.md)）。

| 画面幅 | サイドバー | ロゴの置き場 | コンテンツの左余地 |
| --- | --- | --- | --- |
| 640px 以上 | 表示する | サイドバーの最上部 | `--size-sidebar` |
| 640px 未満 | **表示しない** | ヘッダーの左端 | 0（全幅） |

境界の値そのものが受け入れ条件である（spec US1 の 4: 幅 640 でサイドバーが表示される）。
`min-width` の向きなので、**640px ちょうどは「表示する」側**である。

## 3. ロゴの二重配置（FR-003）

ロゴ（C2）は DOM の 2 か所（サイドバーの中とヘッダーの中）に置き、使わない側を
**`display: none` で消す**。

| 事項 | 規則 |
| --- | --- |
| 消し方 | `display: none`（Tailwind の `hidden` / `sm:hidden` / `sm:block`）。`visibility` や `opacity` は使わない |
| 理由 | `display: none` は支援技術からも消えるので、製品名が 2 回読まれない |
| 見出し | ロゴが `h1` を持つ（[R-508](../research.md)）。一覧に見出し文字は置かない |
| 対話性 | **リンクにしない。** spec 2. の 4 状態の一覧に C2 は無く、リンクにすると `Tab` の停止位置と操作が 1 つ増えて FR-013 に反する（[contracts/components.md](./components.md) 1.） |

幅の監視（`matchMedia`）を JavaScript で行わない。分岐は CSS だけで閉じる。

## 4. 再生画面 `/videos/:id` の 2 分割（FR-015）

再生画面に**サイドバーもヘッダーも被せない**。骨格（`AppShell`）を通さず、
`App.tsx` の経路ごとに器を分ける（[R-505](../research.md)）。

| 画面幅 | 並び |
| --- | --- |
| 640px 以上 | 左に映像、右に情報パネル（C14）。パネルの幅は `minmax(18rem, 24rem)` の範囲 |
| 640px 未満 | 映像の下にパネル（縦に畳む） |

| 事項 | 規則 |
| --- | --- |
| 映像 | パネルを除いた領域いっぱい。比率を保つ（高さを決め打たない）。操作列はブラウザ標準（FR-015 / spec US5-2） |
| 見出し文字 | 画面の見出しは出さない。題名はパネルの中にある |
| 一覧へ戻る | パネル右上の ×（C15）だけ。**映像に重ねない**（FR-017） |
| パネルの中身の順序 | ×（右上）→ 題名 → 知らせ（再生できない形式・再生の失敗）→ 動画の情報（C16） |
| 再開 | 視聴途中の動画は中断位置から始まり、再開したことを示す通知は出さない（spec US5-6 / US4-6） |

境界を一覧と同じ 640px にするのは、狭くしていく途中で構図が変わる点を 2 つにしない
ためである。

| 一覧の復元・無限スクロールが変わっていない | [S1](../quickstart.md)（機械。004 の既存テスト）+ [S8](../quickstart.md) |

**画面幅による出し分けは jsdom では確かめられない**（CSS メディアクエリが効かない）。
機械の検査を用意しないのは手抜きではなく、擬似的に確かめると「テストは通るが画面は
壊れている」状態を招くからである（[R-511](../research.md)）。
