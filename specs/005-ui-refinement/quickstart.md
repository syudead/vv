# Quickstart / 受け入れ検証: 原案デザインに合わせた UI の再構築

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Date**: 2026-09-15

この機能が「できた」と言える状態を、実行して確かめる手順。各シナリオは
[spec.md](./spec.md) の成功基準に対応する。実装の詳細は書かない（`tasks.md` と実装で
扱う）。

本機能は**構図の再現**なので、機械で確かめられるもの（S1）と、人が原案と並べて確かめる
もの（S2〜S7）が混ざる。どちらに属するかを各シナリオの見出しに示す。
機械の検査を増やさない理由は [R-511](./research.md) にある。

### 004 の S4 から引き継ぐ確認（一覧側）

[004 の S4](../004-library-ui/quickstart.md) が一覧について見ていたものを、ここで引き取る。
**幅 360・768・1280・2560 の 4 つ**で見る。

| 事項 | 期待 | 004 から |
| --- | --- | --- |
| 横方向のスクロールバー | どの幅でも出ない（SC-007） | 変わらない |
| 操作要素の重なり | 帯の中が重ならない（狭いときは折り返す）。サイドバー・ヘッダーとも重ならない | 見る対象が増える |
| 押せる要素の当たり判定 | 44px 四方以上（開発者ツールで寸法を見る） | 変わらない |
| 一覧の列数 | 下の表のとおり。幅 360 でも 1 列にならない | **期待値が変わる** |

**列数の期待値は 004 の表をそのまま使えない。**格子の式（`minmax(min(--tile-min,
(100% - gap) / 2), 1fr)`）は変えないが、器が変わる — 幅 640 以上ではコンテンツ領域から
サイドバーの 240px が引かれるためである。

期待値は[契約](./contracts/layout.md)が式から先に決めてある。**実測をここへ書き写すのでは
なく、実測がこの表と一致することを確かめる。**

| 画面幅 | 細かい | 標準 | ゆったり |
| --- | --- | --- | --- |
| 360px | 2 | 2 | 2 |
| 768px | 3 | 2 | 2 |
| 1280px | 6 | 5 | 3 |
| 2560px | 7 | 5 | 4 |

一致したら、同じ値で
[004 の contracts/design-tokens.md](../004-library-ui/contracts/design-tokens.md) 3. の表を
更新する。**食い違ったら実装か契約のどちらかが誤っている**ので、表を書き換えて済ませない
こと — 導出の前提（サイドバー 240px、器の上限 1152px、余白 16px、gap 16px）のどれが
実装と違うかを突き止める。

## S3: サイドバーとヘッダー（人）

原案と並べて見る。

1. サイドバーの最上部に、アイコンと製品名が**2 段**で並ぶ（製品名は本リポジトリの名前。
   原案の「MDM」ではない。spec の Assumptions）
2. その下に**ライブラリ → コレクション → タグ**の 3 区画が、原案と同じ順序で並ぶ
3. 「すべての動画」に**実際の総件数**が右端に出て、選択中としてアクセントカラーで示される
4. 「最近追加」「お気に入り」「未整理」、コレクションの 3 つ、タグの 3 つは**淡く**表示され、
   **件数が出ていない**
5. それらを押しても**何も起きない**（画面が変わらない・URL が変わらない）
6. ヘッダーに「動画 / 画像 / コレクション / タグ」のタブが並び、「動画」だけが下線付きで
   選択中、ほかは淡い
7. ヘッダー右端に歯車（設定）があり、淡い
8. 機能する要素（「すべての動画」・「動画」タブ）に hover すると背景が 1 段明るくなり、
   淡い要素は hover しても**変化しない**。ロゴは見出しであって押せない（`Tab` でも止まらない）

**期待**: 1〜8 がすべて成立する。**SC-001 の判定はここで行う** — 原案に写っている要素が
同じ領域に同じ順序で存在すればよく、色・寸法・余白の画素単位の一致は求めない。

## S4: 動画カード（人）

1. サムネイルとタイトル行が**1 つの枠**にまとまり、枠全体に角丸が付く（US3-1）
2. 尺が取得できている動画は、サムネイル**右下**に時間バッジが出る（US3-2）
3. 尺がまだ取得できていない動画には、時間バッジが**出ない**（US3-3）
4. サムネイルが明るい動画でも、バッジの文字が読める（US3-4 / FR-009）
5. 題名が長い動画は 2 行で切られ、末尾が省略される（US3-5）

**期待**: 1〜5 がすべて成立する。3 は取り込み直後（サムネイル生成前）に一覧を開くと見られる。

## S5: ツールバーと通知（人）

1. 検索欄の左端に虫眼鏡アイコンがある（US4-1）
2. ソートが原案の体裁になり、**選択肢は従来どおり 2 つ**（追加が新しい順 / 題名順。US4-2）
3. 密度が**スライダー**になり、3 段階を選べる。選んだ結果の列の見え方は従来と同じ（US4-3）
4. ツールバーの右に件数（「N 本」／「「語」に一致 N 本」）が出る
5. 漏斗（フィルタ）と表示切替（グリッド / リスト）が淡く表示され、押しても何も起きない
6. 検索・ソート・密度を変えてから**再読み込み**すると、従来どおり設定が残る（US4-4）
7. 通知が 3 段階（情報 / 警告 / エラー）のどれかとして、**色と形から**判別できる（US4-5）
8. **利用者が実際に行える操作を数える** — 検索・並べ替え・密度・取り込み・一覧を開く・
   動画を開く・再生・再開 / 先頭から見直す・一覧へ戻る。004 の時点と**同じ数**である
   （SC-004 / FR-013）

**期待**: 1〜8 がすべて成立する。7 は、蔵書が空のとき（情報）、再生できない形式の動画
（警告）、サーバーを落として一覧を再読み込みしたとき（エラー）で見られる。

## S6: 再生画面（人）

動画を 1 本開く。

1. サイドバー・ヘッダー・画面の見出し文字が**表示されず**、左に映像、右に情報パネルが
   並ぶ（US5-1 / FR-015）
2. 映像はパネルを除いた領域いっぱいに広がり、操作列は**ブラウザ標準**のものが下端に出る
   （US5-2）
3. パネルの右上に × があり、その下に題名、動画の情報の順に並ぶ（US5-3）
4. 動画の情報が**等幅フォントの羅列ではなく**、ラベルと値が読み分けられる（US5-4 / FR-016）
5. × を押すと一覧へ戻り、**直前のスクロール位置から再開する**（US5-5）
6. 視聴途中の動画を開くと、再開の知らせが**パネルの中**に出て、映像の大きさが変わらない
   （US5-6）
7. 幅 640 未満では、パネルが映像の**下**へ回る（US5-7）
8. **ブラウザ既定の見た目のまま残っている要素が、動画の操作列だけである**（SC-008）

**期待**: 1〜8 がすべて成立する。5 は、一覧を数画面ぶん送ってから動画を開き、× で戻って
確かめる。

### 004 の S4 から引き継ぐ確認（再生画面側）

[004 の S4](../004-library-ui/quickstart.md) が再生画面について見ていたものを、ここで
引き取る。**幅 360・768・1280・2560 の 4 つ**で動画を 1 本開く。

| 事項 | 期待 | 004 から |
| --- | --- | --- |
| 横方向のスクロールバー | どの幅でも出ない | 変わらない |
| 映像 | 幅に収まり、比率が保たれる | 変わらない |
| 押せる要素の当たり判定 | ×（C15）と知らせの中のボタンが 44px 四方以上 | 変わらない |
| 操作要素の重なり | パネルと映像が重ならない。× が映像に重ならない（FR-017） | 見る対象が増える |
| 情報の置き場 | **幅 640 以上は映像の右、640 未満は映像の下** | **期待値が変わる** |

最後の 1 行が 004 と逆になっているのが要点である。004 の S4 は「情報は映像の下に縦に
並ぶ」を全幅で期待していたが、005 の FR-015 は 640px 以上で右へ置くことを求める。
**004 の S4 をそのまま実行すると、正しい 005 の実装が不合格になる。**だから S4 は
[S8](#s8-004-の受け入れ基準機械--人) で「そのまま実行する」対象から外してある。

## S7: キーボードと読み上げ（人）

1. 一覧で `Tab` を押していく。到達順が **「すべての動画」→ 「動画」タブ →
   検索 → 並び順 → 密度 → 取り込む → 一覧の項目** である（[R-509](./research.md)）
2. **淡い要素（表示のみ）とロゴに一度も止まらない**（FR-005 / FR-013 /
   [R-503](./research.md) / [R-509](./research.md)）
3. どの要素でも、狙いを合わせた印（輪郭）が見える（FR-008）
4. 密度のスライダーに止めて左右の矢印キーを押すと、3 段階が動く
5. 項目で `Enter` を押すと再生画面へ移り、最初の `Tab` の到達先が × である
6. `Enter` で一覧へ戻る。**マウス操作 0 回で往復できた**（SC-005）
7. 読み上げ（OS 標準のもので可）で一覧をたどると、淡い要素が「お気に入り（未実装）」の
   ように読まれ、**利用できないことが分かる**（US2-5 / FR-006）
8. 製品名が**1 回だけ**読まれる（ロゴは DOM に 2 つあるが、片方は `display: none`。
   [R-502](./research.md)）
9. OS の「動きを減らす」設定を入れると、hover の遷移が無くなる。ただし**色の変化は残り**、
   操作結果は判別できる（FR-012）

**期待**: 1〜9 がすべて成立する。

## S8: 004 の受け入れ基準（機械 + 人）

FR-018 / SC-009 の確認である。

```bash
make check
```

続けて [004 の quickstart](../004-library-ui/quickstart.md) の S3〜S9 を実行する。手順も
期待値も 004 のものを使い、ここには写さない（写すと 2 か所が食い違う）。特に
**本機能が触っていないことを確かめたい**のは次の 4 つである。

| 事項 | 004 の対応シナリオ |
| --- | --- |
| 密度を変えたときに見ていた項目が画面上端に残る — **ヘッダーの裏に隠れていないこと**を見る（[contracts/layout.md](./contracts/layout.md) 1.「固定領域の下端」） | S6-2 |
| 表示設定が再読み込み・往復で保たれ、壊れた値でも既定で出る | S6 |
| 無限スクロールの継ぎ目（1000 件まで読んでも反応が鈍らない） | S7 |
| 一覧へ戻ったときの位置・検索語・並び順の復元、再生位置の記録と再開 | S9（002 の S1〜S10 を通す） |

**004 の S4（画面幅）だけは、そのまま実行しない。**期待値のうち 2 つが本機能で意図的に
変わるからである。

| S4 の期待 | 005 での扱い |
| --- | --- |
| 「情報は映像の下に縦に並ぶ」 | **変わる。** 640px 以上は映像の右（FR-015）。そのまま実行すると正しい実装が不合格になる |
| 列数が 004 の表の目安どおり | **変わる。** 器からサイドバーの 240px が引かれる |
| 横スクロールが出ない | 変わらない |
| 操作要素が重ならない | 変わらない（見る対象は増える） |
| 押せる要素が 44px 四方以上 | 変わらない |
| 映像が幅に収まり比率が保たれる | 変わらない |

S4 の中身は**丸ごと引き取ってある** — 一覧側は [S2](#s2-レイアウトと画面幅人) の
「004 の S4 から引き継ぐ確認」、再生画面側は [S6](#s6-再生画面人) の同名の節で、どちらも
幅 360・768・1280・2560 の 4 つを見る。**S2 と S6 を実行すれば S4 の穴は埋まる。**

**S4 以外（S3・S5〜S9）はそのまま実行する。**手順も期待値も 004 のものを使い、ここには
写さない（写すと 2 か所が食い違う）。004 の S3 に含まれる聞き取り（初見の人が「探す・
並べ替える・取り込む」を 10 秒以内に指せるか）も**再実施する** — 帯の中身は変わって
いないが、帯そのものがヘッダーの下へ移り、周りに淡い要素が 15 個増えるためである。

**期待**: 004 の S3・S5〜S9 がすべて成功する。見た目は変わっているが、**振る舞いは
1 つも変わっていない**。
