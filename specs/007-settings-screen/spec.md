# Feature Specification: メディアフォルダ設定画面

**Feature Branch**: `codex/feature-settings-screen`

**Created**: 2026-09-20

**Status**: Draft

**Parent Issue**: #62

**Input**: User description: "設定画面を作る"

## Original Request

- **2026-09-20 / User**: 「設定画面を作る」
- **2026-09-20 / User clarification**: 「メディアフォルダ　だけ」
- **2026-09-20 / User clarification**: 「起動時の自動取り込みは恒久的に不要」

本仕様で設定画面に置く設定項目は、サーバー上の動画を探す**メディアフォルダ1項目だけ**
である。起動時の自動取り込みは設定項目にせず、機能そのものを廃止する。取り込みは既存の
手動操作からのみ開始する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - メディアフォルダを確認・変更する (Priority: P1)

セルフホスト環境を管理する利用者は、サイドバー末尾の「設定」から専用画面を開き、現在
動画を探しているサーバー上のフォルダを確認できる。別のフォルダへ切り替えるときは、絶対
パスを入力して保存し、次回以降もその場所を使える。

**Why this priority**: メディアフォルダは設定画面に置く唯一の項目であり、現在値の確認、
妥当性の確認、保存がこの機能の中心価値である。

**Independent Test**: 読み取り可能な別の絶対パスを保存し、画面の再読み込みとアプリケーション
の再起動後にも同じ値が表示されれば、このストーリーだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** ライブラリ画面を表示している、**When** サイドバーの「設定」を選ぶ、**Then**
   設定画面へ移動し、「設定」が現在位置として示される
2. **Given** 設定画面を開いている、**When** メディアフォルダ欄を見る、**Then** 現在有効な
   サーバー上の絶対パスと、その配下を再帰的に取り込むことが分かる
3. **Given** 存在し読み取り可能なフォルダの絶対パスを入力した、**When** 保存する、**Then**
   その値が新しいメディアフォルダとして保存され、反映結果が画面上で分かる
4. **Given** メディアフォルダを保存済みである、**When** 画面を再読み込みする、または
   アプリケーションを再起動する、**Then** 保存したフォルダが現在値として維持される
5. **Given** 相対パス、存在しない場所、ファイル、または読み取れないフォルダを入力した、
   **When** 保存する、**Then** 保存されず、入力内容を失わないまま理由と直し方が示される

---

### User Story 2 - 新しいフォルダを手動で取り込む (Priority: P2)

利用者はメディアフォルダを変更したあと、自分の判断で既存の「取り込み」操作を実行する。
保存しただけでは取り込みは始まらず、アプリケーションを起動しただけでも始まらない。

**Why this priority**: 利用者は大量のファイル走査が始まる時期を自分で決められる必要がある。
「起動時の自動取り込みは恒久的に不要」という要求を、単なる既定値ではなく製品挙動として
保証する。

**Independent Test**: メディアフォルダを変更しても取り込みが始まらないこと、その後に既存の
取り込み操作を行うと新しい場所だけがライブラリへ反映されることを確認できる。

**Acceptance Scenarios**:

1. **Given** メディアフォルダの変更を保存した、**When** 保存が完了する、**Then** 取り込みは
   自動開始されず、新しい内容を反映するには手動取り込みが必要だと示される
2. **Given** 新しいメディアフォルダを保存済みである、**When** 利用者が取り込みを開始する、
   **Then** 新しいフォルダ配下だけが探索され、完了後の一覧がその内容に一致する
3. **Given** 以前のフォルダから取り込んだ動画に再生位置がある、**When** 新しいフォルダへ
   切り替えて手動取り込みする、**Then** 一覧の索引は新しい場所へ更新されるが、内容で同じ
   動画が再び見つかった場合は再生位置を失わない
4. **Given** アプリケーションを起動する、**When** 待ち受けを開始する、**Then**
   メディアフォルダの内容にかかわらず取り込みを自動開始しない
5. **Given** 旧 `MDM_SCAN_ON_START` が指定された環境で起動する、**When** 起動が完了する、
   **Then** その値にかかわらず取り込みを自動開始しない

---

### User Story 3 - 迷わず安全に設定する (Priority: P3)

利用者は、デスクトップ、モバイル、キーボード、支援技術のいずれでも、メディアフォルダの
意味、現在値、編集欄、保存操作の関係を見失わずに操作できる。

**Why this priority**: サーバー上の場所を誤って指定するとライブラリ全体の見え方が変わるため、
1項目だけの画面でも影響と操作順を明確にする必要がある。

**Independent Test**: 幅 360px と 1280px、およびキーボードだけで、現在値の確認から保存結果の
確認までを横スクロールや要素の重なりなしに完了できれば独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 幅 360px の設定画面、**When** 長いパスを表示・編集する、**Then** 画面全体の
   横スクロールや文字・操作部品の重なりが起きない
2. **Given** キーボードだけを使う利用者、**When** 入力欄と保存操作をたどる、**Then**
   フォーカス位置が常に見え、Enterキーを含む標準的な操作で保存できる
3. **Given** 支援技術を使う利用者、**When** 設定画面を読む、**Then** 画面見出し、説明、
   入力欄、検証結果、保存結果が意味の通る順序で伝わる

### Edge Cases

- 空文字、空白だけ、相対パス、通常ファイルへのパスは保存しない。
- 存在するが読み取れないフォルダは保存しない。
- 空のフォルダは有効なメディアフォルダとして保存できる。
- Windows のドライブ名を含むパスと、Linuxコンテナ内の絶対パスを、それぞれ実行環境に
  合った絶対パスとして扱う。
- 長いパスや日本語を含むパスを省略表示しても、編集欄では値全体を確認・変更できる。
- 保存の直前にフォルダが失われた場合は、以前の有効な設定を維持する。
- 取り込み中はメディアフォルダを変更できない。進行中の取り込みを別の場所へ途中から
  切り替えない。
- 複数の画面から同時に変更された場合、古い現在値を基にした保存で新しい設定を黙って
  上書きしない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、サイドバー末尾の「設定」を設定画面への操作可能な入口に
  置き換えなければならない
- **FR-002**: 設定画面は、設定項目としてメディアフォルダだけを表示しなければならない
- **FR-003**: システムは、現在有効なメディアフォルダの絶対パスを表示しなければならない
- **FR-004**: 利用者は、サーバー上の別の絶対パスをメディアフォルダとして入力し、保存できなければ
  ならない
- **FR-005**: システムは、入力された場所が絶対パスであり、存在するディレクトリであり、
  読み取り可能であることを保存前に検証しなければならない
- **FR-006**: 検証に失敗した場合、システムは現在有効な設定を変更せず、入力値を保持したまま、
  失敗理由と修正方法を示さなければならない
- **FR-007**: 保存したメディアフォルダは、画面の再読み込みおよびアプリケーションの再起動を
  越えて維持されなければならない
- **FR-008**: メディアフォルダの保存は取り込みを開始してはならず、保存完了後に既存の手動
  取り込みが必要であることを示さなければならない
- **FR-009**: 保存後に利用者が手動取り込みを開始した場合、システムは保存したメディアフォルダ
  配下だけを再帰的に探索しなければならない
- **FR-010**: 取り込み実行中はメディアフォルダの保存操作を利用不能にし、その理由を
  利用者へ示さなければならない
- **FR-011**: システムはアプリケーション起動時に取り込みを自動開始してはならない
- **FR-012**: `MDM_SCAN_ON_START` は廃止された設定として扱い、値の有無にかかわらず
  起動時の取り込みを開始してはならない
- **FR-013**: 設定画面に、データフォルダ、待ち受けアドレス、ログレベル、起動時の自動取り込み、
  またはその他の設定項目を表示してはならない
- **FR-014**: 初めて画面から保存する前の現在値は、従来のメディアフォルダ起動設定を
  引き継がなければならない
- **FR-015**: 設定画面は既存のアプリケーションシェル、ダーク配色、タイポグラフィ、操作状態の
  規則に従わなければならない
- **FR-016**: 画面の視覚的階層は、画面見出し、設定の説明、現在値・入力欄、保存操作、補足情報の
  順とし、補足情報を主要操作より強く見せてはならない
- **FR-017**: 1項目を確認・編集するための密度を保ち、ページ区画や設定行を装飾的なカードとして
  重ねてはならない
- **FR-018**: 画面外周、説明と入力欄、入力欄と検証結果、区切りと保存操作の余白に、既存画面と
  一貫したリズムを持たせなければならない
- **FR-019**: 見出し、項目名、説明、パス、検証結果には既存画面の文字体系を使い、長いパスでも
  項目名や操作を押し出してはならない
- **FR-020**: 保存を唯一の主要操作として示し、現在値の表示、補足説明、ライブラリへ戻る操作より
  明確に優先しなければならない
- **FR-021**: 幅 360px からデスクトップ幅まで、横スクロールや内容の重なりなしに確認・操作
  できなければならない
- **FR-022**: 入力、保存、エラー確認、完了確認の全工程をキーボードと支援技術から利用できなければ
  ならない

### Key Entities

- **メディアフォルダ設定**: サーバー上で動画を探す1つのルートディレクトリ。現在値、更新を
  競合させないための版、最終更新時刻を持つ。
- **メディアフォルダ候補**: 利用者が保存前に入力したパス。絶対パス、存在、ディレクトリ種別、
  読み取り可否の検証結果を持つが、検証に通るまでは現在値にならない。
- **取り込み**: 利用者が明示的に開始する、現在のメディアフォルダとライブラリを一致させる処理。
  設定保存やアプリケーション起動から暗黙には開始されない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初めて設定画面を使う利用者の90%以上が、説明を読まずに現在のメディアフォルダを
  確認し、1分以内に有効な別フォルダを保存できる
  （Original Request の「メディアフォルダだけを設定する画面」を満たす）
- **SC-002**: 有効なフォルダの保存成功率を100%とし、無効なパスが現在設定へ反映される件数を
  0件にする（Original Request の「メディアフォルダ」を安全に設定できることを満たす）
- **SC-003**: 保存したメディアフォルダが画面再読み込みとアプリケーション再起動後に維持される
  割合を100%とする（Original Request の「設定」として恒久的に使えることを満たす）
- **SC-004**: 設定保存時およびアプリケーション起動時に自動開始される取り込みを0件にする
  （Original Request の「起動時の自動取り込みは恒久的に不要」を満たす）
- **SC-005**: 新しいフォルダを保存して手動取り込みを完了したあと、一覧に残る旧フォルダだけの
  動画を0件、新フォルダ内の取り込み可能な動画の欠落を0件にする
  （Original Request の「メディアフォルダ」を実際のライブラリへ反映できることを満たす）
- **SC-006**: 幅360px、768px、1280pxのすべてで、横スクロール、文字の欠落、操作部品の
  重なりを0件にする（Original Request の「設定画面」を各画面幅で利用できることを満たす）
- **SC-007**: 現在値の確認から保存結果の確認までをキーボードだけで完了でき、見えないフォーカスと
  名前のない操作を0件にする（Original Request の「設定画面」を入力方法によらず利用できる
  ことを満たす）
- **SC-008**: 視覚レビューで、設定の説明と値の階層、1項目に適した情報密度、一貫した余白、
  既存画面と揃った文字体系、保存操作の優先順位の5観点すべてを満たす
  （Original Request の「設定画面」を既存製品に属する実用品として満たす）

## Superseded Behavior

本仕様は、次の既存仕様のうち起動時取り込みに関する部分を置き換える。

- `specs/002-core-video-library/spec.md` の「取り込みの起点は、アプリケーションの起動時と
  利用者の指示とする」という仮定は、「利用者の明示的な指示だけ」に変更する。
- `specs/002-core-video-library/contracts/configuration.md` の `MDM_SCAN_ON_START` は廃止する。
- `specs/002-core-video-library/research.md` の R-108 にある起動直後の自動実行は採用を終了する。

手動取り込み、取り込み進捗、移動・改名の同一性、失われた動画の除去、再生位置の保護に
関する既存契約は維持する。

## Assumptions

- 対象利用者は、現在の単一利用者・セルフホスト構成を管理する本人である。
- メディアフォルダはブラウザを開いている端末ではなく、サーバーから見える場所を表す。
- メディアフォルダは1つだけとし、複数ルートの登録は対象外である。
- フォルダ選択ダイアログ、動画のアップロード、サーバー上のフォルダ作成は対象外である。
- メディアフォルダの変更前に取り込んだ索引は、次の手動取り込みが完了するまで残る。保存完了時に
  この状態と手動取り込みの必要性を利用者へ示す。
- 保存後は新しいフォルダを現在値として扱うため、旧フォルダだけに存在する動画は次の手動取り込み
  まで一覧に残っていても再生できない場合がある。
- 再生位置と視聴済み状態は内容由来の識別子に結び付いており、フォルダ変更や手動取り込みだけでは
  削除しない。
- データフォルダ、待ち受けアドレス、ログレベル、サムネイル設定、除外規則、ジョブ並列数、
  テーマ、一覧の表示設定は本機能の対象外である。
- 認証と複数利用者ごとの権限管理は本機能の対象外である。
