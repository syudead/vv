## Settled Without Asking

- 設定画面は既存のサイドバーにある「設定」入口を実画面へ置き換え、既存のAppShell、responsive
  sidebar、配色、文字体系、密度を維持する。出所は
  [ARCHITECTURE.md](../../ARCHITECTURE.md) のWeb layerと
  [Sidebar.tsx](../../web/src/shell/Sidebar.tsx) の既存settings entryである。
- メディアフォルダはブラウザ端末のlocal folderやupload先ではなく、アプリケーションserverから
  見える既存directoryを表す。出所は
  [001 configuration contract](../001-initial-setup/contracts/configuration.md) のserver-side media/data
  configurationと、本featureのself-hosted deployment境界である。
- folder操作から自動取り込みを開始せず、既存の手動取り込み、進捗表示、部分失敗後の継続を再利用する。
  出所は [002 core video library](../002-core-video-library/spec.md) のUS1、FR-006〜FR-008である。
- folder変更時に削除できるのは再構築可能な索引・解析データだけであり、再生位置と視聴済み状態は
  維持する。出所は [002 core video library](../002-core-video-library/spec.md) のFR-025・FR-026である。
- 同一contentを複数pathで発見しても論理videoは重複させず、各folder内の実在場所を別に保持する。
  出所は [002 core video library](../002-core-video-library/spec.md) のFR-004と、要求者が指定した
  複数folder・変更対象だけへ作用する規則の組み合わせである。
- 認証を本featureへ追加せず、単一利用者が家庭内のtrusted networkで運用する境界を維持する。
  出所は [002 core video library](../002-core-video-library/spec.md) のAssumptionsである。

本仕様の対象は、アプリケーションの設定を確認・変更する**設定画面**である。初回に置く
設定項目は、サーバー上の動画を探す**メディアフォルダ1項目だけ**とし、その項目へ複数の
ディレクトリを登録できるようにする。起動時の自動
取り込みは設定項目にせず、機能そのものを廃止する。取り込みは既存の手動操作からのみ
開始する。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 設定画面を開く (Priority: P1)

利用者は、サイドバー末尾の「設定」からアプリケーションの設定画面を開ける。画面には
「設定」という見出しがあり、設定項目としてメディアフォルダだけが並ぶ。

**Why this priority**: ユーザー要求の主語は設定画面であり、メディアフォルダはその画面に
置く最初の設定項目である。専用画面として到達でき、現在位置と設定項目を理解できることが
ほかの操作の前提になる。

**Independent Test**: デスクトップとモバイルの両方でサイドバーから設定画面を開き、画面
見出しと1件の設定項目を確認できれば、このストーリーだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** ライブラリ画面を表示している、**When** サイドバーの「設定」を選ぶ、**Then**
   設定画面へ移動し、「設定」が現在位置として示される
2. **Given** モバイル幅でサイドバーを開いている、**When**「設定」を選ぶ、**Then**
   ドロワーが閉じて設定画面へ移動する
3. **Given** 設定画面を開いている、**When** 設定項目を確認する、**Then** メディアフォルダ
   だけが表示され、ほかの設定項目は表示されない

---

### User Story 2 - メディアフォルダを確認・変更する (Priority: P2)

設定画面を開いたセルフホスト環境の管理者は、現在動画を探しているサーバー上の複数フォルダを
確認できる。フォルダを追加・削除するときは、サーバー上のディレクトリを画面内で辿って選択し、
1件ずつ登録・変更・削除する。絶対パスを文字列で入力する必要はなく、一覧全体を編集して
一括保存する操作もない。

**Why this priority**: メディアフォルダは設定画面に置く唯一の項目であり、現在値の確認、
妥当性の確認、1件単位の登録・変更・削除がこの機能の中心価値である。

**Independent Test**: フォルダ選択UIで複数の読み取り可能なディレクトリを1件ずつ登録し、画面の
再読み込みとアプリケーションの再起動後にも同じ一覧が表示されれば、このストーリーだけで
独立して検証できる。

**Acceptance Scenarios**:

1. **Given** メディアフォルダが0件である、**When** 設定画面を開く、**Then** 未設定である
   ことと、フォルダの選択が必要であることが分かる
2. **Given** 設定画面を開いている、**When**「フォルダを選択」を実行する、**Then** サーバー上の
   読み取り可能なディレクトリを階層移動し、現在表示しているディレクトリを候補にできる
3. **Given** 既存のメディアフォルダと取り込み済み動画がある、**When** 別のフォルダを追加する、
   **Then** 新しいフォルダ1件だけが登録され、既存フォルダとそのライブラリDBデータは変わらない
4. **Given** メディアフォルダを複数登録済みである、**When** 画面を再読み込みする、または
   アプリケーションを再起動する、**Then** 登録した一覧が現在値として維持される
5. **Given** 既存フォルダに取り込み済み動画がある、**When** その1件を別のフォルダへ変更する、
   **Then** 対象フォルダ内の実在場所だけが削除され、別の登録済みフォルダにも同じ内容の動画が
   ある場合は、その動画と別フォルダ側の実在場所が維持される
6. **Given** 表示中または選択したフォルダが消失・読取不能になった、**When** 登録または変更を
   実行する、**Then** 永続状態は変更されず、選択し直すための理由が示される

---

### User Story 3 - 新しいフォルダを手動で取り込む (Priority: P3)

利用者はメディアフォルダを追加・変更・削除したあと、自分の判断で既存の「取り込み」操作を
実行する。設定操作だけでは取り込みは始まらず、アプリケーションを起動しただけでも始まらない。

**Why this priority**: 利用者は大量のファイル走査が始まる時期を自分で決められる必要がある。
「起動時の自動取り込みは恒久的に不要」という要求を、単なる既定値ではなく製品挙動として
保証する。

**Independent Test**: メディアフォルダを追加しても既存ライブラリが維持され、既存フォルダを
変更・削除した場合だけ対象データが消えること、その後の手動取り込みで現在の全フォルダが
反映されることを確認できる。

**Acceptance Scenarios**:

1. **Given** メディアフォルダを追加した、**When** 登録が完了する、**Then** 既存の動画と関連DB
   データは維持され、取り込みは自動開始されない
2. **Given** 既存メディアフォルダを変更または削除した、**When** 操作が完了する、**Then** その
   フォルダ由来の実在場所と、ほかに実在場所がない動画の再構築可能データだけが削除され、
   取り込みは自動開始されない
3. **Given** 1件以上のメディアフォルダを登録済みである、**When** 利用者が取り込みを開始する、
   **Then** 登録済みの全フォルダ配下が探索され、完了後の一覧がその集合と一致する
4. **Given** 走査中に一部のdirectoryやfileが消失・読取不能になった、**When** 探索を続ける、
   **Then** 対象の失敗を記録して残りを処理し、プロセスを停止しない
5. **Given** アプリケーションを起動する、**When** 待ち受けを開始する、**Then**
   メディアフォルダの内容にかかわらず取り込みを自動開始しない
6. **Given** 旧 `MDM_SCAN_ON_START` が指定された環境で起動する、**When** 起動が完了する、
   **Then** その値にかかわらず取り込みを自動開始しない
7. **Given** 旧 `MDM_MEDIA_DIR` が指定された環境で初回起動する、**When** 設定画面を開く、
   **Then** その値を引き継がず、メディアフォルダは未設定として表示される

---

### User Story 4 - 迷わず安全に設定する (Priority: P4)

利用者は、デスクトップ、モバイル、キーボード、支援技術のいずれでも、メディアフォルダの
意味、現在値、フォルダ選択、各フォルダ操作の関係を見失わずに操作できる。

**Why this priority**: サーバー上の場所を誤って指定するとライブラリ全体の見え方が変わるため、
1項目だけの画面でも影響と操作順を明確にする必要がある。

**Independent Test**: 幅 360px と 1280px、およびキーボードだけで、現在値の確認から操作結果の
確認までを横スクロールや要素の重なりなしに完了できれば独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 幅 360px の設定画面、**When** 長いパスを表示してフォルダを選択する、**Then** 画面全体の
   横スクロールや文字・操作部品の重なりが起きない
2. **Given** キーボードだけを使う利用者、**When** フォルダ選択UIと登録・変更・削除操作をたどる、
   **Then** フォーカス位置が常に見え、各操作を完了できる
3. **Given** 支援技術を使う利用者、**When** 設定画面を読む、**Then** 画面見出し、説明、
   現在値、フォルダ選択、検証結果、操作結果が意味の通る順序で伝わる

### UI Quality Intent

- **改善を感じる人**: 環境変数と再起動に頼っていたセルフホスト環境の管理者が、現在の探索場所と
  1件の操作結果を画面内で把握できるようになったと感じること。
- **現状の問題**: サイドバーの設定入口が実際の管理画面につながらず、メディアフォルダの現在値、
  変更方法、変更範囲を画面から確認できないこと。
- **維持する特徴**: 既存AppShell、暗色背景、抑制した境界線、コンパクトな文字サイズと行高、
  明るい文字による階層、機能中心で装飾を増やさない密度を維持すること。
- **視覚的階層**: 画面見出し、設定項目名、登録済みpath、対象行の操作、補足説明の順で強くする。
- **情報密度**: 複数pathを比較できる行密度を保ち、1項目を大きなheroや装飾cardへ引き伸ばさない。
- **余白のリズム**: AppShellの既存間隔を基準に、行内は詰め、項目説明と一覧、一覧と追加操作の
  区切りには一段広い余白を使う。
- **タイポグラフィ**: 既存の見出し・本文・補助文のscaleを維持し、pathは可読性を保ったまま折り返す。
- **操作の優先順位**: 通常時は追加を主操作、各行では変更を通常操作、削除を破壊的操作として示す。
- **非達成条件**: 一覧全体の保存操作がある、変更対象以外も消えるように見える、長いpathで操作が
  押し出される、既存画面より過度に大きい見出し・余白・cardを使う場合は要求未達とする。

### Edge Cases

- ファイルは選択候補に表示せず、ディレクトリだけを扱う。
- 読み取れない、または一覧取得中に失われたディレクトリへは移動・登録できない。
- 空のフォルダは有効なメディアフォルダとして登録できる。
- Windows ではドライブ、Linuxでは `/` を起点として、実行環境のサーバー側ディレクトリを辿れる。
- 長いパスや日本語を含むパスを省略表示しても、選択中の値全体を確認できる。
- 登録・変更の直前にフォルダが失われた場合は、以前の有効な設定を維持する。
- 同じdirectoryの重複と、親子関係で探索範囲が重なるdirectoryは同時登録しない。
- filesystem root、Windows drive root、シンボリックリンクはメディアフォルダとして登録しない。
- pickerはシンボリックリンクを候補に表示せず、走査はroot配下のシンボリックリンクを辿らない。
- 取り込み中はメディアフォルダを変更できない。進行中の取り込みを別の場所へ途中から
  切り替えない。
- 複数の画面から同じフォルダを同時に変更された場合、古い版を基にした操作で新しい値を
  黙って上書きしない。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: システムは、サイドバー末尾の「設定」を設定画面への操作可能な入口に
  置き換えなければならない
- **FR-002**: 設定画面は、設定項目としてメディアフォルダだけを表示しなければならない
- **FR-003**: システムは、メディアフォルダ一覧または0件の未設定状態を表示しなければならない
- **FR-004**: 利用者は、サーバー上のディレクトリをフォルダ選択UIで階層移動し、メディア
  フォルダを1件ずつ登録・変更・削除できなければならない
- **FR-005**: フォルダ選択UIはファイルを候補に含めず、読み取り可能なディレクトリと親へ戻る
  操作、現在位置を示さなければならない
- **FR-006**: 選択済みディレクトリが登録・変更前に失われた、または読取不能になった場合、
  システムは永続状態を変更せず、失敗理由と選択し直す方法を示さなければならない
- **FR-007**: 登録したメディアフォルダ一覧は、画面の再読み込みおよびアプリケーションの再起動を
  越えて維持されなければならない
- **FR-008**: メディアフォルダの登録・変更・削除は取り込みを開始してはならず、操作完了後に既存の手動
  取り込みが必要であることを示さなければならない
- **FR-009**: folder操作後に利用者が手動取り込みを開始した場合、システムは登録済みのすべての
  メディアフォルダ配下を再帰的に探索しなければならない
- **FR-010**: 取り込み実行中はメディアフォルダの登録・変更・削除を利用不能にし、その理由を
  利用者へ示さなければならない
- **FR-011**: システムはアプリケーション起動時に取り込みを自動開始してはならない
- **FR-012**: `MDM_SCAN_ON_START` は廃止された設定として扱い、値の有無にかかわらず
  起動時の取り込みを開始してはならない
- **FR-013**: 設定画面に、データフォルダ、待ち受けアドレス、ログレベル、起動時の自動取り込み、
  またはその他の設定項目を表示してはならない
- **FR-014**: 初回起動時のメディアフォルダ一覧は0件とし、利用者がフォルダ選択UIから1件以上登録するまで
  取り込みを開始できない状態にしなければならない
- **FR-015**: 設定画面は既存のアプリケーションシェル、ダーク配色、タイポグラフィ、操作状態の
  規則に従わなければならない
- **FR-016**: 画面の視覚的階層は、画面見出し、設定の説明、現在値、フォルダ操作、補足情報の
  順とし、補足情報を主要操作より強く見せてはならない
- **FR-017**: 1項目を確認・編集するための密度を保ち、ページ区画や設定行を装飾的なカードとして
  重ねてはならない
- **FR-018**: 画面外周、説明と現在値、現在値とフォルダ操作の余白に、既存画面と
  一貫したリズムを持たせなければならない
- **FR-019**: 見出し、項目名、説明、現在位置、選択中のパス、検証結果には既存画面の文字体系を使い、長いパスでも
  項目名や操作を押し出してはならない
- **FR-020**: 設定画面では追加と各行の変更・削除を区別し、フォルダ選択UI内では
  ディレクトリ移動と現在位置の確定を区別して示さなければならない
- **FR-021**: 幅 360px からデスクトップ幅まで、横スクロールや内容の重なりなしに確認・操作
  できなければならない
- **FR-022**: フォルダ選択、登録・変更・削除、エラー確認、完了確認の全工程をキーボードと支援技術から利用できなければ
  ならない
- **FR-023**: `MDM_MEDIA_DIR` を設定手段および初期値として使用してはならず、利用者向け設定、
  起動設定、ログ、文書から廃止しなければならない
- **FR-024**: メディアフォルダが未設定の場合、手動取り込みを開始できず、設定画面からフォルダを
  選択する必要があることを示さなければならない
- **FR-025**: メディアフォルダの新規登録は1件のatomicな操作とし、既存フォルダ、動画、検索索引、
  job、scan、再生状態を変更してはならない
- **FR-026**: 既存メディアフォルダの変更または削除は1件のatomicなtransactionとし、その
  フォルダ由来の動画の実在場所を削除し、実在場所が0件になった動画、検索索引、jobだけを削除し、
  再生位置・視聴済み状態、ほかのフォルダ側の実在場所が残る動画とそのjob・thumbnail、scan履歴を
  変更してはならない
- **FR-027**: 非同期走査はroot・directory・file単位のfilesystem失敗を記録して残りを処理し、
  継続不能なerrorまたはpanicでもscanをfailedへ確定してrunning状態とprocess crashを残してはならない
- **FR-028**: 同一directoryと、祖先・子孫関係で探索範囲が重複するdirectoryを同時に登録してはならない
- **FR-029**: システムはメディアフォルダ一覧全体を編集して一括保存する操作を提供してはならない
- **FR-030**: メディアフォルダの登録・変更・削除後も、システムは取り込みを自動開始してはならない
- **FR-031**: directory listingはシンボリックリンクを返さず、登録・変更時はroot候補を`Lstat`で
  再検証してシンボリックリンクを拒否し、scannerもroot配下のリンクを辿ってはならない
- **FR-032**: filesystem rootおよびWindows drive rootをメディアフォルダとして登録してはならない
- **FR-033**: 非同期jobの結果は処理開始時の`video_id`、`content_key`、`location_id`、
  `location_version`、`path`が現在のvideoとlocationに一致する場合だけ書き戻し、消失・変更済みlocationの
  結果を破棄しなければならない。location固有のI/O失敗は別のcurrent locationへ再試行し、論理videoを
  failedにしてはならない
- **FR-034**: 走査のmissing削除は完全に列挙できた範囲だけに適用し、列挙に失敗したrootまたは
  subtree配下の既存DB行を維持しなければならない
- **FR-035**: directory listingとfolder mutationは既存アプリと同じtrusted-network境界で提供し、
  CORSを許可せず、全mutationをsame-originに限定し、POST/PUTはJSON requestだけを受理しなければならない
- **FR-036**: システムは同じ内容の動画が複数の登録済みフォルダに存在する状態を、1つの動画と
  複数の実在場所として保持し、1つのフォルダの変更・削除で別フォルダ側から利用できる動画を
  削除してはならない
- **FR-037**: folder変更・削除はcontent key名のthumbnail fileを削除してはならない。orphan thumbnailの
  回収は本機能の対象外とし、将来実装する場合も同じcontentの再登録・再生成と競合しない参照確認付きGCとして
  folder操作から分離しなければならない

### Key Entities

- **メディアフォルダ**: サーバー上で動画を探す1つのルートディレクトリ。各行が識別子、path、
  変更競合を防ぐ版、最終更新時刻を持ち、ほかの行と独立して追加・変更・削除される。
- **ディレクトリエントリ**: フォルダ選択UIに表示するサーバー上のディレクトリ。表示名、絶対パス、
  親へ戻れるかを持ち、ファイルを含まない。
- **メディアフォルダ候補**: 利用者がフォルダ選択UIで選んだ1つのディレクトリ。登録・変更時の
  再検証と重複・包含検証に通るまで現在値にならない。
- **取り込み**: 利用者が明示的に開始する、現在のメディアフォルダとライブラリを一致させる処理。
  folder操作やアプリケーション起動から暗黙には開始されない。
- **動画**: 内容識別子で重複排除される論理的な動画。probe結果、再生可否、thumbnail状態を持つ。
- **動画の実在場所**: 動画ファイルが存在する正規化済み絶対path。1つの動画に複数存在でき、
  メディアフォルダの変更・削除は対象root配下の実在場所だけに作用する。

## Assumptions

- 対象利用者は、現在の単一利用者・セルフホスト構成を管理する本人である。
- 認証が実装されるまでは、既存仕様どおり家庭内の信頼できるネットワークだけで運用し、
  インターネットや信頼できないnetwork clientへ公開しない。
- メディアフォルダはブラウザを開いている端末ではなく、サーバーから見える場所を表す。
- メディアフォルダ設定は1項目だけだが、その値として複数のルートディレクトリを登録できる。
- フォルダ選択UIはサーバー上の既存ディレクトリを選ぶ。動画のアップロードとサーバー上の
  フォルダ作成は対象外である。
- 新しいメディアフォルダの追加では既存ライブラリを維持する。既存フォルダの変更・削除では、
  そのフォルダ由来の実在場所と、ほかに実在場所がない動画の再構築可能データだけを同じtransactionで
  削除する。
- データフォルダ、待ち受けアドレス、ログレベル、サムネイル設定、除外規則、ジョブ並列数、
  テーマ、一覧の表示設定は本機能の対象外である。
- 認証と複数利用者ごとの権限管理は本機能の対象外である。
