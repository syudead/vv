- **2026-09-20 / User**: 「設定画面を作る」
- **2026-09-20 / User clarification**: 「メディアフォルダ　だけ」
- **2026-09-20 / User clarification**: 「起動時の自動取り込みは恒久的に不要」

本仕様の対象は、アプリケーションの設定を確認・変更する**設定画面**である。初回に置く
設定項目は、サーバー上の動画を探す**メディアフォルダ1項目だけ**とし、その項目へ複数の
ディレクトリを登録できるようにする。起動時の自動
取り込みは設定項目にせず、機能そのものを廃止する。取り込みは既存の手動操作からのみ
開始する。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 設定画面を開く (Priority: P1)

利用者は、サイドバー末尾の「設定」からアプリケーションの設定画面を開ける。画面には
「設定」という見出しがあり、設定項目としてメディアフォルダだけが並ぶ。

**Why this priority**: ユーザー要求の主語は設定画面であり、メディアフォルダはその画面に
置く最初の設定項目である。専用画面として到達でき、現在位置と設定項目を理解できることが
ほかの操作の前提になる。

**Independent Test**: デスクトップとモバイルの両方でサイドバーから設定画面を開き、画面
見出しと1件の設定項目を確認できれば、このストーリーだけで独立して検証できる。

**Acceptance Scenarios**:

1. **Given** ライブラリ画面を表示している、**When** サイドバーの「設定」を選ぶ、**Then**
   設定画面へ移動し、「設定」が現在位置として示される
2. **Given** モバイル幅でサイドバーを開いている、**When**「設定」を選ぶ、**Then**
   ドロワーが閉じて設定画面へ移動する
3. **Given** 設定画面を開いている、**When** 設定項目を確認する、**Then** メディアフォルダ
   だけが表示され、ほかの設定項目は表示されない

---

### User Story 2 - メディアフォルダを確認・変更する (Priority: P2)

設定画面を開いたセルフホスト環境の管理者は、現在動画を探しているサーバー上の複数フォルダを
確認できる。フォルダを追加・削除するときは、サーバー上のディレクトリを画面内で辿って選択し、
一覧を保存する。絶対パスを文字列で入力する必要はない。

**Why this priority**: メディアフォルダは設定画面に置く唯一の項目であり、現在値の確認、
妥当性の確認、保存がこの機能の中心価値である。

**Independent Test**: フォルダ選択UIで複数の読み取り可能なディレクトリを選んで保存し、画面の
再読み込みとアプリケーションの再起動後にも同じ一覧が表示されれば、このストーリーだけで
独立して検証できる。

**Acceptance Scenarios**:

1. **Given** メディアフォルダが0件である、**When** 設定画面を開く、**Then** 未設定である
   ことと、フォルダの選択が必要であることが分かる
2. **Given** 設定画面を開いている、**When**「フォルダを選択」を実行する、**Then** サーバー上の
   読み取り可能なディレクトリを階層移動し、現在表示しているディレクトリを候補にできる
3. **Given** フォルダ選択UIで複数のディレクトリを追加した、**When** 保存する、**Then** その一覧が
   メディアフォルダとして保存され、旧ライブラリのDBデータが削除されたことが画面上で分かる
4. **Given** メディアフォルダ一覧を保存済みである、**When** 画面を再読み込みする、または
   アプリケーションを再起動する、**Then** 保存した一覧が現在値として維持される
5. **Given** 表示中または選択済みのフォルダが消失・読取不能になった、**When** 一覧表示または
   保存を行う、**Then** 現在の保存値は変更されず、選択し直すための理由が示される

---

### User Story 3 - 新しいフォルダを手動で取り込む (Priority: P3)

利用者はメディアフォルダ一覧を変更したあと、自分の判断で既存の「取り込み」操作を実行する。
保存しただけでは取り込みは始まらず、アプリケーションを起動しただけでも始まらない。

**Why this priority**: 利用者は大量のファイル走査が始まる時期を自分で決められる必要がある。
「起動時の自動取り込みは恒久的に不要」という要求を、単なる既定値ではなく製品挙動として
保証する。

**Independent Test**: メディアフォルダを変更しても取り込みが始まらないこと、その後に既存の
取り込み操作を行うと新しい場所だけがライブラリへ反映されることを確認できる。

**Acceptance Scenarios**:

1. **Given** メディアフォルダ一覧の変更を保存した、**When** 保存が完了する、**Then** 旧動画、
   job、scan、再生状態のDBデータは削除され、取り込みは自動開始されない
2. **Given** 1件以上のメディアフォルダを保存済みである、**When** 利用者が取り込みを開始する、
   **Then** 保存した全フォルダ配下が探索され、完了後の一覧がその集合と一致する
3. **Given** 走査中に一部のdirectoryやfileが消失・読取不能になった、**When** 探索を続ける、
   **Then** 対象の失敗を記録して残りを処理し、プロセスを停止しない
4. **Given** アプリケーションを起動する、**When** 待ち受けを開始する、**Then**
   メディアフォルダの内容にかかわらず取り込みを自動開始しない
5. **Given** 旧 `MDM_SCAN_ON_START` が指定された環境で起動する、**When** 起動が完了する、
   **Then** その値にかかわらず取り込みを自動開始しない
6. **Given** 旧 `MDM_MEDIA_DIR` が指定された環境で初回起動する、**When** 設定画面を開く、
   **Then** その値を引き継がず、メディアフォルダは未設定として表示される

---

### User Story 4 - 迷わず安全に設定する (Priority: P4)

利用者は、デスクトップ、モバイル、キーボード、支援技術のいずれでも、メディアフォルダの
意味、現在値、フォルダ選択、保存操作の関係を見失わずに操作できる。

**Why this priority**: サーバー上の場所を誤って指定するとライブラリ全体の見え方が変わるため、
1項目だけの画面でも影響と操作順を明確にする必要がある。

**Independent Test**: 幅 360px と 1280px、およびキーボードだけで、現在値の確認から保存結果の
確認までを横スクロールや要素の重なりなしに完了できれば独立して検証できる。

**Acceptance Scenarios**:

1. **Given** 幅 360px の設定画面、**When** 長いパスを表示してフォルダを選択する、**Then** 画面全体の
   横スクロールや文字・操作部品の重なりが起きない
2. **Given** キーボードだけを使う利用者、**When** フォルダ選択UIと保存操作をたどる、**Then**
   フォーカス位置が常に見え、ディレクトリの移動・選択・保存を完了できる
3. **Given** 支援技術を使う利用者、**When** 設定画面を読む、**Then** 画面見出し、説明、
   現在値、フォルダ選択、検証結果、保存結果が意味の通る順序で伝わる

### Edge Cases

- ファイルは選択候補に表示せず、ディレクトリだけを扱う。
- 読み取れない、または一覧取得中に失われたディレクトリへは移動・保存できない。
- 空のフォルダは有効なメディアフォルダとして保存できる。
- Windows ではドライブ、Linuxでは `/` を起点として、実行環境のサーバー側ディレクトリを辿れる。
- 長いパスや日本語を含むパスを省略表示しても、選択中の値全体を確認できる。
- 保存の直前にフォルダが失われた場合は、以前の有効な設定を維持する。
- 同じdirectoryの重複と、親子関係で探索範囲が重なるdirectoryは同時登録しない。
- 取り込み中はメディアフォルダを変更できない。進行中の取り込みを別の場所へ途中から
  切り替えない。
- 複数の画面から同時に変更された場合、古い現在値を基にした保存で新しい設定を黙って
  上書きしない。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: システムは、サイドバー末尾の「設定」を設定画面への操作可能な入口に
  置き換えなければならない
- **FR-002**: 設定画面は、設定項目としてメディアフォルダだけを表示しなければならない
- **FR-003**: システムは、メディアフォルダ一覧または0件の未設定状態を表示しなければならない
- **FR-004**: 利用者は、サーバー上のディレクトリをフォルダ選択UIで階層移動し、複数の候補を
  追加・削除して一覧として保存できなければならない
- **FR-005**: フォルダ選択UIはファイルを候補に含めず、読み取り可能なディレクトリと親へ戻る
  操作、現在位置を示さなければならない
- **FR-006**: 選択済みディレクトリが保存前に失われた、または読取不能になった場合、システムは
  現在有効な設定を変更せず、候補を保持したまま、失敗理由と選択し直す方法を示さなければならない
- **FR-007**: 保存したメディアフォルダ一覧は、画面の再読み込みおよびアプリケーションの再起動を
  越えて維持されなければならない
- **FR-008**: メディアフォルダの保存は取り込みを開始してはならず、保存完了後に既存の手動
  取り込みが必要であることを示さなければならない
- **FR-009**: 保存後に利用者が手動取り込みを開始した場合、システムは保存したすべての
  メディアフォルダ配下を再帰的に探索しなければならない
- **FR-010**: 取り込み実行中はメディアフォルダの保存操作を利用不能にし、その理由を
  利用者へ示さなければならない
- **FR-011**: システムはアプリケーション起動時に取り込みを自動開始してはならない
- **FR-012**: `MDM_SCAN_ON_START` は廃止された設定として扱い、値の有無にかかわらず
  起動時の取り込みを開始してはならない
- **FR-013**: 設定画面に、データフォルダ、待ち受けアドレス、ログレベル、起動時の自動取り込み、
  またはその他の設定項目を表示してはならない
- **FR-014**: 初回起動時のメディアフォルダ一覧は0件とし、利用者がフォルダ選択UIから1件以上保存するまで
  取り込みを開始できない状態にしなければならない
- **FR-015**: 設定画面は既存のアプリケーションシェル、ダーク配色、タイポグラフィ、操作状態の
  規則に従わなければならない
- **FR-016**: 画面の視覚的階層は、画面見出し、設定の説明、現在値、フォルダ選択、保存操作、補足情報の
  順とし、補足情報を主要操作より強く見せてはならない
- **FR-017**: 1項目を確認・編集するための密度を保ち、ページ区画や設定行を装飾的なカードとして
  重ねてはならない
- **FR-018**: 画面外周、説明と現在値、現在値とフォルダ選択、選択結果と保存操作の余白に、既存画面と
  一貫したリズムを持たせなければならない
- **FR-019**: 見出し、項目名、説明、現在位置、選択中のパス、検証結果には既存画面の文字体系を使い、長いパスでも
  項目名や操作を押し出してはならない
- **FR-020**: 設定画面では保存を主要操作として示し、フォルダ選択UI内ではディレクトリ移動と
  現在位置の選択を区別して示さなければならない
- **FR-021**: 幅 360px からデスクトップ幅まで、横スクロールや内容の重なりなしに確認・操作
  できなければならない
- **FR-022**: フォルダ選択、保存、エラー確認、完了確認の全工程をキーボードと支援技術から利用できなければ
  ならない
- **FR-023**: `MDM_MEDIA_DIR` を設定手段および初期値として使用してはならず、利用者向け設定、
  起動設定、ログ、文書から廃止しなければならない
- **FR-024**: メディアフォルダが未設定の場合、手動取り込みを開始できず、設定画面からフォルダを
  選択する必要があることを示さなければならない
- **FR-025**: メディアフォルダ一覧が変更された場合、システムは設定更新と同じtransactionで、
  旧一覧から生成された動画、検索索引、job、scan、再生位置・視聴済み状態をDBから削除しなければならない
- **FR-026**: メディアフォルダ一覧の変更によるDB削除後も、システムは取り込みを自動開始してはならない
- **FR-027**: 非同期走査はroot・directory・file単位のfilesystem失敗を記録して残りを処理し、
  継続不能なerrorまたはpanicでもscanをfailedへ確定してrunning状態とprocess crashを残してはならない
- **FR-028**: 同一directoryと、祖先・子孫関係で探索範囲が重複するdirectoryを同時に保存してはならない

### Key Entities

- **メディアフォルダ設定**: サーバー上で動画を探す0件以上のルートディレクトリ集合。更新を
  競合させないための版、最終更新時刻を持つ。
- **ディレクトリエントリ**: フォルダ選択UIに表示するサーバー上のディレクトリ。表示名、絶対パス、
  親へ戻れるかを持ち、ファイルを含まない。
- **メディアフォルダ候補**: 利用者がフォルダ選択UIで組み立てたディレクトリ集合。保存時の
  再検証と重複・包含検証に通るまで現在値にならない。
- **取り込み**: 利用者が明示的に開始する、現在のメディアフォルダとライブラリを一致させる処理。
  設定保存やアプリケーション起動から暗黙には開始されない。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 初めて利用する人の90%以上が、15秒以内にサイドバーから設定画面を開き、
  設定項目がメディアフォルダだけであると判断できる
  （Original Request の「設定画面」と「メディアフォルダだけ」を満たす）
- **SC-002**: 有効なフォルダ一覧は1分以内に保存でき、その保存成功率を100%とする。無効なパスが
  現在設定へ反映される件数は0件にする
  （Original Request の「メディアフォルダ」を安全に設定できることを満たす）
- **SC-003**: 保存したメディアフォルダが画面再読み込みとアプリケーション再起動後に維持される
  割合を100%とする（Original Request の「設定」として恒久的に使えることを満たす）
- **SC-004**: 設定保存時およびアプリケーション起動時に自動開始される取り込みを0件にする
  （Original Request の「起動時の自動取り込みは恒久的に不要」を満たす）
- **SC-005**: 新しいフォルダ一覧を保存した直後の旧ライブラリDB行を0件とし、手動取り込み完了後は
  保存した全フォルダ内の取り込み可能な動画の欠落を0件にする
  （Original Request の「メディアフォルダ」を実際のライブラリへ反映できることを満たす）
- **SC-006**: 幅360px、768px、1280pxのすべてで、横スクロール、文字の欠落、操作部品の
  重なりを0件にする（Original Request の「設定画面」を各画面幅で利用できることを満たす）
- **SC-007**: 現在値の確認から保存結果の確認までをキーボードだけで完了でき、見えないフォーカスと
  名前のない操作を0件にする（Original Request の「設定画面」を入力方法によらず利用できる
  ことを満たす）
- **SC-008**: 視覚レビューで、設定の説明と値の階層、1項目に適した情報密度、一貫した余白、
  既存画面と揃った文字体系、保存操作の優先順位の5観点すべてを満たす
  （Original Request の「設定画面」を既存製品に属する実用品として満たす）

## Superseded Behavior

本仕様は、次の既存仕様のうち起動時取り込みに関する部分を置き換える。

- `specs/002-core-video-library/spec.md` の「取り込みの起点は、アプリケーションの起動時と
  利用者の指示とする」という仮定は、「利用者の明示的な指示だけ」に変更する。
- `specs/002-core-video-library/contracts/configuration.md` の `MDM_SCAN_ON_START` は廃止する。
- `specs/002-core-video-library/contracts/configuration.md` の `MDM_MEDIA_DIR` は廃止する。
- `specs/002-core-video-library/research.md` の R-108 にある起動直後の自動実行は採用を終了する。

手動取り込み、取り込み進捗、移動・改名の同一性、失われた動画の除去、再生位置の保護に
関する既存契約は維持する。

## Assumptions

- 対象利用者は、現在の単一利用者・セルフホスト構成を管理する本人である。
- メディアフォルダはブラウザを開いている端末ではなく、サーバーから見える場所を表す。
- メディアフォルダ設定は1項目だけだが、その値として複数のルートディレクトリを登録できる。
- フォルダ選択UIはサーバー上の既存ディレクトリを選ぶ。動画のアップロードとサーバー上の
  フォルダ作成は対象外である。
- メディアフォルダ一覧を変更した時点で旧ライブラリDBデータを削除し、次の手動取り込みまでは
  ライブラリを空として扱う。
- データフォルダ、待ち受けアドレス、ログレベル、サムネイル設定、除外規則、ジョブ並列数、
  テーマ、一覧の表示設定は本機能の対象外である。
- 認証と複数利用者ごとの権限管理は本機能の対象外である。
