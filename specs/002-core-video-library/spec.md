## User Scenarios & Testing _(mandatory)_

本機能の利用者は、自分の動画ファイルを1台のマシンに溜め込んでいる個人である。現状、
動画はフォルダ階層に散らばっており、目当ての1本を探すにはファイル名を頼りにフォルダを
たどるしかなく、内容はファイルを開くまで分からない。

受け取った[画面案](assets/ui-mockup.webp)には、動画・画像・コレクション・タグ・
お気に入り・未整理・一括選択・表示密度の切り替えなど多くの要素が含まれる。本仕様はその
全体像のうち、**これが無ければ製品として成り立たない機能だけに絞る**。すなわち
「置いた動画が自動で一覧に並び、ブラウザで再生でき、目当ての1本を名前で探せる」まで
である。整理のための機能（タグ・お気に入り・コレクション）と画像（静止画）の管理は含めない
（下記 Assumptions と「本仕様のスコープ外」を参照）。

前提として、[001 初期セットアップ](../001-initial-setup/spec.md)の骨組み（起動・設定・
保存先の自動初期化）はすでに満たされているものとする。

### User Story 1 - 置いた動画が自動で一覧に並ぶ (Priority: P1)

利用者は、動画を置いた場所をアプリケーションに教えるだけでよい。ファイルを登録したり
名前を付け直したりする作業は必要なく、一覧を開くと、そこにある動画が内容の分かる静止画・
題名・長さとともに並んでいる。あとから動画を追加しても、同じ操作なしに一覧へ現れる。

**Why this priority**: 「何が手元にあるか」が見える状態が、本製品の存在理由そのものである。
再生も検索も一覧の上に載る機能であり、ここだけが完成しても「フォルダを開かずに手持ちを
見渡せる」という価値が単独で成立する。

**Independent Test**: 動画を何本か置いたフォルダを指定してアプリケーションを起動し、
一覧画面を開く。手作業の登録なしに、置いた本数と同じ件数が静止画・題名・長さ付きで
並べば成功。フォルダに1本追加し、取り込みを促したあとに一覧へ現れることも確認する。

**Acceptance Scenarios**:

1. **Given** 動画ファイルが置かれた場所を設定済みの初回起動、**When** 取り込みが完了して
   一覧を開く、**Then** その場所にある再生対象の動画が、内容を表す静止画・題名・長さ・
   解像度の区別とともに一覧に並ぶ
2. **Given** 取り込み済みのライブラリ、**When** 新しい動画ファイルを追加して取り込みを
   行う、**Then** 追加分だけが一覧に増え、既存の項目は作り直されない
3. **Given** 取り込み済みのライブラリ、**When** 動画ファイルを別のフォルダへ移動する、
   または名前を変更して取り込みを行う、**Then** 同じ動画として扱われ、重複した項目は
   増えず、その動画に紐づく利用者データ（再生位置など）は保持される
4. **Given** 取り込み済みのライブラリ、**When** 元のファイルが削除された状態で取り込みを
   行う、**Then** その動画は一覧から消え、ほかの項目に影響しない
5. **Given** 数千本規模のライブラリの初回取り込み中、**When** 一覧を開く、**Then** 取り込み
   済みの分をすでに閲覧・再生でき、進行中であることと残りの規模が画面から分かる
6. **Given** 一覧画面、**When** 並び順を「追加が新しい順」「題名順」などから選ぶ、
   **Then** 選んだ順で並び替わり、総件数が画面から分かる

---

### User Story 2 - ブラウザで再生し、続きから見られる (Priority: P2)

利用者は、一覧から動画を選ぶだけでブラウザ上で再生できる。ファイルをダウンロードしたり
別の再生ソフトを開いたりする必要はない。任意の位置へ飛べるし、途中でやめた動画は、
次に開いたときに続きから再生できる。

**Why this priority**: 一覧で見つけた動画をその場で見られて初めて、フォルダを開く習慣を
置き換えられる。User Story 1 の上に載るが、再生位置の保存まで含めて単独で検証できる。

**Independent Test**: 一覧から動画を選んで再生し、任意の位置へ飛べることを確認する。
途中で画面を閉じ、再度同じ動画を開いて続きから始まることを確認する。

**Acceptance Scenarios**:

1. **Given** 一覧に並んだ再生可能な動画、**When** その動画を選ぶ、**Then** ブラウザ上で
   映像と音声の再生が始まり、題名・長さ・解像度などの情報を同じ画面で確認できる
2. **Given** 再生中の動画、**When** 再生位置を任意の箇所へ移動する、**Then** 先頭から
   読み直すことなくその位置から再生が続く
3. **Given** 途中まで再生して離脱した動画、**When** あとから同じ動画を開く、**Then** 中断
   位置から再生を再開できる
4. **Given** 最後まで再生した動画、**When** 一覧に戻る、**Then** その動画は視聴済みと
   分かる表示になり、途中まで見た動画は進捗が一覧上で分かる
5. **Given** ブラウザが再生できない形式の動画、**When** 一覧でその動画を見る、**Then**
   再生を試みる前に再生できないことが分かり、原因（形式が対象外であること）が示される
6. **Given** 再生中に元のファイルが失われた場合、**When** 再生を続けようとする、**Then**
   利用者に何が起きたかが伝わり、アプリケーション全体は使い続けられる

---

### User Story 3 - 題名で目当ての1本を探す (Priority: P3)

ライブラリが数千本に育っても、利用者は覚えている語の一部を入力するだけで候補を絞り込める。
日本語の題名でも、先頭からでなく途中の語で探せる。

**Why this priority**: 一覧の並べ替えだけでは、数千本規模から1本を取り出せない。ただし
一覧と再生が動いていれば少数のライブラリでは実用になるため、優先度は3番目とする。

**Independent Test**: 日本語を含む題名の動画を多数取り込んだ状態で、題名の途中の数文字を
入力し、該当する動画だけが残ることを確認する。

**Acceptance Scenarios**:

1. **Given** 取り込み済みのライブラリ、**When** 題名の一部を検索語として入力する、
   **Then** 該当する動画だけが一覧に残り、件数が分かる
2. **Given** 日本語の題名を含むライブラリ、**When** 題名の先頭ではなく途中の語を入力する、
   **Then** その動画が結果に含まれる
3. **Given** 検索結果が表示された状態、**When** 検索語を消す、**Then** 元の一覧に戻る
4. **Given** 該当する動画が1本もない検索語、**When** 検索する、**Then** 結果が無いことが
   明示され、次に取れる操作（検索語を変える）が分かる

---

### Edge Cases

- 対象の場所に動画以外のファイル（文書・画像・一時ファイル）が混在する場合、取り込みは
  それらを無視し、失敗として扱わない
- 破損していて情報を読み取れないファイルは、取り込み全体を止めず、当該ファイルだけを
  取り込めなかったものとして利用者が確認できる
- 同一内容のファイルが複数の場所に存在する場合は1つの動画と複数の実在場所として扱い、
  どの場所から再生しても同じ再生位置を使う
- 取り込み対象の場所が存在しない・読み取れない場合、原因と対処が分かる形で示され、
  アプリケーションは起動したまま利用できる
- macOS 由来のファイル名など、同じ文字列が異なる表現で保存されている場合でも、同じ
  題名として検索・並べ替えできる
- 内容を表す静止画をまだ用意できていない動画も、一覧に並び再生できる（静止画は後から
  埋まる）
- 極端に短い動画・長さ情報を持たない動画でも、一覧の表示と再生が崩れない
- 1〜2文字などの短い検索語でも、該当する動画を取り出せる
- 複数のタブや端末から同じ動画を再生した場合、再生位置は最後の操作が残り、利用者から見て
  不整合な巻き戻りが起きない
- 取り込み中にアプリケーションが停止した場合、次の起動で取り込みを最初からやり直さずに
  再開でき、途中で重複した項目を残さない

## Requirements _(mandatory)_

### Functional Requirements

**取り込み（ライブラリの構築）**

- **FR-001**: システムは、設定された場所以下にある動画ファイルを再帰的に探索し、利用者の
  手作業による登録なしにライブラリへ取り込まなければならない
- **FR-002**: システムは、取り込み時に各動画の長さ・解像度・形式・ファイルサイズ・追加
  日時を取得し、一覧と詳細で参照できるようにしなければならない
- **FR-003**: システムは、ブラウザで再生できない形式の動画を取り込み時に判別し、その
  状態を利用者に示さなければならない（変換は行わない）
- **FR-004**: システムは、ファイルの移動・改名を、内容にもとづいて同一の動画として認識
  しなければならない。再取り込みで重複した項目を作ってはならない
- **FR-005**: システムは、元ファイルが失われた動画を一覧から取り除かなければならない
- **FR-006**: システムは、利用者の指示によって再取り込みを実行でき、その進捗（対象件数・
  完了件数・失敗件数）を画面から確認できなければならない
- **FR-007**: システムは、取り込みが完了していない段階でも、取り込み済みの動画の閲覧と
  再生を妨げてはならない
- **FR-008**: システムは、個別のファイルの取り込みに失敗しても処理全体を中止せず、失敗
  した対象と理由を利用者が確認できるようにしなければならない
- **FR-009**: システムは、取り込み対象の動画ファイルを変更・移動・削除してはならない
  （読み取りのみ）
- **FR-010**: システムは、各動画について内容を表す静止画を用意し、一覧で表示しなければ
  ならない。静止画が未作成の動画も一覧に並べなければならない

**一覧（見つける）**

- **FR-011**: システムは、取り込んだ動画を静止画・題名・長さ付きの一覧として表示しなければ
  ならない
- **FR-012**: システムは、一覧の総件数を表示しなければならない
- **FR-013**: 利用者は、一覧の並び順を少なくとも「追加が新しい順」と「題名順」から選べ
  なければならない
- **FR-014**: システムは、数千本規模のライブラリでも一覧を段階的に表示し、全件の読み込み
  完了を待たせてはならない
- **FR-015**: システムは、視聴済みの動画と途中まで見た動画を、一覧上で区別できるように
  しなければならない

**再生**

- **FR-016**: 利用者は、一覧から選んだ動画を、ダウンロードや外部ソフトなしにブラウザ上で
  再生できなければならない
- **FR-017**: システムは、動画の任意の位置への移動（シーク）を、先頭からの読み直しなしに
  行えなければならない
- **FR-018**: システムは、再生位置を継続的に記録し、次回同じ動画を開いたときに続きから
  再開できなければならない
- **FR-019**: システムは、動画を最後まで再生したことを視聴済みとして記録しなければならない
- **FR-020**: システムは、再生できない動画に対して、失敗の理由が分かる表示を行わなければ
  ならない

**検索**

- **FR-021**: 利用者は、題名の一部を入力して一覧を絞り込めなければならない
- **FR-022**: システムは、日本語を含む題名に対して、先頭一致ではない部分一致で検索できな
  ければならない
- **FR-023**: システムは、1文字の検索語でも該当する動画を取り出せなければならない
- **FR-024**: システムは、該当が無い場合にその旨を明示しなければならない

**利用者データの保護**

- **FR-025**: システムは、再生位置・視聴済みなど利用者の操作で生まれたデータを、再取り込み
  や動画ファイルの移動によって失ってはならない
- **FR-026**: システムは、再構築できるデータ（取り込みで得た情報・静止画）と、再構築できない
  利用者データを区別して扱わなければならない

### Key Entities _(include if feature involves data)_

- **動画**: ライブラリの1項目。所在（ファイルの場所）、題名、長さ、解像度、形式、サイズ、
  追加日時、再生可否、内容を表す静止画を持つ。ファイルの移動・改名を越えて同一と判定
  できる内容由来の識別子を持つ
- **再生位置**: ある動画をどこまで見たか。再生位置と視聴済みの別を持ち、再取り込みでは
  失われない
- **取り込み**: ライブラリを実際のファイルに合わせる処理の単位。対象件数・完了件数・失敗
  件数・失敗の理由を持ち、進行中でも一覧の利用を妨げない
- **ライブラリ**: 取り込み対象の場所と、そこから得られた動画の集合。総件数を持つ

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 動画を置いた場所を設定して起動してから、最初の動画が一覧に現れるまで 30 秒
  以内である
- **SC-002**: 1,000 本規模のライブラリが、初回取り込みの開始から 15 分以内に一覧へ出そろう
- **SC-003**: 10,000 本規模のライブラリでも、一覧の最初の画面が 2 秒以内に表示される
- **SC-004**: 一覧で動画を選んでから映像が表示されるまで 3 秒以内、再生位置を移動してから
  再生が再開するまで 2 秒以内である
- **SC-005**: 途中まで見た動画を開き直したとき、100% の動画で中断位置（誤差 5 秒以内）から
  再開できる
- **SC-006**: 検索語を入力してから結果が表示されるまで、10,000 本規模のライブラリで 1 秒
  以内である
- **SC-007**: ブラウザで再生できない動画は、再生を試みる前に 100% 判別できる（再生してから
  失敗する事象が起きない）
- **SC-008**: 動画ファイルの移動・改名だけを行ったあとの再取り込みで、重複した項目が 0 件、
  再生位置などの利用者データの消失が 0 件である
- **SC-009**: 取り込み中に一部のファイルが失敗しても、残りの取り込みは 100% 完了し、失敗
  した対象を画面から特定できる
- **SC-010**: 本製品を初めて使う利用者が、説明を読まずに、目当ての動画を見つけて再生を
  始めるまで 3 分以内である

## Assumptions

- 「絞られたコア機能」は、添付の画面案が示す全体像のうち
  [技術選定文書](../../docs/design-docs/tech-stack-selection.md)「8. 実装の進め方」の
  **Phase 1 — 一覧と再生** を中心に、一覧が実用になるための最小限（内容を表す静止画・
  題名検索・再生位置）までを含む範囲と解釈した
- 手動の整理機能（タグ・お気に入り・コレクション・未整理の絞り込み）はコアに**含めない**。
  一覧・再生・検索が動いたあとの次の段階として扱う（2026-09-12 決定）
- 管理対象は**動画のみ**とし、画面案の「画像」タブが示す静止画像の管理はコアに含めない
  （2026-09-12 決定）
- 利用者は単一で、家庭内の信頼できるネットワークに置いた1台で運用する。認証は本仕様の
  範囲外であり、インターネットへ公開しない前提とする
- 動画ファイルはアプリケーションから読み取り専用で扱う。ファイルの削除・改名・移動・
  変換といった書き込み操作は行わない
- 主たる対象は、ブラウザがそのまま再生できる形式の動画である。対象外の形式は「再生できない」
  と示すにとどめ、形式変換は本仕様の範囲外とする
- 想定するライブラリの規模は数千〜1万本、総容量は数 TB とする
- 取り込みの起点は利用者の明示的な指示だけとする。起動時の自動取り込みとファイル変更の常時監視に
  よる自動反映は行わない（[007 設定画面](../007-settings-screen/spec.md)による置換）
- 題名は、取り込み時にファイル名から決める。利用者による題名の編集は本仕様の範囲外とする
- 外部の動画解析ツールの存在は 001 の起動前確認で保証されているものとし、本仕様では
  改めて扱わない

### 本仕様のスコープ外

明示的に扱わないもの（画面案には現れるが、コアには含めない）:

- 画像（静止画）の管理
- コレクション、タグ、お気に入り、未整理の絞り込みといった手動の整理機能
- 一覧の複数選択と一括操作、表示密度の切り替え、リスト表示
- 認証・複数利用者・外部公開
- 形式変換（トランスコード）、字幕の変換と表示
- バックアップ手順の整備
