## 実装で確定したこと

- **依存は3つ増えた（計画は2つ）。** `golang.org/x/text` と `react-router` に加えて
  `github.com/oapi-codegen/runtime` が増えた。契約に経路・問い合わせパラメータを
  足した結果、生成物がそれを import するようになったためである。詳細は
  [TD-005](../tech-debt.md)。
- **`internal` の兄弟パッケージは互いを import しない。** `scanner`・`jobs`・`httpapi`
  は必要な操作を自分で interface として宣言し、`store` がたまたまそれを満たす。
  どの具体型をどこへ渡すかを知っているのは `cmd/mdm` だけである。境界をまたぐ値
  （`domain.VideoFile`・`domain.Job`・`domain.VideoQuery` など）は `internal/domain`
  に置いた。depguard が強制するのは `internal/domain` の側だけなので、これは
  規約であって機械的な強制ではない。
- **中断からの復帰は2箇所で要る。** ジョブの巻き戻し（`running` → `queued`）は
  設計どおりだが、走査にも同じ手当てが要った。`running` のまま残った `scans` 行を
  起動時に閉じないと、「実行中は1件だけ」の部分ユニーク索引が働いたまま二度と
  取り込みを始められなくなる（`FailInterruptedScans`）。
- **検索語の文字数は NFC 正規化してから数える。** 結合文字で書かれた「が」を
  2文字と数えると、2文字の入力が `MATCH` 経路へ回って0件になる。

## 受け入れ検証の記録（2026-09-13）

| シナリオ | 結果 |
| --- | --- |
| S1 置いた動画が自動で一覧に並ぶ | 3 本が静止画・題名・長さ付きで並ぶ。`.txt`・隠しファイル・`.part` は除外 |
| S2 取り込みの進捗が見える | `state`・`total`・`completed`・`failed` が返る。実行中の `POST` は実行中のものを返す（202） |
| S3 再生できない形式が分かる | `mkv` が `playable: false`・`unplayableReason: "container"` |
| S4 Range 配信 | 先頭・途中・末尾で `206` と `Content-Range`、範囲外は `416` |
| S5 続きから再生 | 記録・読み出し・95% 以降の視聴済み判定。`text/plain` の本文も受理 |
| S6 題名で探す | 3文字（`MATCH`）・2文字と1文字（`LIKE`）・該当なし・FTS5 の特殊文字 |
| S7 移動・改名 | `id` が変わらず題名とパスが更新され、総件数も増えない |
| S8 削除 | 件数が1つ減り、孤児サムネイルも掃除される |

### S9: 規模と応答（1,000 本）

`ffmpeg` で内容の異なる 1,000 本を生成して計測した（1 本 1 秒・160x90）。

| 指標 | 実測 | 上限 |
| --- | --- | --- |
| 索引付け（`scans` が `done` になるまで） | 2 秒 | — |
| 取り込み完了（解析とサムネイルまで、直列） | 約 105 秒 | 15 分（SC-002） |
| 一覧1ページ目（60 件） | 1.4〜3.4 ミリ秒 | 2 秒（SC-003） |
| 検索（3文字・`MATCH` 経路、111 件該当） | 3.2 ミリ秒 | 1 秒（SC-006） |
| 検索（2文字・`LIKE` 経路、111 件該当） | 3.7 ミリ秒 | 1 秒（SC-006） |
| カーソルで全 1,000 件を走査（5 ページ） | 20 ミリ秒 | — |
| `MDM_DATA_DIR` の大きさ | 22MB（うちサムネイル 1,000 枚） | — |

**この検証で1件の不具合が出た。** 1 秒の動画すべてでサムネイル生成が失敗した。
抽出位置の下限（1 秒）が尺と同じかそれ以上になり、`ffmpeg` が終了コード 0 の
まま1枚も出力しなかったためである。下限が尺を越える場合は 10% 地点へ戻すよう
直し、あわせて「位置を変えて一度だけ取り直す」経路を足した（1,000 / 1,000 成功）。
規模で走らせなければ、短い動画を使わない限り気付けなかった。

### S10: データを消しても復旧する

`MDM_DATA_DIR` を丸ごと削除して起動し直した（`docker volume rm vv_data` 相当）。

- スキーマは手作業なしに作り直された
- 再スキャンで 1,000 件の一覧が復元した（2 秒）
- 記録しておいた再生位置は失われた — 「索引は再構築できる／利用者データは
  できない」という区分どおりの挙動である（バックアップ手順の整備は Phase 3）

## 決定の記録

- **2026-09-12: コアの範囲を確定した。** 整理機能（タグ・お気に入り・コレクション）と
  画像（静止画）の管理は含めない。一覧・再生・検索が動いたあとの段階で扱う。
- **2026-09-12: 同一判定の鍵は「サイズ + 先頭/末尾 1MiB の SHA-256」にした。**
  技術選定文書 3.2 は BLAKE3 を挙げているが、読む量が 2MiB に固定されているため
  速度差が取り込み時間を律速しない。標準ライブラリで済ませ、依存を増やさない。
  技術選定文書の記述はこの決定に合わせて更新する（実装時のタスク）。
  詳細は [research.md R-101](../../../specs/002-core-video-library/research.md)。
- **2026-09-12: 再生位置は `content_key` を鍵に持つ。** `videos.id` に紐づけると、
  ファイルを消して置き直したときに失われる。「再構築できる索引」と「再構築できない
  利用者データ」をテーブル単位で分ける方針（技術選定文書の判断基準2）がそのまま成立する。
- **2026-09-12: 再生可否は許可リストで判定し、取り込み時に確定させる。** 未知の
  コーデックを「再生できる」と誤るより「できない」と誤る方が損失が小さい。
  一覧では列を読むだけにして、再生を試みる前に判別できる状態にする（SC-007）。
- **2026-09-12: サムネイルは JPEG にした。** WebP の方が小さいが、`libwebp` を含む
  `ffmpeg` ビルドを前提にすると実行環境の差で失敗しうる。
- **2026-09-12: 新しい依存は 2 つに絞った。** `golang.org/x/text`（NFC 正規化）と
  `react-router` v7（2画面のルーティング）。データ取得ライブラリと `sqlc` は入れない。
- **2026-09-12: 画面が増えるため、PR には画像を添える。** 本機能は
  [UI の変更を画像で示す規約](../../how-to/ui-change-screenshots.md)が初めて適用される
  変更になる。
