# Screen text and formatting (i18n)

Screen text in `web/src` and the formatting of dates, numbers and the like live
in `web/src/i18n/`. The only language provided is English, and there is no
language selection. The background for these decisions is in
[specs/023-english-i18n/research.md](../../specs/023-english-i18n/research.md)
(R-1 to R-3, R-5, R-6, R-9).

## Catalog

- `en.ts` is the English catalog: nested objects per screen area. Text with
  embedded values is a function taking arguments (`t.count.videos(n)`,
  `t.folderGrouping.ungrouped(name)`).
- Components import it statically with `import { t } from "../i18n"`. The
  language is one constant decided at startup (`LOCALE` in `intl.ts`) and does
  not change at runtime, so there is no React context or provider.
- The catalog's shape is `MessageSource` (`typeof en`). Adding a language means
  writing an object that satisfies this type; type checking finds missing keys
  and mismatched function arguments. There is no translation management tool or
  extraction step; adding a language means writing TypeScript from the English
  catalog.
- User data (video names, folder names, tag names, paths) is not translated; it
  is passed as an argument to a catalog function and embedded. The Japanese font
  (Noto Sans JP) is kept so that Japanese names render correctly on the English
  screen.

## UiText

Values returned by the catalog and the output of formatting functions have the
branded type `UiText` (`uiText.ts`). Text props of components in `web/src/ui/`
(`label` of `IconButton`, `title` of `ModalFrame`, toast text, `placeholder`,
`aria-label` and reasons of `Combobox`, and so on) and error text returned by
hooks in `api/` are `UiText` too. An English literal that does not come through
the catalog cannot go there, so type checking fails. Values that carry user data
(`ComboboxOption.label`, `title` of `Chip`, and so on) stay `string`.

## Video player (video.js)

The accessible names and tooltips of the video.js control bar are replaced by a
custom language (`en-x-vv`) that `playerDictionary()` in
`web/src/player/VideoPlayer.tsx` builds from the catalog's `t.player.controls`.
Buttons with keyboard shortcuts get the key appended through `withKey`
(`Play (Space)`, `Mute (M)`, `Fullscreen (F)`, and `Restart (0)`, which is
inserted into the control bar). The language is registered again every time a
player is created, so the pseudo-locale reaches it too. Video.js also uses this
name for the player's `lang` attribute, and text missing from the table falls
back to the defaults of the primary language `en`.

## Formatting

The functions in `format.ts` and `intl.ts` use `Intl` with the same `LOCALE` as
the catalog.

| Function | Output |
| --- | --- |
| `formatNumber` | A number with digit grouping |
| `formatDate`, `formatDateTime` | `Intl.DateTimeFormat` with a `medium` date and a `short` time |
| `formatRelative` | The "3 days ago" form from `Intl.RelativeTimeFormat`. The thresholds (just now, minutes, hours, days, weeks, months, years) are the same as before the English conversion; under 45 seconds it is the catalog's `t.time.justNow` |
| `selectPlural` | Chooses `one` or `other` with `Intl.PluralRules`; used by the catalog's count functions |
| `formatList` (`intl.ts`) | Joins as "A, B, and C" with `Intl.ListFormat`; used by catalog functions that list catalog text (the "being created" line on the playback screen) |

Locale-independent formatting (duration, file size, resolution, quality labels)
is in `web/src/lib/format.ts`.

## API error display

`RequestFailed` in `web/src/api/client.ts` holds the response's `status`, `code`
and `message`, plus `reason`, `limit` and `tagName`
([contracts/error-api.md §1](../../specs/023-english-i18n/contracts/error-api.md)).
A failure of `fetch` itself is `NetworkFailed`. `errorText` in `i18n/errors.ts`
picks the screen text in this order:

1. A known `reason`, or else a known `code`: the catalog sentence (with `limit`
   and `tagName` embedded).
2. An unknown `code` with a `message`: the server's English `message`.
3. A body that is not JSON, is empty, or has no `message`:
   `Request failed (HTTP <status>)`.
4. `NetworkFailed`: a sentence saying the server could not be reached. Any other
   exception gets a generic sentence; browser and exception messages are not
   shown.

The error tables are written as the generated types `Record<ErrorCode, …>` and
`Record<ErrorReason, …>`, so adding a code or reason to `api/openapi.yaml` fails
type checking until a sentence exists. For analysis and import failures,
`probeErrorText` and `scanErrorText` build the explanation from `ProbeErrorCode`
and `ScanErrorCode` (and `errorPath`); the free-text `probeError` and
`Scan.error` are not used. Past failures without a code get a generic sentence.

## Detecting untranslated text

- **ESLint**: `no-restricted-syntax` in `web/eslint.config.js` reports, in
  non-test code under `web/src` outside `i18n/`: string literals and templates
  containing Japanese, JSX text containing letters, string literals passed to
  `aria-label`, `title`, `placeholder` and `alt`, `"ja-JP"`, and
  `toLocaleString`, `toLocaleDateString` and `toLocaleTimeString` without a
  locale. It inspects the AST, so comments left in Japanese are not reported. No
  directory is excluded (only tests and `i18n/` are out of scope).
- **Types**: `UiText` above and the `Record` error tables.
- **Pseudo-locale screen tests**: `enablePseudoLocale()` in `i18n/pseudo.ts`
  wraps every catalog sentence and formatting output in `⟦ ⟧`.
  `expectCatalogTextOnly(root, userData)` checks that all visible text and every
  `aria-label`, `title`, `placeholder` and `alt` on the rendered screen either
  carries the marks or is user data supplied by the test. English rendered
  through a `string` variable slips past the types but has no marks, so it is
  caught here. `web/vitest.setup.ts` switches back to English after each test.

Types catch omissions when the code is written; screen tests catch them in the
states they render. Text that reaches the screen through a `string` variable in
a state no test renders is visible to neither.

## Wording in ui-design.md

Each feature's `ui-design.md` quotes Japanese screen text. After the English
conversion, the English catalog (`web/src/i18n/en.ts`) is the source of truth
for screen text. Read the text in a `ui-design.md` as the intent of that screen.
