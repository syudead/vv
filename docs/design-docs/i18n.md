# 画面の文言と書式（i18n）

画面（`web/src`）の文言と、日付・数などの書式は `web/src/i18n/` にまとまっている。提供する言語は
英語で、言語の選択は無い。決定の経緯は
[specs/023-english-i18n/research.md](../../specs/023-english-i18n/research.md)（R-1〜R-3、R-5、R-6、R-9）にある。

## カタログ

- `en.ts` が英語のカタログである。画面の領域ごとの入れ子のオブジェクトで、埋め込みを持つ文言は
  引数を取る関数（`t.count.videos(n)`、`t.folderGrouping.ungrouped(name)`）になっている。
- コンポーネントは `import { t } from "../i18n"` で静的に引く。言語は起動時に決まる 1 つの
  定数（`intl.ts` の `LOCALE`）で、実行中に変えないので、React の context や provider は無い。
- カタログの形は `MessageSource`（`typeof en`）である。言語を足すときはこの型を満たす
  オブジェクトを書く。鍵の漏れと関数の引数の食い違いは型検査で見つかる。翻訳管理の道具や
  抽出の手順は無く、言語を足すときは英語のカタログから TypeScript を書く前提である。
- 利用者のデータ（動画名、フォルダ名、タグ名、パス）は翻訳せず、文言の関数へ引数として
  渡して埋め込む。日本語の名前を英語の画面でも崩さずに描くため、和文フォント（Noto Sans JP）は
  残してある。

## UiText

カタログが返す値と書式関数の出力は、branded 型 `UiText` である（`uiText.ts`）。`web/src/ui/` の
部品の文言の props（`IconButton` の `label`、`ModalFrame` の `title`、トーストの本文、
`Combobox` の `placeholder`・`aria-label`・理由など）と、`api/` のフックが返すエラーの文言も
`UiText` になっている。カタログを通らない英語のリテラルはここへ入らないので、型検査で落ちる。
利用者のデータを運ぶ値（`ComboboxOption.label`、`Chip` の `title` など）は `string` のままである。

## 動画プレイヤー（video.js）

video.js の操作バーの読み上げ名とツールチップは、`web/src/player/VideoPlayer.tsx` の
`playerDictionary()` がカタログの `t.player.controls` から作る独自言語（`en-x-vv`）で置き換えている。
キーボード操作を持つボタンには `withKey` でキーを添える（`Play (Space)`、`Mute (M)`、
`Fullscreen (F)`、操作バーへ差し込む `Restart (0)`）。言語はプレイヤーを作るたびに登録し直すので、
疑似ロケールも届く。video.js はこの名前をプレイヤーの `lang` 属性にも使い、表に無い文言は主の
言語 `en` の既定に戻る。

## 書式

`format.ts` と `intl.ts` の関数は、カタログと同じ `LOCALE` の `Intl` を使う。

- `formatNumber`: 桁区切り付きの数。
- `formatDate`・`formatDateTime`: `Intl.DateTimeFormat` の `medium` の日付と `short` の時刻。
- `formatRelative`: `Intl.RelativeTimeFormat` による「3 days ago」の形。区切り（たった今・分・
  時間・日・週・か月・年）は英語化の前と同じで、45 秒未満はカタログの `t.time.justNow`。
- `selectPlural`: `Intl.PluralRules` で `one` と `other` を選ぶ。カタログの件数の関数が使う。
- `formatList`（`intl.ts`）: `Intl.ListFormat` で「A, B, and C」とつなぐ。カタログの関数が、
  カタログの文言を並べるときに使う（再生画面の作成中の 1 行）。

ロケールに依存しない書式（再生時間、容量、解像度、品質の表記）は `web/src/lib/format.ts` に
ある。

## API エラーの表示

`web/src/api/client.ts` の `RequestFailed` は、応答の `status`・`code`・`message` と、
`reason`・`limit`・`tagName`（[contracts/error-api.md §1](../../specs/023-english-i18n/contracts/error-api.md)）を
持つ。`fetch` 自体の失敗は `NetworkFailed` になる。`i18n/errors.ts` の `errorText` が、次の順に
画面の文言を選ぶ。

1. 既知の `reason`、なければ既知の `code`: カタログの文（`limit`・`tagName` を埋め込む）。
2. 未知の `code` で `message` がある: サーバーの英語の `message`。
3. 本文が JSON でない・空・`message` が無い: `Request failed (HTTP <status>)`。
4. `NetworkFailed`: サーバーに届かなかったことを表す文。それ以外の例外は一般的な文で、
   ブラウザや例外の文言は出さない。

エラーの表は生成型の `Record<ErrorCode, …>`・`Record<ErrorReason, …>` として書いてあるので、
`api/openapi.yaml` にコードや理由を足すと、文が無い間は型検査で落ちる。解析と取り込みの失敗は
`probeErrorText`・`scanErrorText` が `ProbeErrorCode`・`ScanErrorCode`（と `errorPath`）から
説明を作り、自由文の `probeError`・`Scan.error` は使わない。コードの無い過去の失敗には一般的な
文を出す。

## 訳し漏れの検出

- **ESLint**: `web/eslint.config.js` の `no-restricted-syntax` が、`web/src` の非テストで `i18n/` の
  外にある、日本語を含む文字列リテラル・テンプレート、文字を含む JSX テキスト、`aria-label`・
  `title`・`placeholder`・`alt` への文字列リテラル、`"ja-JP"`、ロケールを渡さない
  `toLocaleString`・`toLocaleDateString`・`toLocaleTimeString` を報告する。AST を見るので、
  日本語のまま残すコメントは報告しない。除外するディレクトリは無い（テストと `i18n/` だけが
  対象外）。
- **型**: 上の `UiText` とエラーの表の `Record`。
- **疑似ロケールの画面テスト**: `i18n/pseudo.ts` の `enablePseudoLocale()` は、カタログのすべての
  文と書式関数の出力を `⟦ ⟧` で囲む。`expectCatalogTextOnly(root, userData)` は、描画した画面の
  見えるテキストと `aria-label`・`title`・`placeholder`・`alt` のすべてが、印を持つか、テストが
  与えた利用者のデータであることを確かめる。`string` の変数を経由して描かれた英語は、型を
  すり抜けても印が無いのでここで見つかる。`web/vitest.setup.ts` が各テストのあとに英語へ戻す。

型は書いた時点で、画面テストは描画した状態について漏れを捕まえる。テストが描かない状態で
`string` の変数を経由して出る文言は、どちらにも見えない。

## ui-design.md の文言

各 feature の `ui-design.md` は日本語の文言を引用している。英語化のあとの画面の文言は、英語の
カタログ（`web/src/i18n/en.ts`）が正本である。`ui-design.md` の文言は、その画面の意図を表す
ものとして読む。
