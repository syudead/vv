# UI text and formatting (i18n)

UI text and the formatting of dates, numbers and similar values for the UI (`web/src`) live in
`web/src/i18n/`. The UI ships in English, and there is no language picker. The reasoning is in
[specs/023-english-i18n/research.md](../../specs/023-english-i18n/research.md) (R-1 to R-3, R-5,
R-6, R-9).

## Catalog

- `en.ts` is the English catalog. It is a nested object grouped by UI area. Text with
  placeholders is a function that takes arguments (`t.count.videos(n)`,
  `t.folderGrouping.ungrouped(name)`).
- Components read it statically with `import { t } from "../i18n"`. The language is one constant
  fixed at startup (`LOCALE` in `intl.ts`) and never changes at runtime, so there is no React
  context or provider.
- The catalog's shape is `MessageSource` (`typeof en`). To add a language, write an object that
  satisfies this type. The type check finds missing keys and mismatched function arguments. There
  is no translation management tool or extraction step; a new language is written in TypeScript
  from the English catalog.
- User data (video names, folder names, tag names, paths) is not translated. It is passed to the
  catalog functions as arguments and embedded. The Japanese font (Noto Sans JP) stays so that
  Japanese names render correctly in the English UI.

## UiText

Catalog values and formatter output have the branded type `UiText` (`uiText.ts`). The text props
of components in `web/src/ui/` are `UiText`: `label` of `IconButton`, `title` of `ModalFrame`, toast
bodies, and `placeholder`, `aria-label` and reasons of `Combobox`, among others. The error text
returned by the hooks in `api/` is also `UiText`. An English literal that bypasses the catalog
cannot be passed there, so the type check fails. Values that carry user data
(`ComboboxOption.label`, `title` of `Chip`, and similar) stay `string`.

## Video player (video.js)

The accessible names and tooltips of the video.js control bar are replaced by a custom language
(`en-x-vv`). `playerDictionary()` in `web/src/player/VideoPlayer.tsx` builds it from the catalog's
`t.player.controls`. Buttons with a keyboard shortcut get the key appended by `withKey`
(`Play (Space)`, `Mute (M)`, `Fullscreen (F)`, and `Restart (0)`, which is inserted into the
control bar). The language is registered again every time a player is created, so the pseudo
locale reaches it too. video.js also uses this name as the player's `lang` attribute. Text missing
from the table falls back to the default of the primary language `en`.

## Formatting

The functions in `format.ts` and `intl.ts` use `Intl` with the same `LOCALE` as the catalog.

| Function | Output |
| --- | --- |
| `formatNumber` | A number with digit grouping. |
| `formatDate`, `formatDateTime` | The `medium` date and the `short` time of `Intl.DateTimeFormat`. |
| `formatRelative` | The "3 days ago" form from `Intl.RelativeTimeFormat`. The thresholds (just now, minutes, hours, days, weeks, months, years) are the same as before the English migration. Under 45 s it uses the catalog's `t.time.justNow`. |
| `selectPlural` | Picks `one` or `other` with `Intl.PluralRules`. The catalog's count functions use it. |
| `formatList` (`intl.ts`) | Joins items as "A, B, and C" with `Intl.ListFormat`. Catalog functions use it to list catalog text (the "Creating" line on the video page). |

Locale-independent formatting (duration, file size, resolution, quality labels) is in
`web/src/lib/format.ts`.

## API error display

`RequestFailed` in `web/src/api/client.ts` carries the response's `status`, `code` and `message`,
plus `reason`, `limit` and `tagName`
([contracts/error-api.md §1](../../specs/023-english-i18n/contracts/error-api.md)). A failure of
`fetch` itself is `NetworkFailed`. `errorText` in `i18n/errors.ts` picks the UI text in this order.

1. A known `reason`, or else a known `code`: the catalog sentence (with `limit` and `tagName`
   embedded).
2. An unknown `code` with a `message`: the server's English `message`.
3. A body that is not JSON, is empty, or has no `message`: `Request failed (HTTP <status>)`.
4. `NetworkFailed`: a sentence saying the server could not be reached. Any other exception gets a
   generic sentence; browser or exception messages are never shown.

The error tables are written as the generated types `Record<ErrorCode, …>` and
`Record<ErrorReason, …>`. Adding a code or reason to `api/openapi.yaml` fails the type check until
it has a sentence. For probe and scan failures, `probeErrorText` and `scanErrorText` build the
explanation from `ProbeErrorCode` and `ScanErrorCode` (and `errorPath`). The free-text
`probeError` and `Scan.error` are not used. Old failures without a code get a generic sentence.

## Detecting untranslated text

- **ESLint**: `no-restricted-syntax` in `web/eslint.config.js` reports, in non-test files of
  `web/src` outside `i18n/`: string literals and templates containing Japanese, JSX text
  containing letters, string literals passed to `aria-label`, `title`, `placeholder` or `alt`,
  `"ja-JP"`, and `toLocaleString`, `toLocaleDateString` or `toLocaleTimeString` without a locale.
  It inspects the AST, so comments left in Japanese are not reported. No directory is excluded;
  only tests and `i18n/` are out of scope.
- **Types**: `UiText` above and the `Record` error tables.
- **Pseudo-locale UI tests**: `enablePseudoLocale()` in `i18n/pseudo.ts` wraps every catalog
  string and every formatter output in `⟦ ⟧`. `expectCatalogTextOnly(root, userData)` checks that
  all visible text and all `aria-label`, `title`, `placeholder` and `alt` values in the rendered UI
  either carry the marker or are user data supplied by the test. English that reached the screen
  through a `string` variable slips past the types but has no marker, so this test finds it.
  `web/vitest.setup.ts` switches back to English after each test.

The types catch leaks at write time, and the UI tests catch them in the rendered states. Text that
reaches the screen through a `string` variable in a state no test renders is visible to neither.

## Labels in ui-design.md

Each feature's `ui-design.md` quotes UI labels. Those quoted labels are proposals that show the
intent of the screen. The English catalog (`web/src/i18n/en.ts`) is the source of truth for the
text the UI actually shows.
